# 공통 작업 기록과 보고

여러 세션이 같은 작업을 배정하고 재개하거나 결과를 사용할 때 읽는다. 조정 책임자는 [coordinate](../skills/coordinate/SKILL.md)로 공통 기록을 관리하고, 수행 세션은 [work](../skills/work/SKILL.md)로 맡은 범위의 관찰과 변경을 보고한다.

## 작업을 같은 원본으로 식별한다

공통 기록은 관련 세션이 함께 접근할 수 있는 세션 외부의 원본이다. 기존 작업 시스템이나 공유 실행 계획을 사용할 수 있다. 기록 형식과 위치는 프로젝트와 호스트에 맞게 정하고 모든 담당자에게 같은 원본을 전달한다. 원본 대화와 산출물은 링크나 경로로 연결한다.

각 작업에는 수행과 조율에 필요한 다음 정보를 연결한다.

| 정보             | 담을 내용                                                                   |
| ---------------- | --------------------------------------------------------------------------- |
| 식별과 목적      | 작업 ID, 목표와 완료 조건, 발견 이유와 원본 근거                            |
| 범위와 계약      | 맡긴 범위와 권한, 공통 계약, 필요한 입력과 작업 환경                        |
| 관계와 우선순위  | 부모 작업, 필요한 선행 산출물과 의존 작업, 우선순위와 그 판단 근거          |
| 책임과 수행      | 조정 책임자, 담당 세션과 대화 참조, 작업 공간과 통합 담당                   |
| 결과와 다음 행동 | 산출물과 버전, 완료 조건별 검증 근거, 수락 여부와 근거, 남은 일과 재개 조건 |

작업 ID는 재개와 재시도에서도 유지한다. 기존 목적과 범위에 해당하는 요청은 현재 담당과 결과를 확인해 같은 작업에 연결한다. 조정 책임자를 바꿀 때는 기록과 관련 세션에 변경을 전달한다.

형제 관계와 실행 가능 여부를 별도 상태로 중복 저장하지 않는다. 부모 관계와 의존 결과의 수락, 필요한 입력을 기준으로 판단한다. 세션의 실행 중·대기·유휴 여부는 호스트에서 확인하고, 작업 결과의 수락은 조정 책임자가 기록한다. 결과 제출이나 프로세스 종료만으로 수락을 추정하지 않는다.

## 변경과 결과를 보고한다

보고는 현재 작업 ID와 계약에 연결하고, 관찰한 사실과 제안을 구분한다. 필요한 경우 다음 내용을 전달한다.

- 새 작업을 발견하면 해결할 문제, 현재 목표와의 관계, 부모 또는 형제 관계, 선행 조건과 실행이 필요한 이유를 알린다.
- 막히면 필요한 입력이나 결정, 영향을 받는 범위와 재개 조건을 알린다.
- 범위나 계약이 바뀌면 사용자 지시나 새 근거, 바뀐 내용과 영향받는 작업을 알린다. 사용자와 작업 세션의 직접 대화에서 나온 결정도 같은 방식으로 전달한다.
- 결과를 제출하면 사용한 계약, 산출물과 버전, 완료 조건별 관찰과 검증 근거, 실패나 미확인, 남은 일을 알린다.

조정 책임자는 전달받은 변경을 해당 작업의 공통 기록에 반영하고 영향을 받는 담당자에게 알린다. 변경되지 않은 기록과 대화 전체를 사본으로 덧붙이지 않는다. 서브 에이전트는 호출 세션으로 보고하고, 호출 세션이 지속 작업의 보고와 기록 반영을 책임진다.

## 수락과 후속 사용을 연결한다

수락은 검증한 계약과 산출물에 연결한다. 후속 작업은 실제로 사용할 문서, 파일이나 커밋을 입력으로 받는다. 계약이나 산출물이 바뀌면 기존 근거가 유효한 범위를 확인하고 영향을 받은 검증만 다시 수행한다.

하위 결과가 수락되어도 상위 작업의 통합 검증은 남을 수 있다. 상위 완료는 해당 목표와 완료 조건으로 따로 판정한다. 지속 작업 세션의 맥락 보존과 재개는 작업 결과의 수락 여부와 구분한다.
