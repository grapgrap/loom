# Separate Before Serializing Shared State

동시 변경의 제어 방식은 상태의 소유 범위와 도메인의 불변 조건에서 도출한다. 독립적으로 소유할 수 있는 상태는 분리하고, 실제로 공유해야 하는 상태에 필요한 동기화나 직렬화를 적용한다.

## 적용

- 동시 변경을 설계하면 어떤 책임이 상태를 소유하고 어떤 값들이 함께 일관되어야 하는지 확인한다.
- 상태를 분리해도 계약이 유지되는지 확인한다. 독립된 도메인의 상태를 구현 편의 때문에 하나의 전역 상태에 묶지 않는다.
- 공유가 필요한 경우에는 동시에 허용할 동작과 보호할 불변 조건을 정하고 그 범위에 동기화를 적용한다.

## 예시

서로 독립된 작업의 진행 상태는 각 작업이 소유할 수 있다. 반면 여러 주문이 같은 상품의 재고를 예약하면 가용 재고라는 공유 제약이 있으므로 재고 도메인에서 초과 예약을 막아야 한다. 주문별 상태를 나누는 것만으로 공유 재고의 제약이 해결되지는 않는다.

## 경계

상태의 분리가 도메인의 계약을 바꾸면 분리를 강행하지 않는다. 동기화 방식도 보호할 범위에 맞춰 선택한다. 전역 직렬화로 모든 도메인의 동작을 묶기 전에 실제로 공유하는 제약인지 확인한다.
