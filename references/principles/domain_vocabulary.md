# Domain Vocabulary

모듈, 모델과 동작의 이름은 도메인의 개념과 역할을 일관되게 드러낸다. 코드의 어휘에서 어느 책임과 계약을 다루는지 읽을 수 있어야 한다.

## 적용

- 모델, 상태, 공개 동작을 정의하면 도메인의 전문가나 사용자가 쓰는 어휘를 확인하고 같은 개념에 같은 이름을 사용한다.
- 도메인의 의미를 일반적인 처리·관리라는 표현으로 대체하지 않는다. 동작의 목적과 모델의 역할이 이름에 드러나게 한다.
- 모듈의 이름은 맡은 대상과 역할을 드러낸다. 이름을 정하기 전에 어떤 판단과 보장을 소유하는지 설명한다. 입력의 종류나 호출 시점만으로 이름을 지으면 실제 책임을 가리는지 확인한다.
- 동작의 이름은 입력을 어떻게 처리하는지보다 수행하는 일과 결과의 의미를 표현한다. 요청, 시작, 갱신과 완료가 서로 다른 계약이라면 그 차이를 이름에 담는다.
- 다른 도메인의 어휘는 인터페이스 경계에서 자기 도메인의 어휘로 변환한다. 서로 다른 개념을 이름이 비슷하다는 이유로 같은 모델로 취급하지 않는다.

## 예시

외부 결제사의 승인 응답을 결제 도메인의 승인 결과로 변환한다. 주문 도메인은 필요한 결제 상태를 자기 계약으로 받아 사용한다. 결제사의 상태 코드나 일반적인 데이터 처리라는 이름이 주문 규칙 전체에 퍼지지 않게 한다.

좌석을 배정하는 규칙을 소유한 모듈은 좌석 배정을, 예약을 저장하고 복원하는 모듈은 예약 저장을 이름에 드러낸다. 둘을 모두 예약 처리라고 부르면 서로 다른 변경 이유와 제공하는 계약을 알기 어렵다. 예약 요청을 받았다는 사실만으로 예약을 확정한 것은 아니므로, 요청을 접수하는 동작과 좌석 확보를 보장하는 동작의 이름도 구분한다.

## 경계

도메인이 실제로 사용하는 기술 용어도 어휘가 될 수 있다. 외부와 내부가 같은 의미를 공유한다면 불필요한 번역을 만들지 않는다. 용어가 다르면 이름의 통일보다 의미의 차이를 경계에서 명시하는 것이 먼저다.

역할을 나타내는 접미사만으로 책임을 정하지 않는다. 더 정확한 이름을 붙이기 어려운 이유가 서로 무관한 판단이 한곳에 섞여 있기 때문이라면, 이름과 함께 책임 배치를 다시 판단한다.
