# Domain as Folder

같은 도메인의 모델과 동작을 한 폴더에 모아 책임의 경계를 파일 배치에서 드러낸다. 기술적 역할만으로 한 도메인의 코드를 최상위 여러 폴더에 흩어 놓지 않는다.

## 적용

- 도메인을 추가하거나 코드를 옮기면 목적·개념·책임을 기준으로 소속을 정한다.
- 도메인 폴더는 평면으로 배치한다. 논리적인 부모·자식 관계는 공개 모델의 합성이나 인터페이스의 사용으로 드러낸다.
- 도메인 내부의 파일은 역할과 응집도로 나눈다. 공개 계약과 내부 구현을 구분하여 다른 도메인이 내부 파일을 참조하지 않게 한다.

## 예시

역할별로 흩어진 models/order, operations/place-order, views/order-card를 order/ 안에 모은다. order/와 customer/의 관계는 두 폴더의 중첩보다 공개 모델과 인터페이스의 사용에서 확인할 수 있게 한다.

## 경계

파일 저장이나 메시지 전달 같은 기반 기능도 자신이 보장할 개념과 계약을 기준으로 도메인을 정한다. 도메인의 논리적 중첩은 폴더를 중첩해야 할 이유가 아니다. 폴더를 모으는 것만으로 공개 계약이나 의존 방향이 보장되지는 않는다.
