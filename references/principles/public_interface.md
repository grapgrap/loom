# Public Interface

도메인·클래스·모듈의 공개 인터페이스는 다른 단위와 맺는 계약이다. 공개하는 이름은 그 단위가 협력에서 맡은 역할과 실제 계약을 표현한다. 필요한 동작과 값, 실패와 사용 조건을 의도적으로 공개하고 내부 모델의 일관성을 보장한다.

## 적용

- 공개 범위를 정하면 외부에서 필요한 동작과 모델을 선택한다. 내부 파일과 모듈을 한꺼번에 자동으로 공개하지 않는다.
- 공개 값·동작·콜백의 이름은 이를 소유한 단위가 제공하거나 요구하는 의미에서 정한다. 협력 상대가 수행할 처리나 특정 사용 흐름을 소유자의 역할처럼 이름에 담지 않는다.
- 계약에는 입력과 결과, 보장할 상태, 구분하여 대응할 실패, 호출 순서와 호출자가 지켜야 할 조건을 담는다.
- 사용 조건은 입력 형태나 계약으로 표현한다. 코드만으로 드러내기 어려운 조건은 호출자가 확인할 수 있는 계약 설명에 남긴다.
- 외부 기능을 요구하면 도메인의 작업으로 계약을 정의한다. 특정 외부 도구의 전체 기능과 설정을 도메인의 계약으로 노출하지 않는다.

## 예시

재고 예약은 예약할 수량, 예약 결과, 재고 부족 실패와 중복 요청의 의미를 공개한다. 호출자가 내부 재고 저장 구조를 읽거나 수량을 직접 변경해야 예약할 수 있다면 공개 계약이 책임을 충분히 소유하지 못한 것이다.

버튼이 클릭 콜백을 속성으로 받는다면 `handleClick` 대신 클릭 사건을 나타내는 `onClick`으로 공개한다. 버튼을 사용하는 화면은 자신의 클릭 처리 함수를 `handleClick`으로 부를 수 있다. 화면이 수행하는 처리를 버튼의 속성 이름에 담지 않는다.

자원을 소유한 객체는 자신이 맡은 정리와 종료를 `close`로 제공한다. 호출자가 작업을 마친 뒤 이 동작을 사용하더라도, 작업 완료가 객체의 책임이 아니라면 `closeAfterWork`처럼 호출 시점을 이름에 넣지 않는다.

작업을 완료하려면 모든 하위 작업이 끝나야 하고 완료 시각도 기록해야 한다고 하자. `withStatus(COMPLETED)`가 상태만 교체한다면 호출자가 이 조건과 기록을 책임져야 한다. 작업 객체가 완료 규칙을 소유한다면 `complete()`는 완료 가능 여부를 확인하고 상태와 완료 시각을 함께 반영한다. 객체가 불변이어도 이 동작은 규칙을 적용한 새 작업을 반환할 수 있다.

## 경계

공개는 다른 단위와의 협력 경계를 뜻하며 외부에 배포하는 API에 한정하지 않는다. 협력 상대나 사용 맥락이 해당 단위의 실제 책임이라면 그 의미를 이름에 담을 수 있다. 시그니처가 같아도 결과, 실패와 호출 조건의 의미가 바뀌면 계약의 변경이다. 호출자 전환은 [Migrate Callers Then Delete Legacy](migrate_callers_delete_legacy.md)를 따른다. 공개 계약을 정하는 것과 그 계약의 외부 구현을 선택하는 것은 별개의 책임이다.
