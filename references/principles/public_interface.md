# Public Interface

도메인의 공개 인터페이스는 외부와의 계약이다. 필요한 동작과 값, 실패와 사용 조건을 의도적으로 공개하고 내부 모델의 일관성을 보장한다.

## 적용

- 공개 범위를 정하면 외부에서 필요한 동작과 모델을 선택한다. 내부 파일과 모듈을 한꺼번에 자동으로 공개하지 않는다.
- 계약에는 입력과 결과, 보장할 상태, 구분하여 대응할 실패, 호출 순서와 호출자가 지켜야 할 조건을 담는다.
- 사용 조건은 입력 형태나 계약으로 표현한다. 코드만으로 드러내기 어려운 조건은 호출자가 확인할 수 있는 계약 설명에 남긴다.
- 외부 기능을 요구하면 도메인의 작업으로 계약을 정의한다. 특정 외부 도구의 전체 기능과 설정을 도메인의 계약으로 노출하지 않는다.

## 예시

재고 예약은 예약할 수량, 예약 결과, 재고 부족 실패와 중복 요청의 의미를 공개한다. 호출자가 내부 재고 저장 구조를 읽거나 수량을 직접 변경해야 예약할 수 있다면 공개 계약이 책임을 충분히 소유하지 못한 것이다.

## 경계

시그니처가 같아도 결과, 실패와 호출 조건의 의미가 바뀌면 계약의 변경이다. 호출자 전환은 [Migrate Callers Then Delete Legacy](migrate_callers_delete_legacy.md)를 따른다. 공개 계약을 정하는 것과 그 계약의 외부 구현을 선택하는 것은 별개의 책임이다.
