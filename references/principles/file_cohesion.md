# File Cohesion

한 파일에는 같은 도메인과 역할에서 함께 이해하고 같은 이유로 변경할 코드를 모은다. 파일의 책임을 설명하기 위해 서로 무관한 관심사를 열거해야 한다면 경계를 다시 검토한다.

## 적용

- 파일을 추가하거나 나누면 각 코드의 도메인, 역할과 변경 이유를 확인한다.
- 같은 책임을 이해하는 데 필요한 모델과 동작은 가까이 두되, 다른 레이어의 책임을 편의상 한 파일에 묶지 않는다.
- 파일 분할이 의미 없는 전달과 탐색만 늘리면 독립된 입력이나 제약이 있는지 [Earn Your Boundary](earn_your_boundary.md)로 확인한다.

## 예시

주문의 허용 상태와 상태를 판정하는 모델 연산은 함께 이해할 수 있다. 외부 결제 응답의 변환과 주문 화면의 포커스 상태는 변경 이유와 역할이 다르므로 주문 모델 파일에 함께 넣지 않는다.

## 경계

파일 크기나 선언 개수만으로 분할하지 않는다. 하나의 응집된 역할을 불필요하게 흩뜨리는 것도 책임을 이해하는 비용을 높인다.
