# Single Level of Abstraction

같은 맥락에서 동등한 책임과 동작은 일관된 방식으로 표현한다. 분기와 유사한 흐름을 읽을 때 표현의 차이에서 실제 의미의 차이를 알 수 있어야 한다.

## 설명

독자는 코드의 표현에서 의미를 추론한다. 같은 역할을 맡는 분기나 단계의 처리 방식이 제각각이면, 독자는 그 차이가 실제 동작이나 책임의 차이를 뜻하는지 확인해야 한다. 실제 차이가 없다면 일관된 방식으로 구성해 불필요한 해석을 줄인다.

추상화 수준은 코드가 동작의 의도를 드러내는지, 그 동작을 실현하는 세부 절차를 드러내는지를 뜻한다. 여러 단계를 조율하는 함수는 각 단계의 의도와 순서를 보여주고, 각 단계를 구현하는 함수는 세부 절차를 보여준다. 대응하는 처리의 추상화 수준을 맞추는 것은 표현의 일관성을 확보하는 방법이다.

이 기준은 한 함수의 분기와 연속된 단계, 서로 다른 함수나 파일에서 같은 맥락으로 비교할 수 있는 흐름에 적용한다. 비교할 대상은 도메인에서 수행하는 책임과 동작으로 정한다.

## 적용

- 분기와 유사한 흐름에서 동등한 책임·동작을 맡는 단계는 이름, 함수 분리 여부와 구현의 노출 수준을 일관되게 맞춘다.
- 조율하는 흐름은 각 단계의 의도와 순서를 보여준다. 특정 단계나 분기만 세부 절차를 드러내면 대응하는 처리와 표현 수준을 맞춘다.
- 함수의 이름은 해당 단계의 의도를 설명해야 한다. 흐름을 이해하기 위해 매번 함수 본문을 확인해야 한다면 이름과 분리 단위를 다시 검토한다.
- 실제 책임·동작·제약이 달라 다르게 구성해야 한다면, 그 차이가 이름과 구조에서 드러나도록 한다.

## 경계

일관성을 맞추는 방법에는 함수 분리와 인라인 표현이 모두 포함된다. 해당 흐름 전체에서 책임과 의도를 읽기 쉬운 쪽을 선택한다. 개별 구간이 짧다는 이유만으로 동등한 처리의 표현을 다르게 유지하지 않는다. 의미 없는 함수로 감싸 탐색만 늘린다면 일관성을 유지하는 다른 표현을 선택한다.

표현의 일관성이 구현의 공유를 요구하지는 않는다. 유사한 코드를 같은 수준으로 표현하더라도 변경 이유가 다르면 별도로 유지한다.

조건문이나 반복문이 있다는 이유만으로 추상화 수준이 낮다고 판단하지 않는다. 업무의 분기와 반복을 표현하는 제어문은 상위 흐름의 일부일 수 있다.

## 예시

CSV와 JSON 내보내기는 보고서를 해당 형식으로 변환하고 파일에 저장하는 역할을 맡는다. `exportCsv`가 이 역할 전체를 표현한다면 JSON 분기도 같은 수준으로 표현한다.

### Don't

```typescript
const exportReport = async (report: Report, format: "csv" | "json", path: string) => {
  if (format === "csv") {
    await exportCsv(report, path);
  } else {
    const content = JSON.stringify(report.rows);
    await writeFile(path, content);
  }
};
```

### Do

```typescript
const exportJson = async (report: Report, path: string) => {
  const content = JSON.stringify(report.rows);
  await writeFile(path, content);
};

const exportReport = async (report: Report, format: "csv" | "json", path: string) => {
  if (format === "csv") {
    await exportCsv(report, path);
  } else {
    await exportJson(report, path);
  }
};
```

JSON 분기가 짧더라도 한쪽은 내보내기 동작을, 다른 쪽은 변환과 저장 절차를 드러내고 있다. 두 분기를 각각의 내보내기 동작으로 표현하면 호출부에서 역할과 차이를 같은 방식으로 읽을 수 있다.

## 검토 질문

- 분기와 유사한 흐름의 동등한 처리가 이유 없이 서로 다른 방식으로 표현되어 있는가?
- 이름, 단계 구성과 구현의 노출 수준에 나타난 차이가 실제 책임·동작·제약의 차이를 반영하는가?
- 개별 구간의 간결함만으로 전체 흐름의 일관성이 깨지는 표현을 정당화하고 있지 않은가?
- 흐름을 읽다가 특정 단계의 세부 절차를 해석해야 하는가?
- 함수 분리와 인라인의 선택이 전체 흐름에서 책임과 의도를 일관되게 읽는 데 도움이 되는가?
