# Foundational Thinking

새 개념이나 구조를 추가하기 전에 기존 책임과 공개 계약의 조합으로 요구를 충족할 수 있는지 확인한다. 추가하는 구조에는 기존 구성으로 충족할 수 없는 책임이나 제약이 있어야 한다.

불필요한 모듈과 전달 계층은 도메인과 역할을 이해하기 위해 추적할 관계를 늘린다.

## 적용

- 새로운 요구를 받으면 관련 도메인의 모델, 동작과 공개 계약을 확인하고 기존 구성으로 가능한 안을 검토한다.
- 추가할 구조가 필요하면 어떤 책임이나 제약이 현재 구성에서 빠져 있는지 설명한다.
- 기존 구성을 사용하기 위해 내부 구현을 참조하거나 책임을 다른 도메인에 넣어야 한다면 그 안을 다시 판단한다.

## 예시

여러 주문을 조회하는 기능을 추가할 때 기존 주문 조회 계약을 조합하여 결과를 만들 수 있는지 확인한다. 새 조회 관리 계층을 먼저 만들지 않는다. 주문 간 일관된 시점의 결과가 필요하고 기존 계약이 이를 보장하지 못한다면 그 제약을 소유할 계약을 추가한다.

## 경계

기존 방식과 새로운 방식 자체를 목표로 삼지 않는다. 기존 구성이 새 책임을 자연스럽게 수용하지 못하면 [Redesign From First Principles](redesign_from_first_principles.md)로 전제를 다시 판단한다.
