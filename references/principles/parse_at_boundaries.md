# Parse at Boundaries

계약으로 신뢰할 수 없는 입력은 이를 받아들이는 책임에서 해석·검증하여 도메인 모델로 변환한다. 내부에서는 생성 과정과 호출 계약이 보장하는 형식과 값의 조건을 신뢰한다.

## 적용

- 외부 응답, 저장된 데이터나 사용자 입력의 계약을 신뢰할 수 없다면 이를 해석하는 책임에 필요한 검증과 모델 변환을 모은다.
- 타입을 사용하는 환경에서는 생성 과정과 호출 계약에 맞게 타입을 선언한다. 타입 선언이나 강제 변환만으로 신뢰할 수 없는 입력의 계약을 확보했다고 간주하지 않는다.
- 양수, 비어 있지 않음, 정렬 상태처럼 타입에 표현되지 않은 조건도 생성 과정과 호출 계약이 보장하면 신뢰한다. 선행 검증 함수가 없다는 이유로 소비자에 검사를 추가하지 않는다.
- 도메인 사이의 어휘·모델 변환과 값의 검증을 구분한다. 함수·모듈·도메인의 경계를 넘었다는 사실만으로 같은 계약을 다시 검증하지 않는다.

## 예시

내부에서 비어 있지 않은 항목 묶음의 길이로 수량을 계산했다면 주문 동작은 그 수량이 양수라는 계약을 신뢰한다. 수량을 단순한 숫자로 전달해도 주문 생성과 재고 차감에서 양수 검사를 반복하지 않는다.

CLI 문자열을 수량으로 해석할 때 정수·양수 조건이 필요하면 그 입력을 해석하는 곳에서 확인한다. 현재 재고가 충분한지는 재고 차감을 책임지는 곳에서 판단한다.

## 경계

현재 재고나 리비전처럼 실행 시점에 달라지는 조건은 그 상태를 사용하는 책임에서 판단한다. 생성 당시 보장한 값의 조건을 소비자마다 확인하는 것과 구분한다.
