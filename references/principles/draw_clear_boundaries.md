# Draw Clear Boundaries

모듈이 어떤 판단을 내리고 어떤 상태와 결과를 보장하는지 분명히 한다. 그 책임에서 입력을 해석하는 위치, 상태의 소유자와 협력 계약을 정한다. 서로 다른 관심사를 한 책임에 묶거나 같은 책임을 여러 위치에 흩뜨리지 않는다.

## 적용

- 실제 사용 사례에서 호출자가 요청하는 일과 그 결과에 필요한 판단을 확인한다. 각 판단을 맡은 단위가 어떤 모델과 불변 조건을 소유하고 어떤 이유로 변경하는지 설명한다.
- 입력의 해석, 동작의 선택, 상태 전이와 여러 동작의 조율을 구분해 책임을 배치한다. 입력 형식을 아는 곳과 내부 규칙을 아는 곳이 서로 다른 이유로 바뀐다면 각자의 계약으로 협력하게 한다.
- 상태 변경의 허용 조건과 함께 반영할 값은 그 규칙을 소유한 단위에서 보장한다. 호출자가 내부 상태를 읽고 같은 규칙과 변경 절차를 재구성해야 한다면 공개 동작과 책임 배치를 다시 확인한다.
- 도메인 규칙은 외부 프로토콜, 화면과 실행 환경의 세부 구현에서 분리하여 독립적으로 이해하고 검증할 수 있게 한다. 외부 실행이 필요하면 도메인의 동작으로 정의한 협력 계약을 사용한다.
- 입력을 해석·검증하는 책임은 [Parse at Boundaries](parse_at_boundaries.md)에 따라 정한다. 생성 과정과 호출 계약으로 보장한 형식과 값의 조건은 소비자에서 다시 검증하지 않는다.
- 공개 범위는 [Public Interface](public_interface.md)에 따라 필요한 동작과 값으로 제한한다.

## 예시

배송 가능 여부를 정하는 도메인 규칙과 외부 배송사의 응답을 해석하는 코드를 구분한다. 배송 규칙은 자기 모델로 판단하고, 외부 응답의 변환과 검증은 경계가 맡는다. 배송사의 응답 형식이 바뀌었다는 이유로 배송 가능 여부의 규칙까지 바뀌지 않게 한다.

주문 취소에는 주문의 취소 가능 여부와 취소 상태 반영, 결제 환불과 재고 예약 해제가 필요할 수 있다. 주문은 취소 규칙을, 결제와 재고는 각자의 동작을 보장한다. 취소 흐름은 이 동작들의 순서와 일부 실패 시 남는 상태를 책임진다. 흐름을 조율하는 곳에서 주문의 취소 규칙이나 재고 수량 변경 절차까지 다시 구현하지 않는다.

## 경계

서로 다른 책임이 있다는 근거 없이 전달 계층을 추가하지 않는다. 초기 탐색에서 아직 확인하지 못한 경계는 가정으로 남긴다. 분리할 필요는 [Earn Your Boundary](earn_your_boundary.md)로 판단한다.

책임의 구분이 각각의 클래스나 계층을 요구하지는 않는다. 규칙은 상태를 가진 객체의 동작이나 모델과 함께 둔 함수로 표현할 수 있다. 외부 실행을 협력 계약으로 요청하는 방식과 판단 결과를 반환해 다른 곳에서 실행하는 방식도 필요한 사용 사례와 보장으로 선택한다.
