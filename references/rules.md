# 코드 작성·리뷰 규칙

[원칙](principles.md)의 책임·계약·의존 관계를 코드에 드러내기 위한 실천 기준이다. 코드를 작성·변경하거나 리뷰할 때 적용하며, 프로젝트 언어의 관용적 표현을 존중한다. 수정과 검토의 범위는 맡긴 작업을 따른다.

## 적용할 항목을 고른다

프로젝트 지침과 사용자의 명시적 선택을 먼저 적용한다. 아래 적용 상황과 판단 기준에서 현재 작업에 관련된 항목을 고르고, 적용하기 전에 해당 규칙의 본문을 읽는다. 새로운 사실이 판단의 전제나 영향 범위를 바꾸면 관련 항목을 다시 확인한다.

| 적용 상황                                         | 규칙                                                                        | 판단 기준                                                                    |
| ------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 이름·제어 흐름·주석을 작성하거나 검토할 때        | [이름과 흐름으로 책임을 드러낸다](rules/names_and_flow.md)                  | 각 단위의 역할과 실제 동작·상태 변경이 이름과 흐름에서 드러나게 한다.        |
| 함수를 나누거나 매개변수·호출 관계를 정할 때      | [함수의 책임과 경계를 정한다](rules/function_boundaries.md)                 | 길이나 개수보다 독립된 책임과 계약을 근거로 경계를 정한다.                   |
| 상태를 저장·공유·변경하거나 실행 순서를 정할 때   | [상태의 소유자와 변경을 명시한다](rules/state_ownership.md)                 | 상태의 소유자와 변경·동기화의 계약을 드러낸다.                               |
| 조건 분기를 추가하거나 복잡한 조건을 정리할 때    | [조건 판단을 담당자에게 모은다](rules/condition_ownership.md)               | 정책 담당자에게 판단을 모으고 정상 흐름을 얕게 유지한다.                     |
| 입력 검증을 추가·변경하거나 실행 조건을 판단할 때 | [입력 계약과 실행 조건을 구분한다](rules/validation_and_preconditions.md)   | 내부 계약을 신뢰하고 외부 입력의 검증과 현재 상태의 판단을 담당 책임에 둔다. |
| 실패를 전달하거나 재시도·복구·안내를 결정할 때    | [대응할 책임과 수단이 있는 곳에서 오류를 처리한다](rules/error_handling.md) | 대응할 책임과 수단이 있는 곳에서 원인과 맥락을 보존해 처리한다.              |
| 모듈·파일·공개 범위·외부 의존성·상수를 배치할 때  | [모듈·파일·의존성을 같은 변경 이유로 구성한다](rules/module_cohesion.md)    | 같은 변경 이유를 모으고 외부 구현의 지식은 통합 경계에 둔다.                 |
| 중복을 합치거나 추상화를 추가할 때                | [같은 책임의 중복을 제거한다](rules/duplication_and_abstraction.md)         | 같은 정책과 계약의 중복만 모으고 현재 사용 사례로 추상화를 정당화한다.       |
| 새 동작·동작 변경·버그 수정을 구현할 때           | [테스트로 책임의 계약을 먼저 표현한다](rules/test_contracts_first.md)       | 기대 계약을 실패 테스트로 먼저 표현하고 관찰 가능한 결과를 검증한다.         |
| 기존 코드를 수정하거나 구조를 정리할 때           | [리팩터링으로 책임 배치를 바로잡는다](rules/refactoring.md)                 | 동작을 보존하면서 책임 배치를 개선하고 편법의 영향과 해소 조건을 드러낸다.   |
| 변경·검토 결과를 전달하기 전                      | [변경 결과를 확인한다](rules/verify_changes.md)                             | 요청한 동작·계약·테스트와 변경 영역의 책임·중복·잔여 코드를 확인한다.        |
