# 테스트로 책임의 계약을 먼저 표현한다

- 테스트 주도 개발을 기본으로 한다. 새 동작·동작 변경·버그 수정에서는 기대 동작을 나타내는 가장 작은 실패 테스트를 먼저 작성하거나 수정하고, 의도한 이유로 실패하는지 확인한 뒤 구현한다.
- 입력·결과·실패·중요한 불변 조건을 테스트한다. 사용자가 관찰하는 결과를 검증하고 우연한 구현 세부사항이나 모의 객체의 동작만 따라가는 테스트는 피한다.
- 조건과 기대 결과로 이름을 짓고, 준비 코드는 맡은 계약에 필요한 범위로 유지한다. 결과는 결정적이며 실행 순서와 독립적이어야 한다.
- 테스트 환경 부재나 레거시 제약 때문에 테스트 우선 순서가 막히면 그 사실을 명시한다. 즉시 가능한 가장 가까운 검증을 추가하고, 해당 책임을 이전보다 테스트하기 쉬운 상태로 남긴다.
- 예상 동작이 실제로 바뀌지 않았다면 잘못된 구현에 맞춰 기대값이나 검증 조건을 약화하지 않는다.
