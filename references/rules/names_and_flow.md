# 이름과 흐름으로 책임을 드러낸다

- 도메인 용어를 일관되게 사용하고, 값과 동작이 맡은 역할을 이름에 담는다. 외부 프로토콜의 정확한 용어가 아니라면 `data`, `manager`, `helper`, `util`처럼 역할을 특정하지 못하는 이름을 피한다.
- Boolean은 언어의 관례에 따라 `active?`, `isActive`, `hasItems`처럼 조건으로 읽히게 한다. 컬렉션은 복수형으로 이름을 짓는다.
- 함수 이름은 실제 동작과 상태 변경을 설명한다. `do_invoice`보다 `calculate_invoice_total`처럼 구체적으로 쓴다.
- 단순한 제어 흐름을 우선하고, 책임을 이해하기 위해 추적해야 하는 호출과 기억해야 하는 상태를 줄인다.
- 주석은 코드만으로 알기 어려운 제약과 선택 이유를 설명한다. 코드의 재서술, 불분명한 이름을 보완하는 설명, 주석 처리된 코드와 변경 일지는 남기지 않는다.
