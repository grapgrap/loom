# 입력 계약과 실행 조건을 구분한다

- 직접 설계한 내부 협력은 생성 과정과 호출 계약을 따른다고 본다. 타입에 나타나지 않는 양수·비어 있지 않음·정렬 상태 같은 값의 조건도 그 계약이 보장하면 신뢰한다.
- 명시적인 선행 검증이 없거나 함수·모듈·도메인의 경계를 넘었다는 이유로 다시 검사하지 않는다. 계약을 어기는 내부 호출은 호출부나 생성 과정·계약을 바로잡는다.
- CLI·파일·네트워크에서 신뢰할 계약 없이 들어오는 값은 이를 받아들이는 책임에서 검증한다. 공개 메서드나 생성자라는 사실만으로 외부 입력 경계로 간주하지 않는다.
- 입력 검증을 추가할 때는 계약을 어기는 값의 구체적인 유입 경로와 이 코드가 검증을 맡을 이유를 확인한다.
- 재고·존재 여부·리비전 충돌처럼 실행 시점의 상태에 따라 달라지는 조건은 그 동작이나 상태를 소유하는 책임에서 사용 시점에 판단한다. 입력 계약의 검증으로 현재 상태의 판단을 대신하지 않는다.

정렬된 항목을 만드는 내부 함수의 결과는 소비자가 정렬 여부를 다시 검사하지 않고 사용한다. 반면 저장할 리비전의 충돌 여부는 저장 시점에 판단한다.
