# 입력 계약과 실행 조건을 구분한다

- CLI·파일·네트워크 등 계약을 위반한 값이 들어올 수 있는 경계에서 입력을 검증하고, 잘못된 입력은 즉시 실패로 드러낸다. 공개 메서드나 생성자라는 사실만으로 외부 입력 경계로 간주하지 않는다.
- 직접 설계한 내부 협력은 의도한 계약을 따른다고 본다. 다른 단위가 맡은 검증을 반복하지 않는다. 계약을 어기는 내부 호출은 호출부나 생성 과정·계약을 바로잡는다.
- 동작의 허용 여부와 상태 전이의 사전 조건은 그 동작을 책임지는 단위가 판단한다. 형식 검증인지 실행 조건인지의 분류만으로 검증을 유지하거나 제거하지 않는다.
- 존재 여부·리비전 충돌·동시 종료처럼 외부 상태에 따라 달라지는 조건은 그 상태를 사용하는 책임에서 사용 시점에 확인한다. 앞서 입력 형식을 검증했다는 사실로 현재 상태의 판단을 대신하지 않는다.

파서가 외부 문자열을 유효한 수량으로 변환했다면 계산 함수는 그 수량으로 계산한다. 반면 리비전 충돌은 입력 형식과 별개이므로 실제 저장을 책임지는 단위가 저장 시점에 판단한다.
