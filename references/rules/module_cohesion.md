# 모듈·파일·의존성을 같은 변경 이유로 구성한다

- 같은 도메인과 역할에서 함께 이해하고 변경할 코드를 모은다. 독립된 정책의 변경을 한 단위가 함께 감당하면 책임을 분리한다.
- 모듈의 책임은 소유하는 판단과 보장으로 설명한다. 입력을 해석하거나 호출 대상을 선택하는 곳에 협력 상대의 상태 전이 규칙까지 옮기지 않는다. 여러 동작의 순서와 부분 실패 대응은 그 흐름을 조율하는 책임에 둔다.
- 공개 범위는 협력에 필요한 계약으로 한정한다. 다른 단위의 내부 구현에 의존하거나, 호출자가 책임질 필요가 없는 내부 설정을 공개하지 않는다.
- 함수 추출, 파일 분리와 공개 API 추가를 각각 판단한다. 같은 책임 안의 헬퍼는 전체 흐름의 표현 일관성을 기준으로 정한다. 함께 이해할 모델과 동작은 가까이 두고, 독립된 변경 이유와 실제 소비자가 필요한 계약을 근거로 파일 경계와 공개 범위를 정한다.
- 서로 다른 책임은 합성을 우선해 조합한다. 외부 구현의 선택과 연결은 조합을 맡은 곳에 두고, 도메인 코드에는 해당 통합의 지식을 흩뜨리지 않는다.
- 외부 형식은 경계에서 내부 계약으로 변환한다. 외부 프로토콜·공급자·프레임워크의 표현을 도메인 모델로 대신 사용하지 않는다.
- 모델은 필드 모양만으로 공유하지 않는다. 같은 의미, 허용 상태와 변경 이유를 공유의 근거로 삼고, 계약이 다르면 각 책임에 맞게 구분한다.
- 의미 있는 리터럴·임계값·상태 매핑은 해당 정책의 책임에 둔다. 서로 다른 책임의 값을 전역 상수 모음에 넣지 않는다. 의미가 분명한 지역 리터럴은 추출이 가독성을 해치면 그대로 둔다.
