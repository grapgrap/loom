# Plan 산출물 검토

Plan 산출물은 현재 구현의 조사 결과와 문제를 해결할 구현 방안을 구분하여 설명해야 한다. 구현 방안의 예상 영향을 검토하고 변경안에서 실행 작업을 도출해야 한다. concept·flow와 다른 의미나 경계를 전제로 한다면 해당 설계에 반영되었는지 확인한다.

변경안을 다음 기준으로 검토한다.

- 현재 동작과 문제 원인에 대한 설명을 관련 코드·문서·테스트와 대조한다. 확인한 사실과 가정이 구분되는지 확인한다.
- 구현 방안이 문제를 해결하고 원하는 결과를 만드는지 확인한다. 기존 구조의 유지 자체를 타당성의 기준으로 삼지 않는다. 선택에 따라 동작이나 구조가 달라지는 지점의 영향이 드러나는지 본다.
- 영향을 받는 사용처, 상태 변경과 실패 경로에 필요한 대응이 누락되지 않았는지 확인한다.
- 주요 변경의 코드 위치, 책임, 인터페이스, 호출 관계와 핵심 로직이 구현 초안에 있는지 확인한다. 목적과 완료 조건만으로 초안을 대신하지 않았는지 본다.
- 실행자가 새로 정해야 할 주요 설계를 남긴 범위가 실행 가능 상태로 확정되어 있으면 결함으로 판단한다. 검증 결과를 기다리는 범위는 별도로 구분되었는지 확인한다.
- 합의한 구현 초안과 부작용 대응이 실행 작업 및 검증 방법에 반영되는지 확인한다.
- 미확인 사항을 확인할 방법과 시점이 있으며, 그 결과에 의존하는 실행 전에 재검토할 수 있는지 확인한다.

구현이 진행된 plan의 변경 전 동작은 확보한 diff나 변경 전 코드와 대조한다. 이미 적용된 변경 때문에 현재 코드가 설명과 달라진 것을 plan의 오류로 판단하지 않는다.

산출물과 기록된 근거로 변경안을 평가한다. 사용자가 대화 중 주요 결정을 알아차렸는지 또는 실행 요약을 확인했는지는 산출물만으로 추론하지 않는다.

각 태스크의 결과 계약을 다음 기준으로 검토한다.

- 각 태스크가 목적, 수행할 변화, 완료 결과와 검증 방법을 모두 기술하는지 확인한다.
- 목적, 수행할 변화, 완료 결과와 검증 방법이 같은 결과를 가리키는지 확인한다.
- 완료 결과가 활동의 반복이 아니라 검증 가능한 상태, 산출물 또는 능력인지 확인한다.
- 완료 결과가 변경안을 실체화하거나 후속 태스크의 전제가 되는지 추적한다.
- 제외가 범위로 오해할 만한 인접 작업만 한정하는지 확인한다. 필요한 결과나 검증을 제외로 숨긴 경우에는 결함으로 판단한다.
- 임시 핸드오프가 있으면 현재 미완료 태스크 안에 있으며 재개 지점과 아직 끝나지 않은 작업만 담는지 확인한다. 태스크가 완료되었거나 확인된 변경 증거에서 핸드오프 작성 후 실행을 재개했는데도 남아 있으면 결함으로 판단한다. 사용자의 명시적 요청 여부는 산출물만으로 추론하지 않는다.

전체 결과 사슬을 다음 기준으로 검토한다.

- 각 결과 의존이 구체적인 선행 결과와 그 결과를 요구하는 후속 전제를 연결하는지 확인한다.
- 단순한 작성 순서나 선호하는 실행 순서를 결과 의존으로 기록하지 않았는지 확인한다.
- 필요한 선행 결과의 누락, 후속 전제가 없는 고아 결과 또는 순환하는 결과 의존이 있는지 확인한다.
- 모든 중간 결과가 Plan의 목적이 요구하는 최종 결과까지 이어지는지 확인한다.

실행 중 발견의 반영은 확인된 변경 증거를 기준으로 검토한다. 변경 증거에서 남은 실행을 제약하는 기술적 사실이 확인되면 영향받는 변경안·태스크·검증 또는 결과 의존에 그 사실이 반영되었는지 확인한다. 실행 중 발견을 시간순으로 누적한 전역 진행 맥락은 결함으로 판단한다.

주요 변경의 코드 구조·인터페이스·핵심 로직은 구현 초안으로 검토한다. 모든 코드 줄이나 함수 시그니처의 완성을 요구하지 않는다. task가 적용 가능성을 확인하며 조정할 수 있다는 이유로 주요 설계가 빠진 초안을 허용하지 않는다. 작업 견적이나 파일별 체크리스트가 없다는 이유만으로 비판하지 않는다. 내부 산출물이나 능력도 변경안을 실체화하거나 후속 태스크의 전제가 되면 정상적인 결과로 인정한다.

## 비판 검증

- Plan의 구현 방안이 부족하다고 비판할 때에는 무엇이 빠졌으며 그 때문에 어떤 변경 영향이나 주요 선택을 판단할 수 없는지 코드 근거와 함께 특정한다. 단순히 더 상세한 명세나 파일별 작업 목록을 요구하지 않는다.
- 실행 중 발견의 반영 누락을 비판하려면 발견을 확인한 변경 증거와 그 발견이 영향을 주는 Plan 위치를 함께 특정한다.
