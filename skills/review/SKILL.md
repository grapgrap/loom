# Review

산출물과 근거를 대조하고 반례를 확인해 잘못된 판단이나 검증의 공백을 찾는다. 독립적인 검토 요청은 조사와 보고까지 수행하고, [work](../work/SKILL.md)의 일부라면 확인한 문제를 실행 담당자에게 전달한다. 문서 검토와 결과 보고에는 [write](../write/SKILL.md)를 적용한다.

## 검토 대상과 기준을 정한다

사용자가 지정한 설계, 파일, diff, 커밋이나 PR을 검토한다. 대상을 지정하지 않았다면 이번 작업의 변경 범위를 확인한다. 사용자 목표와 유지할 계약을 파악하고, 작성자의 설명이 실제 산출물과 검증 근거에 부합하는지 확인한다.

책임 배치나 외부 계약이 바뀌면 [architect](../architect/SKILL.md)에서 정한 장기 목표와 이번 범위를 구분한다. 목표 구조의 타당성을 판단하는지, 이번 구현과 전환 단계의 완료 조건을 확인하는지 밝힌다.

## 실패 경로와 판단 근거를 확인한다

변경이 잘못된 결과를 만들 수 있는 경로와 근거가 부족한 판단을 고른다. 설계, 구현과 검증이 사용자 목표 및 보존하기로 한 조건을 충족하는지 대조한다. 책임이나 계약이 바뀌었다면 다음을 확인한다.

- 책임에 대한 설명이 실제 구현과 호출 관계에 맞는가? 제안한 책임 배치를 현재 구조로 가정하지 않았는가?
- 레퍼런스가 제시한 보장의 전제가 이번 설계에서도 성립하는가? 구조가 비슷하다는 이유만으로 같은 결과를 기대하지 않았는가?
- 범위와 전환 순서가 목표와 유지할 계약을 충족하는가? 정보나 보장의 손실, 전환 비용, 임시 구조의 유지 이유와 해소 조건을 빠뜨리지 않았는가?

구현 중 발견한 사실이 기존 전제를 반박했다면 설계와 완료 주장에 반영됐는지 확인한다. 현재 사용하는 문서가 실제 동작과 다르면 지적하되, 과거 작업 기록을 현재 설계처럼 갱신하도록 요구하지 않는다.

## 위임 결과를 검토한다

위임 결과라면 조율자가 전달한 현재 명세와 완료 조건별 보고를 제출된 산출물과 대조한다. 제출 후 명세가 달라졌다면 변경 내용을 반영한 결과를 다시 받는다.

검토를 위임받은 작업자는 지적과 근거를 조율자에게 반환한다. 조율자는 검토 근거에 따라 결과를 수락하거나 보완할 조건을 명시해 수정을 요청한다. 독립적인 검토만 맡았다면 결과를 임의로 수락하지 않는다.

## 확인한 문제를 보고한다

보고 전에 자신의 지적을 반박해 본다. 이미 처리한 경로, 의도적으로 감수한 비용이나 적용되지 않는 전제를 결함으로 오인하지 않았는지 확인한다. 가능하면 반례를 실행한다.

장기 목표와의 차이나 범위 밖의 기존 문제만으로 이번 구현을 결함이라고 판단하지 않는다. 다만 의도적으로 미룬 문제나 수용한 비용도 이번 목표 또는 유지할 계약을 위반한다면 근거와 함께 지적한다.

확인한 문제를 영향이 큰 순서로 보고한다. 각 지적에는 위치, 재현 결과나 논증 가능한 근거, 사용자에게 미치는 영향을 포함한다. 근거가 부족하면 결함으로 단정하지 말고 확인할 질문으로 남긴다. 문제가 없으면 검토 범위와 검증의 한계를 설명한다. 정해진 지적 수를 채우기 위해 문제를 만들지 않는다.
