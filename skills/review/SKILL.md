# Review

## 테스트를 읽기 전에 판단 기준을 복원한다

사용자의 결정과 대표 장면, 기존 호출자가 의존하는 계약에서 기대 결과와 중요한 책임 경계를 찾는다. PR에 적힌 주장과 테스트의 기대값도 검토 대상이다. 예시를 만들기 위한 값, 모델 검사 가정, 미룬 정책과 구현자에게 맡긴 선택을 제품의 약속과 구별한다.

## 합의와 테스트를 양방향으로 읽는다

- **약속을 어긴 구현도 통과하는가?** 합의한 조건이나 사건 순서를 바꿔 보고, 잘못된 상태나 유실된 이력을 검증문이 실제로 감지하는지 확인한다. 모의 객체가 이미 기대 결과를 돌려준다면 실제로 검사한 경계까지 추적한다.
- **약속을 지킨 구현도 실패하는가?** 각 기대값에서 합의로 거슬러 올라간다. 예시의 횟수를 운영 한도로 삼았거나 위임된 내부 호출 순서를 고정했다면, 같은 약속을 지키는 다른 구현이나 입력 하나로 불필요한 제한을 보여준다.

첫 테스트만 있어도 두 질문을 검토할 수 있다. 어떤 제약의 근거가 부족하다면 반대 정책에도 같은 기준을 적용한다. 가능한 다른 구현은 해당 제약이 필수가 아님을 보이는 반례로 쓴다. 설계 리뷰에서는 같은 장면을 모델에 대입해 역할이 판단에 필요한 정보를 갖는지, 그림이 검사한 전이를 나타내는지, 모델에서 보인 성질이 어떤 가정에 의존하는지 살핀다.

## 실제 경로에서 반례를 확인한다

구현이 있으면 사용자 진입점부터 결과를 결정한 코드까지 따라간다. 정상 경로와 결과가 같은 복구 경로에서도 합의한 역할이 상태 변경을 맡는지 확인한다. 같은 규칙이 분산돼 있으면 어느 변경에서 경로 간 차이가 생기는지 짚는다. 반례를 재현하거나 코드로 경로를 확정하고, 호출자의 다른 보호 조건이 실제로 막는지도 확인한다.

영향이 큰 발견부터 어떤 장면에서 기대와 실제가 갈리고 무엇이 달라지는지 설명한다. 코드 위치나 실행 근거를 붙인다. 테스트 누락, 기대값의 과잉 제약, 실제 구현 위반에 따라 고칠 곳을 구별한다. 제품 동작을 새로 정해야 할 때만 선택을 사용자에게 돌려준다. 반례를 찾지 못하면 검사한 범위와 남은 불확실성을 밝힌다.
