# Tidy

대화 세션을 컴팩션하듯 기존 압축 맥락과 새 기록을 함께 읽고 다시 구성한다. `record`는 맥락을 추가하고, `recall`은 검색 가능한 맥락을 불러오며, `tidy`는 그 누적 맥락을 압축한다. 저장된 기억은 영구 규칙만이 아니라 작업을 이어갈 수 있는 맥락이다. 일반화한 패턴을 만들어야만 세부를 덜어낼 수 있는 것은 아니다.

## 관련 맥락을 준비한다

[작업 맥락](../work/references/context.md)의 CLI와 저장 권한 절차를 사용한다. `tidy prepare --work <id>`로 관련 업무와 프로젝트 공통 기억, 새 기록과 현재 업무 상태를 읽는다. 업무에 걸친 주제는 `--work` 없이 `--query`로 찾는다. 기본 준비는 새 기록이 없어도 기존 기억을 포함하며 `--revisit`은 같은 동작의 호환 옵션이다. 전체 프로젝트를 매번 정리하지 않는다.

묶음의 `records`와 선택한 `current.memories`를 읽고, 부족한 근거는 `search`와 `read --ref`로 보충한다. 그래프가 판단에 필요하면 `graph`로 관련 관계를 조회한다. 준비 응답의 전체 그래프가 필요할 때만 `--full`을 사용한다. 검색 순위와 기록 시각만으로 판단의 유효성을 정하지 않는다.

`--limit`과 페이지별 remaining을 확인한다. 기존 기억은 앞부분만 읽고 나머지를 그대로 복사하지 않는다. 읽지 않은 원본이 있는 묶음을 처리 완료로 반영하지 않는다. 페이지와 snapshot의 일관성은 [준비 계약](references/consolidation.md#준비)을 따른다. `snapshot: null`이면 선택한 기록과 기억이 없으므로 종료한다.

## 누적 맥락을 다시 구성한다

다음 작업자가 현재 위치와 판단을 이해하고 다음 구간을 실행할 수 있는 짧은 재개용 브리프를 작성한다. 각 내용을 빼면 다음 판단이나 행동이 달라지는지, 필요할 때 원본에서 복원할 수 있는지를 기준으로 선별한다. 현재 질문의 답만 남기지 말고 전체 과제의 목표와 완료 조건을 유지한다.

- 현재 목표와 맡긴 범위, 유효한 사용자 제약, 작업 위치, 다음 행동과 완료 조건을 우선한다. 합의·철회·보류·제안을 구분하고 다음 판단에 필요한 이유와 반복하면 안 되는 실패를 남긴다.
- 완료한 구현의 상세 목록, 과거 검사 수치와 진행 경과는 원본 ref와 필요한 조회 단서로 옮긴다. 현재 행동에 직접 필요한 정확한 값·경로·계약과 실패 경계는 본문에 둔다. 현재 변경의 검증 여부와 과거 검증의 적용 범위를 보존하며, 제안을 합의로 바꾸거나 과거 통과를 현재 변경의 증거로 쓰지 않는다.
- 한 번의 응답·도구 실행·실험에만 적용한 지시는 지속할 업무 제약으로 바꾸지 않는다. 예를 들어 현재 응답에서 명령을 실행하지 않는다는 조건을 이후 업무의 테스트 금지로 저장하지 않는다. 지속 범위가 불분명하면 적용 시점과 조건을 함께 남긴다.
- 같은 설명은 합치고, 대체된 상태는 현재 설명으로 교체한다. 선택의 이유나 재발 방지에 필요한 경위만 남긴다. 날짜나 리비전별 진행 로그를 현재 본문에 계속 덧붙이지 않는다.
- 기존 본문과 새 내용을 함께 재작성한다. `새 문단 + 기존 본문`이나 출처 배열의 기계적인 누적을 기본 갱신 방식으로 사용하지 않는다. 본문·미해결 사항·이유에 같은 설명을 반복하지 않는다. `sources`에는 현재 주장과 생략한 세부의 복원을 뒷받침하는 원본을 선별해 연결한다. 과거 원본과 정리 리비전은 따로 남으므로 모든 경과를 현재 본문에 복제할 필요가 없다.
- 같은 맥락의 갱신은 같은 ID를 사용한다. 업무별 맥락은 업무 범위를 유지하고, 다른 업무에도 적용되는 조건이 확인된 내용만 프로젝트 공통 기억에 둔다. 같은 ID의 범위는 바꿀 수 없으므로 잘못된 범위는 새 ID로 옮기고 이전 기억을 근거와 함께 제외한다.

기억 여러 개를 통합하면 [수용 계약](references/consolidation.md#경험을-다른-기억에-수용한다)의 `absorb`를 사용한다. 더는 적용하지 않는 기억은 `retire`로 제외한다. 하나의 기억을 짧게 다시 쓰는 데 두 연산은 필요하지 않다. 조건을 보존한 일반화가 유용하면 패턴을 만들되, 모든 정리에 요구하지 않는다. 현재 필요한 구체 계약과 예외는 유지한다.

관련 그래프도 바뀌었다면 [그래프 계약](../work/references/context-graph.md)에 따라 근거와 적용 조건을 갱신한다. 원본에 담긴 판단 전체를 대체했다고 확인한 경우에만 `supersedes`를 사용한다. `reviewNeeded`가 표시한 추론은 전제와 현재 조건을 대조해 재판단한다.

managed 업무의 정의, 진행과 검증 상태는 업무 CLI가 소유한다. tidy는 이를 중복 일지로 복제하거나 상태를 변경하지 않는다. 기존 checkpoint 업무의 상태는 최신 원본과 사용자 목표를 대조하며, 조사만 끝난 구현 업무를 완료로 바꾸지 않는다. 정리 중 발견한 다른 업무의 실행과 외부 연락은 정리 권한에 포함되지 않는다.

## 반영하고 컴팩션 결과를 확인한다

[변경분](references/consolidation.md#변경분)을 `tidy apply`의 stdin에 전달한다. 기억 파일이나 저장용 입력 파일을 직접 편집하지 않는다. 원본의 물리적 삭제는 컴팩션과 다른 `forget` 계약이다.

CLI는 출처, snapshot과 상태 일관성을 검사한다. 의미가 보존됐는지는 에이전트가 다음 기준으로 확인한다.

- 현재 목표, 유효한 판단, 미확정 사항과 다음 행동을 전후에 동일하게 이해할 수 있는가?
- 다음 실행에 필요하지 않은 세부와 반복을 덜어냈고, 필요한 세부를 원본 ref와 조회 단서로 복원할 수 있는가?
- 일회성 지시를 지속 제약으로 바꾸거나, 적용 조건을 없애 허용·금지할 행동을 바꾸지 않았는가?
- 후속 기록이 추가돼도 전체를 재구성했는가, 이전 로그를 다시 쌓았는가?

미처리 기록을 모두 반영한 것만으로 컴팩션이 끝난 것은 아니다. 원본에 있는 모든 사실을 보존하려고 본문을 늘리지 않는다. 일정 압축률이나 글자 수를 강제하거나 문자열을 잘라 맞추지 않으며, 필요한 재개 맥락 때문에 길어졌다면 그 이유를 설명한다. 이미 충분히 간결하면 변경 없이 검토를 마칠 수 있다. 같은 내용과 같은 신호로 정리를 반복하지 않는다.

기본 반영 응답은 리비전과 처리 범위, 변경한 항목의 ID와 동작을 반환한다. 전체 변경 전후 본문은 같은 요청을 `--full`로 재조회할 때 확인한다. 재시도와 충돌은 [반영 계약](references/consolidation.md#반영과-실패)을 따른다. 필요한 기억만 `recall --work <id> --query <주제>`로 확인하고, 원본 연결은 정확한 ref로 확인한다.

결과는 무엇을 합치거나 교체했고 무엇을 보존했는지, 남은 미해결 사항이 무엇인지 짧게 설명한다. 실제 변경이 없으면 검토만 마쳤음을 알린다. 작업 자체의 완료와 맥락 정리의 완료를 구분한다.
