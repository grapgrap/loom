# Tidy

이후 작업의 에이전트가 현재 유효한 합의와 진행 상태를 복원하고 원본 근거를 확인할 수 있게 한다. 일상 기록은 원본으로 보존하고, 정리 결과는 별도로 갱신한다. 업무 종결이나 세션 종료를 요구하지 않는다.

## 정리할 범위를 고정한다

[작업 맥락](../work/references/context.md)의 진입점으로 프로젝트를 확인한다. 실행 환경과 저장 권한에도 같은 절차를 적용한다. `tidy prepare`를 실행해 미처리 기록 묶음, 기존 기억과 업무 상태, snapshot ID를 받는다. 데이터는 체크아웃 밖의 기존 프로젝트 경로에 저장한다.

새 기록이 없으면 종료한다. 한 묶음의 모든 원본을 읽을 수 있도록 `--limit`을 조절한다. 일부를 읽지 못한 채 그 묶음을 처리 완료로 반영하지 않는다. 남은 기록은 다음 묶음으로 이어갈 수 있다.

## 근거를 읽고 정리한다

새 기록을 모두 검토하고, 쟁점에 맞는 검색어로 `search`를 실행한다. 판단에 필요한 이전 기록과 기존 기억의 출처를 `read --ref`로 읽는다. 검색 순위나 기록 시각만으로 현재 유효한 결정이라고 판단하지 않는다.

- 같은 뜻의 기록은 재사용할 판단으로 합친다. 원본을 반복 인용한 횟수를 독립된 근거의 수로 세지 않는다.
- 합의 변경, 실패 조건, 검증 결과와 남은 일을 구분한다. 제안이나 미해결 모순은 `unresolved`로 남긴다.
- 업무에 한정된 판단은 그 범위를 유지한다. 프로젝트 기억으로 올릴 때에는 다른 업무에도 적용할 근거와 조건을 적는다.
- 기존 기억을 바꿀 때 같은 ID를 사용한다. 중복되거나 더 이상 적용하지 않을 정리된 기억은 이유와 근거를 붙여 `retire`한다.
- 현재의 판단을 뒷받침하는 원본을 `sources`로 연결한다. 원본에 담긴 판단 전체가 대체됐다고 확인한 경우에만 `supersedes`로 연결한다.

업무 상태는 검증 근거에 맞춰 갱신한다. 정리를 실행했다는 이유로 업무를 완료 처리하지 않는다. 기록에 등장하는 다른 업무의 실행이나 외부 연락은 맡긴 정리 범위에 포함되지 않는다.

## 변경분을 반영하고 확인한다

[반영 계약](references/consolidation.md)을 읽고 필요한 기억·업무 상태·퇴역 항목만 JSON stdin으로 `tidy apply`에 전달한다. 언급하지 않은 기존 항목은 유지된다. 저장용 입력 파일이나 기억 파일을 파일 편집 도구로 만들지 않는다.

출처가 없거나 형식이 틀리면 원본부터 확인해 수정한다. 리비전 충돌이면 새 snapshot과 최신 기억을 읽고 변경분을 재검토한다. 이전 결과를 최신 번호에 맞춰 그대로 덮어쓰지 않는다.

반영 후 관련 업무의 `recall`과 필요한 원본 조회로 현재 판단·미정리 기록·근거 연결을 확인한다. 원본 기록은 유지하고, 사용자에게 기억 파일 검토를 요구하지 않는다. 정리 범위와 남은 미해결 사항을 필요한 만큼만 알린다.
