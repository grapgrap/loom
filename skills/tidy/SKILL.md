# Tidy

누적 기록에서 현재 유효한 합의와 업무 상태를 정리해 다음 작업에서 복원할 수 있게 한다. 정리 결과에는 근거가 되는 원본을 연결하고, 원본은 보존한다. 작업 도중에도 실행할 수 있다.

## 정리할 범위를 고정한다

[작업 맥락](../work/references/context.md)의 CLI와 실행 환경·저장 권한 절차를 사용한다. [준비 명령](references/consolidation.md#준비)인 `tidy prepare`로 미처리 기록 묶음, 현재 기억·업무 상태, 반영에 사용할 `snapshot` ID를 받는다.

`snapshot`이 `null`이면 정리할 기록이 없으므로 종료한다. 묶음의 `records`를 모두 읽을 수 있도록 `--limit`을 정한다. 읽지 않은 기록이 있는 묶음은 처리 완료로 반영하지 않는다. 묶음 밖에 남은 기록은 다음 묶음에서 정리할 수 있다.

## 근거를 읽고 정리한다

묶음의 원본을 모두 검토한다. 쟁점에 맞는 검색어로 `search`를 실행하고, 판단에 필요한 이전 원본과 현재 기억의 출처를 `read --ref`로 읽는다. 검색 순위나 기록 시각만으로 결정의 유효성을 판단하지 않는다.

- 같은 뜻의 기록은 하나의 판단으로 합친다. 같은 원본의 반복 인용을 독립된 근거로 세지 않는다.
- 합의 변경·실패 조건·검증 결과·남은 일을 구분한다. 미확정 제안이나 해결되지 않은 모순은 `unresolved`로 남긴다.
- 업무에 한정된 판단은 범위를 유지한다. 프로젝트 기억으로 옮길 때에는 다른 업무에도 적용할 근거와 조건을 적는다.
- 기존 기억을 갱신할 때는 같은 ID를 사용한다. 중복되거나 더 이상 적용하지 않을 기억은 이유와 원본 근거를 붙여 `retire`로 현재 기억에서 제외한다.
- 현재 판단의 근거는 `sources`에 연결한다. 원본에 담긴 판단 전체를 대체했다고 확인한 경우에만 `supersedes`에 연결한다.

업무 상태는 실제 검증 근거에 따라 갱신한다. 기록을 정리한 시점과 업무를 완료한 시점을 구분한다. 기록에 등장하는 다른 업무의 실행이나 외부 연락은 정리 범위에 포함되지 않는다.

## 변경분을 반영하고 확인한다

[변경분의 반영 계약](references/consolidation.md#변경분)에 따라 갱신할 기억·업무 상태·제외할 기억만 JSON으로 작성해 `tidy apply`의 stdin에 전달한다. 생략한 기존 항목은 유지된다. 저장용 입력 파일이나 기억 파일을 편집 도구로 만들지 않는다.

입력이나 출처 오류는 해당 원본과 계약을 확인해 수정한다. 리비전이 충돌하면 새 `snapshot`과 현재 기억을 읽고 변경분을 재검토한다. 이전 결과의 리비전 번호만 바꾸어 덮어쓰지 않는다.

반영 후 관련 업무를 `recall`로 조회해 현재 기억·업무 상태·미처리 기록을 확인한다. 필요한 원본은 `read --ref`로 읽어 근거 연결을 확인한다. 사용자에게 기억 파일 검토를 요구하지 않으며, 정리 범위와 남은 미해결 사항을 필요한 만큼 알린다.
