# Tidy

다음 작업자가 목표와 현재 판단을 이해하고 다음 구간을 실행할 수 있도록 누적 맥락을 다시 구성한다. 현재 판단을 바꿀 정보와 조건을 남기고, 지나간 경과는 원본 ref와 조회 단서로 돌린다. 일반화한 패턴을 만들어야만 세부를 덜어낼 수 있는 것은 아니다. 기억의 표현과 검토 결과를 갱신하며, 증거의 채택·철회는 evidence, 업무의 정의·검증·완료는 work가 소유한다.

## 관련 맥락을 준비한다

[작업 맥락](../work/references/context.md)의 CLI와 저장 권한 절차를 사용한다. `tidy status --work <id> --purpose resume`로 선택한 범위를 확인하고 [준비 계약](references/consolidation.md#준비)에 따라 `tidy prepare`를 호출한다. 업무에 걸친 주제는 --work 없이 --query로 고른다. 기본 준비는 새 원본과 현재 기억을 함께 선택하고, --revisit은 같은 동작의 호환 옵션이다. 전체 프로젝트를 매번 정리하지 않는다.

반환한 records·current.memories·batch와 dependencies를 읽는다. snapshot은 이번 선택과 정정 확인 기준을 고정한다. limit·offset과 각 remaining을 확인하고 읽을 수 있는 묶음으로 나눈다. current 기억의 다음 페이지는 별도로 준비한다. 이전 페이지에 없다는 이유로 항목을 새로 중복 생성하지 않는다.

snapshot이 null이면 선택한 항목이 없거나 같은 입력·목적을 이미 검토한 것이다. reviewed와 이전 결과를 확인하고 같은 묶음의 검토를 끝낸다. 다른 페이지나 범위의 remaining까지 완료됐다고 해석하지 않는다. 필요한 나머지는 해당 범위로 이어가고, 검토하지 않은 것은 남긴다.

## 원본과 현재 표현을 대조한다

batch 전체와 판단에 필요한 정확한 원본을 읽는다. 부족한 근거는 discover와 read로 보충한다. dependencies에 나타난 관련 정정·철회와 conflicts·gaps를 대조한다. 현재 표현의 sources가 존재한다는 것과 현재 적용할 수 있다는 것은 다르다. locator만 알고 원문에 접근하지 않았다면 읽었다고 기록하지 않는다.

현재 목표·완료 조건·사용자 제약·적용 대상과 버전·다음 행동을 유지하며 다음 기준으로 재작성한다.

- 각 내용을 빼면 다음 판단이나 행동이 달라지는지, 필요할 때 원본에서 복원할 수 있는지 판단한다. 완료한 구현의 상세 목록·과거 검사 수치·진행 로그는 원본으로 돌린다.
- 기존 본문과 새 내용을 함께 다시 쓴다. 새 문단을 앞에 붙이고 과거 본문을 계속 누적하거나 출처 배열을 기계적으로 늘리지 않는다.
- 합의·철회·제안·추론·미확인 관찰을 구별하고 적용 조건과 범위를 보존한다. 한 번의 응답에만 적용된 지시를 지속 제약으로 만들지 않는다.
- 같은 맥락은 같은 ID로 갱신한다. 다른 업무에도 적용할 근거가 없다면 업무 범위를 유지한다. 필요한 정확한 값·계약·예외와 해결되지 않은 충돌을 남긴다.
- sources는 현재 표현의 근거와 생략한 세부를 복원할 실제 원본으로 선별한다. 중요한 불확실성은 unresolved와 본문에 남긴다. 파생 표현을 독립적인 원본이나 채택 근거로 취급하지 않는다.

정리 중 의미상 채택·정정·철회가 필요하면 [evidence 계약](../work/references/context-evidence.md)으로 따로 반영한 뒤 새 snapshot을 준비한다. 업무 정의·진행·검증이 바뀌어야 하면 owner가 [업무 CLI](../work/references/context-work.md)로 처리한다. 여러 저장 명령을 하나의 원자적 변경으로 가정하지 않는다. 다른 업무의 실행이나 외부 연락은 정리 권한에 포함되지 않는다.

## 검토 결과와 변경분을 반영한다

[변경분 계약](references/consolidation.md#변경분)에 따라 snapshot·requestKey·reviewed·read와 memories·retire의 변경분을 stdin으로 전달한다. reviewed는 정확한 batch 전체, read는 실제 읽은 원본과 현재 표현의 집합이다. 판단 이유와 남은 공백은 reason·gaps에 남긴다. 읽지 않은 대상을 완료로 표시하지 않는다.

변경할 표현이 없으면 검토 결과만 반영한다. effect: no-change는 기억 리비전을 늘리지 않고 영수증을 저장한다. 같은 입력·목적의 검토는 이 결과를 재사용한다. reviewedAt은 검토 시각, recordedAt은 표현이 바뀐 시각이며 업무나 외부 대상의 검증 시각으로 대체하지 않는다.

관련 정정이나 기준 표현이 바뀌면 conflict를 반환한다. 새 snapshot·현재 표현·정정을 읽고 영향을 받은 판단만 다시 한다. 무관한 신규 원본은 현재 반영을 막지 않고 pending으로 남는다. 같은 요청의 응답을 잃었으면 같은 키와 입력으로 재시도하거나 tidy result --key로 회수한다. 새 키로 중복 적용하지 않는다.

기존 graph·works·absorb 연산은 legacy: true를 명시하는 호환 경로다. [그래프 계약](../work/references/context-graph.md)과 [수용 계약](references/consolidation.md#경험을-다른-기억에-수용한다)을 필요한 경우에만 사용한다. 기본 tidy는 과거 checkpoint나 기억을 새 현재 판단으로 자동 승격하지 않는다. 물리 삭제는 forget의 별도 계약이다.

## 결과를 확인하고 마무리한다

반영한 report.changes와 필요한 recall·read를 대조한다. 현재 목표와 유효한 판단·미확정 사항·다음 행동을 전후에 동일하게 이해할 수 있는지, 조건을 없애 허용·금지할 행동을 바꾸지 않았는지 확인한다. 모든 사실을 현재 본문에 복제하거나 일정 압축률을 강제하지 않는다.

무엇을 합치거나 갱신했고 왜 현재 표현에서 덜어냈는지, 무엇을 보존했는지와 남은 공백을 짧게 전달한다. 실제 변경이 없으면 검토만 마쳤다고 알린다. 맥락 정리의 완료와 사용자가 맡긴 작업의 완료는 구분한다.
