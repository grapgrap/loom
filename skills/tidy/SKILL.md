# Tidy

누적 경험을 재사용할 패턴과 현재 필요한 구체 기억으로 정리한다. 개별 경험이 조건과 책임을 보존한 패턴에 수용되면 그 경험의 세부는 현재 기억에서 잃어도 된다. 시간 경과나 정리 횟수를 손실의 근거로 삼지 않는다. 정리 결과에는 판단 근거를 연결한다. managed 업무의 현재 정의·진행·검증·수락 상태는 [업무 CLI](../work/references/context-work.md)가 소유한다. 작업 도중에도 실행할 수 있다.

## 정리할 범위를 고정한다

[작업 맥락](../work/references/context.md)의 CLI와 실행 환경·저장 권한 절차를 사용한다. [준비 명령](references/consolidation.md#준비)인 `tidy prepare`로 미처리 기록 묶음, 현재 기억·업무 상태, 반영에 사용할 `snapshot` ID를 받는다.

새 기록과 관련된 기존 기억을 함께 재검토하거나 새 기록 없이 기억만 정리할 때는 `tidy prepare --revisit`을 사용한다. `--query`로 주제를, `--work`로 프로젝트 공통과 해당 업무의 범위를 좁힐 수 있다. 주제에 걸친 여러 업무를 비교할 때는 `--work` 없이 검색한다. 준비한 `current.memories`가 이번 snapshot에서 수용할 수 있는 기억이다.

`snapshot`이 `null`이면 정리할 새 기록과 선택된 재검토 기억이 없음을 보고하고 종료한다. 묶음의 `records`와 재검토할 기억을 읽을 수 있도록 `--limit`을 정한다. 읽지 않은 기록이 있는 묶음은 처리 완료로 반영하지 않는다. 묶음 밖에 남은 기록은 다음 묶음에서 정리할 수 있다.

현재 기억·업무 상태·제외 목록도 페이지로 반환된다. 관련 항목이 더 필요하면 [준비 명령의 페이지 계약](references/consolidation.md#준비)에 따라 조회한다. 첫 페이지에 없다는 이유로 기존 기억을 새 항목으로 중복 생성하지 않는다.

## 근거를 읽고 정리한다

묶음의 원본을 모두 검토한다. 쟁점에 맞는 검색어로 `search`를 실행하고, 판단에 필요한 이전 원본과 현재 기억의 출처를 `read --ref`로 읽는다. 검색 순위나 기록 시각만으로 결정의 유효성을 판단하지 않는다.

- 같은 뜻의 기록은 하나의 판단으로 합친다. 같은 원본의 반복 인용을 독립된 근거로 세지 않는다.
- 결과가 같았다는 이유만으로 일반화하지 않는다. 경험을 설명하는 조건과 책임을 패턴으로 남기고, 다른 작업에도 적용되는지 판단할 때 명시된 결정과 추론을 구분한다.
- 수용한 경험은 [수용 계약](references/consolidation.md#경험을-다른-기억에-수용한다)의 `absorb`로 반영한다. 패턴이 담지 못한 예외, 현재의 정확한 계약과 미해결 사항은 별도 기억으로 남긴다. 모든 세부를 복원 가능하게 남겨야 하는 것은 아니며, 오래된 기억도 아직 수용되지 않았거나 현재 필요한 계약이면 구체적으로 유지한다.
- 합의 변경·실패 조건·검증 결과·남은 일을 구분한다. 미확정 제안이나 해결되지 않은 모순은 `unresolved`로 남긴다.
- 업무에 한정된 판단은 범위를 유지한다. 프로젝트 기억으로 옮길 때에는 다른 업무에도 적용할 근거와 조건을 적는다.
- 기존 기억을 갱신할 때는 같은 ID를 사용한다. 중복되거나 더 이상 적용하지 않을 기억은 이유와 원본 근거를 붙여 `retire`로 현재 기억에서 제외한다.
- 현재 판단의 근거는 `sources`에 연결한다. 원본에 담긴 판단 전체를 대체했다고 확인한 경우에만 `supersedes`에 연결한다.

[그래프 계약](../work/references/context-graph.md)에 따라 기존 대상과 진술도 대조한다. 같은 대상을 식별하고 원문에 명시된 진술과 추론을 구분해 실제 근거·적용 조건을 연결한다. 필요한 과거 원본은 graph의 경로와 search·read로 확인한다. 그래프의 대체 관계와 유효 상태는 이번 tidy apply에서 반영한다. 대체된 전제에 의존해 reviewNeeded가 생기는 추론을 살피고, 추가 업무가 필요하면 근거와 함께 실행 담당자에게 전달한다.

수용은 기억이 더는 유효하지 않다는 판단과 구분한다. `absorb`는 현재 기억의 본문을 제거하고 수용 대상과 이유를 남기며, `retire`는 더는 적용하지 않을 기억을 표시한다. 현재 CLI는 원본과 과거 정리본을 물리적으로 삭제하지 않는다. 이는 영구 보존을 요구하는 기억 정책이 아니라 이번 구현의 보관 범위이며, 명시적인 원본 삭제는 `forget` 계약을 따른다.

current.managedWorks는 읽기 전용이다. 현재 상태와 이력을 대조해 기억을 정리하되 tidy의 works로 managed 업무를 갱신하지 않는다. 정리 중 조건·진행·수락 판단이 달라져야 한다고 확인하면 그 근거를 담당 owner에게 전달한다. 기록을 정리한 시점과 업무를 완료한 시점을 구분한다. 다른 업무의 실행이나 외부 연락은 정리 범위에 포함되지 않는다.

사용자의 원래 목표와 하위 성과를 대조한다. 조사·방법 발견이나 단기 요청만 끝났다면 원래 구현 목표의 완료로 해석하지 않는다. blocked·paused·cancelled는 실제 막힘이나 사용자 보류·취소 근거를 확인한다. 새 요청이 있다는 이유만으로 이전 미완료 업무의 상태를 바꾸지 않는다.

기존 checkpoint 업무에만 이전 상태 정리 계약을 적용한다. 준비한 체크포인트의 최신 상태를 기본 반영하고 이후 원본을 함께 대조해 과거 상태로 되돌리지 않는다. 새 업무로 전환된 ID는 업무 CLI의 상태를 우선하며 기존 체크포인트로 덮어쓰지 않는다.

## 변경분을 반영하고 확인한다

[변경분의 반영 계약](references/consolidation.md#변경분)에 따라 기억·그래프와 필요한 기존 업무 요약의 변경분만 JSON으로 작성해 tidy apply의 stdin에 전달한다. `work:<id>@<revision>`도 근거로 인용할 수 있다. 생략한 기존 항목은 유지된다. 저장용 입력 파일이나 기억 파일을 편집 도구로 만들지 않는다.

입력이나 출처 오류는 해당 원본과 계약을 확인해 수정한다. 리비전이 충돌하면 새 `snapshot`과 현재 기억을 읽고 변경분을 재검토한다. 이전 결과의 리비전 번호만 바꾸어 덮어쓰지 않는다.

반영 후 관련 업무를 `recall`로 조회해 현재 기억·업무 상태·미처리 기록을 확인한다. 필요한 원본은 `read --ref`로 읽어 근거 연결을 확인한다. 사용자에게 기억 파일 검토를 요구하지 않으며, 정리 범위와 남은 미해결 사항을 필요한 만큼 알린다.

## 결과 리포트를 전달한다

`tidy apply`가 반환한 [결과 리포트](references/consolidation.md#결과-리포트)의 `report.changes`를 근거로 실제 변경을 모두 요약한다. 추가 작업의 유무와 관계없이 기억·업무·대상·진술의 추가·수정·대체·제외와 새로 미확정이 된 판단을 전달한다. 같은 변화에 속한 항목은 묶되, 무엇이 어떻게 달라졌고 왜 바뀌었는지 알 수 있게 한다. 추가로 해야 할 일과 미해결 사항도 함께 설명한다.

리포트는 반영한 결과를 설명한다. 반영하지 못한 제안은 변경된 내용과 구분한다. 여러 묶음을 처리했다면 각 묶음의 리포트를 모아 전체 결과를 요약한다. 실제 변경이 없으면 원본 검토만 마쳤음을 알리고, 남은 미처리 기록이 있으면 그 범위를 전달한다.
