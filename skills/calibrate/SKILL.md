# Calibrate

현재 concept과 flow의 목적이 프로젝트 목표에 부합하는지를 가늠하는 문서 감사.

review가 세션 단위의 검증이라면, calibrate는 누적된 설계가 프로젝트 목표에 여전히 부합하는지를 가늠하는 감사다. 발견을 리포트할 뿐 직접 교정하지 않으며, 교정 방향은 사용자가 shape 재진입으로 판단한다.

## 언제 실행하는가

- 설계가 누적되면서 프로젝트 목표와의 정렬이 흐려졌다고 느낄 때
- 사용자가 수동으로 호출한다

## Step 0 — 컨텍스트 로드

탐색은 현재 작업 대상 워크트리의 `.loom/` 파일을 기준으로 수행한다. 파일 목록·텍스트 검색 도구(예: `rg --files {대상 .loom 경로}`, `rg -l "{검색어}" {대상 .loom 경로}`, 없으면 동등한 도구)로 문서 경로를 확인한다. concept·flow는 아래 절차에 따라 전부 읽고, decision은 링크와 키워드로 후보를 좁힌 뒤 감사에 관련된 본문을 읽는다. 검색 결과가 없거나 맥락과 맞지 않으면 동의어·도메인 용어로 재검색한다. 위키링크는 대상의 파일명 또는 경로를 확인하여 따라가며, 역참조 검색은 실제 링크 표기에 맞춰 수행한다. 별도 검색 서비스 등록이나 인덱스 동기화를 요구하지 않는다.

1. 작업 대상 프로젝트의 `.loom/index.md`를 읽어 프로젝트 목표와 도메인 전체 지도를 파악한다.
2. index.md에 프로젝트 목표가 명시되어 있는지 확인한다. 목표가 부재하면 그 사실을 기록해 두고 감사를 계속한다 — concept들의 목적 간 정합성은 꼭대기 없이도 점검할 수 있다. 목표 부재는 리포트에서 별도로 알린다.
3. `.loom/concepts/`의 모든 concept과 `.loom/flows/`의 모든 flow를 읽는다.
4. 각 concept과 flow를 가리키는 위키링크를 `.loom/decisions/`에서 검색하여 관련 decision들을 확인한다.

## Step 1 — 룰 카탈로그 로드

`.loom/rules/index.md`가 있으면 읽어 어떤 룰과 컨벤션이 있는지 카탈로그를 인지한다.

파일이 없으면 카탈로그를 통한 추가 룰 로드를 생략하고 작업을 계속한다. 이미 제공된 프로젝트 지침과 확인된 합의는 그대로 적용한다. 카탈로그 부재만으로 파일을 생성하거나 사용자 확인을 요구하지 않는다.

rule은 이 프로젝트에서 항상 지켜져야 하는 강제적 합의, convention은 강하게 권장되지만 대체 가능한 형태이다. 인덱스를 통해 항목 목록과 각 항목의 호출 상황을 파악한다. 본문은 활용 시점에 필요한 항목을 골라낸 뒤 로드한다.

## Step 2 — 목적 정렬 감사

프로젝트 목표에 현재 concept과 flow의 목적이 부합하는지를 가늠한다. 프로젝트 목표가 부재하면 concept·flow 간 목적의 정합성을 점검한다. calibrate는 감사 결과를 리포트로 출력할 뿐, concept이나 decision을 직접 변경하지 않는다. 리포트를 바탕으로 shape 재진입 여부는 사용자가 판단한다.

### 룰 카탈로그 활용

감사의 기준에는 rule·convention이 포함된다. 인지한 룰 카탈로그를 도구 선택 절차로 활용한다:

1. 지금 수행하려는 행동을 의식적으로 명시한다
2. 카탈로그에서 그 행동에 적용될 가능성 있는 항목을 골라낸다
3. 골라낸 항목의 본문 파일을 로드해 정의된 형태를 파악한다
4. 본문에 따라 감사를 진행한다

### 감사 차원

다음 네 차원에서 감사한다. 차원별로 발견 사항과 근거를 수집한다.

#### 목적 연결의 무결성

각 concept과 flow의 목적이 프로젝트 목표에 부합하는지 점검한다. 프로젝트 목표가 부재하면 concept·flow가 상호 링크로 가리키는 관계를 따라 순회하며, 서로 간 목적의 정합성을 점검한다.


**concept:**

- concept의 목적이 프로젝트 목표에 부합하는가 — 어떤 프로젝트 목표에도 부합하지 않고, 다른 concept의 목적과도 정합하지 않는 concept은 방향 없는 누적이다
- 두 concept이 같은 목적을 주장하는가 — 목적의 중복은 경계가 흐려진 신호다
- 한 concept의 목적이 과적되었는가 — 하나의 concept이 여러 프로젝트 목표에 걸쳐 있으면 분화가 필요한 신호다

**flow:**

- flow의 목적이 프로젝트 목표에 부합하는가 — 어떤 목표에도 부합하지 않고, 현재 concept 간 협력 수요에도 대응하지 않는 도메인 간 경로는 방향 없는 누적이다
- 프로젝트 목표가 요구하는 도메인 간 협력의 경로가 flow로 존재하지 않는가 — 목표에 복무하는 경로의 누락이다

#### 전제·제약 무효화

concept과 decision에 기록된 전제가 여전히 유효한지 점검한다. 전제가 무효화된 concept은 프로젝트 목표에 복무하던 근거가 무너진 것이다.

- 무효화가 감지되었는데 유지 decision이 누락된 경우는 목적 위계의 단절 의심 지점이다
- 제약이 풀린 구간이 있는가 — decision의 "제약이 없었다면" 항목을 이제 추구할 수 있는가

#### 분화의 옵션 가치 재평가

- 분화된 concept이 충분한 쓰임을 얻었는가 — 얻지 못한 분화는 프로젝트 목표에 복무하지 않는 누적이며, 다시 합칠 대상일 수 있다
- 비대화가 방치된 concept이 있는가 — 뒤늦게 분화가 필요한 상태가 누적되어 있지 않은가

#### concept과 decision의 괴리

decision이 방향을 전환했는데 concept의 목적이 갱신되지 않은 경우, 목적 위계에 단절이 생긴 것이다.

- decision의 결론이 concept의 현재 목적과 모순되는가
- 괴리를 만든 decision을 최신순으로 추적하여 원인을 파악한다

### 비판 검증

감사 차원에서 수집한 발견 사항 각각에 대해, 해당 concept·flow에 연관된 decision의 전제·제약과 선택 근거가 현재에도 유효한지 확인한다. 현재에도 유효한 근거로 정당화되는 트레이드오프를 반복 지적한 경우에만 비판에서 제외한다. 전제·제약이 달라졌거나 선택 근거가 현재 프로젝트 목표를 뒷받침하지 못하면, 과거에 의도한 선택이어도 재평가한다. 이 단계를 거친 발견 사항만 리포트에 포함한다.

### 리포트 작성

감사 결과를 감사 차원별로 구획한 리포트로 정리해 사용자에게 제시한다. 프로젝트 목표가 부재했다면 리포트 서두에 "목적 위계의 꼭대기 부재"를 별도로 알린다 — 목표 대비 정렬 점검이 불완전했음을 명시한다. 각 항목에는 다음을 포함한다:

- 발견된 이탈의 내용
- 관련 concept과 decision의 경로
- 이탈이 프로젝트 목표와의 정렬에 미치는 영향

리포트를 제시한 뒤 shape 재진입 여부는 사용자에게 맡긴다. 사용자가 재진입을 선택하면 감지된 이탈 중 어느 범위를 shape의 입력으로 삼을지 함께 결정한다. calibrate는 concept이나 decision을 직접 수정하지 않는다.
