# Coordinate

메인 세션에서 맡은 목표를 구체화하고 작업 큐와 지속적인 작업 세션을 조율한다. 메인 세션은 여러 개 존재할 수 있고, 각각 작업 세션을 0개 이상 둔다. 하위 작업을 조율하는 작업 세션은 그 범위에서 메인 역할을 맡는다.

직접 수행에는 [work](../work/SKILL.md)를, 세션 내부의 단발성 서브 에이전트 협업에는 [orchestrate](../orchestrate/SKILL.md)를 적용한다. 설명과 보고에는 [write](../write/SKILL.md)를 적용한다.

## 조율 범위와 실행 수단을 확인한다

사용자 목표, 완료 조건, 맡긴 전달 지점과 현재 작업을 확인한다. 사용자와 프로젝트가 정한 세션 생성, 위임 범위와 모델 정책, 호스트의 권한을 따른다. 이미 전달된 권한과 모델 선택은 재사용하고, 실제로 정하지 않은 필요한 선택만 확인한다. 장기 방향에 대한 동의를 새 작업의 실행 권한으로 확대하지 않는다.

호스트가 제공하는 독립 세션 생성, 조회, 메시지 전달, 대기, 재개와 정리 수단을 확인해 사용한다. 작업 세션은 사용자가 대화를 열고 후속 작업을 이어갈 수 있어야 한다. 필요한 수단이나 권한이 없으면 해당 세션 운영에 미치는 영향과 진행 가능한 범위, 필요한 조치를 설명한다. 제공되지 않는 지속 실행을 보장하거나 독립 작업 세션을 단발성 서브 에이전트로 대체하지 않는다.

다른 메인 세션이 맡은 작업과 범위가 겹치면 조정 책임자와 담당을 확인한다. 맡은 범위 밖의 세션을 임의로 지휘하지 않는다.

## 일을 구체화하며 작업을 발견한다

분해되지 않은 요청에서도 시작한다. 필요한 [understand](../understand/SKILL.md), [explore](../explore/SKILL.md), [architect](../architect/SKILL.md)를 적용해 핵심 사용 흐름과 도메인, 책임과 경계, 협력 관계를 발견한다. 직접 수행할 일은 `work`로 진행한다.

독립적인 목표와 완료 조건, 다른 작업과의 접점이 드러난 영역부터 작업 세션에 맡긴다. 세부 설계도 위임할 수 있으며, 확정된 공통 계약과 아직 검토할 가정을 구분해 전달한다. 남은 문제의 탐색과 전체 설계는 메인에서 계속한다.

새로 발견한 하위 책임은 자식 작업으로, 같은 수준의 별도 책임은 형제 작업으로 연결한다. 기존 작업의 범위와 기여를 대조해 중복 등록을 피하고, 목표와 우선순위를 확인한 뒤 실행 대상을 정한다. 발견한 작업을 모두 즉시 실행하지 않는다.

## 공통 기록에서 큐를 조정한다

작업을 처음 등록하거나 배정하기 전에 [공통 작업 기록](../../references/task-record.md)을 읽는다. 모든 관련 세션이 접근할 원본을 하나 정하고 위치를 전달한다. 기존 공유 기록을 재사용하고, 파일로 조율해야 하면 [실행 계획](../../templates/execution-plan.md)을 사용한다. 작업 기록을 메인 대화에만 보관하거나 세션마다 별도 사본으로 관리하지 않는다.

사용자 우선순위와 각 작업의 목표 기여, 선행 결과를 연결한다. 실행 가능한 작업 중 우선순위에 따라 다음 일을 고른다. 선행 결과가 필요한 작업은 재개 조건을 남기고, 독립적인 작업은 계속한다. 실행 중이거나 이미 수락한 작업을 중복 배정하지 않는다.

형제 관계는 공통 부모에서, 실행 가능 여부는 의존 작업의 수락과 필요한 입력에서 판단한다. 호스트의 세션 실행 상태와 작업 결과의 수락 여부를 구분한다.

## 수행할 세션을 정하고 계약을 전달한다

현재 맥락에서 끝낼 일은 메인이 수행한다. 관련 작업과 대화 맥락이 남아 있으면 기존 작업 세션을 재사용하고, 독립적으로 설계하고 진행할 범위에는 새 작업 세션을 배정한다. 각 작업의 조정 책임자, 수행 세션과 통합 담당을 명시한다.

작업 세션에는 작업 ID와 공통 기록, 목표와 완료 조건, 범위와 권한, 선행 산출물과 공통 계약, 작업 환경과 보고 경로를 전달한다. 코드 변경이 겹치면 작업 공간을 분리하거나 수행 순서를 정한다. 서브 에이전트의 같은 워크트리 규칙을 독립 세션 전체에 강제하지 않는다.

작업 세션이 [지속 작업 세션 지침](../work/references/delegated-session.md)을 읽도록 한다. 명세와 원본 근거에 대한 이해가 어긋나면 계약을 보완한다. 범위 안의 세부 설계와 실행 방법은 작업 세션에 맡긴다.

## 사용자와 작업 세션을 연결한다

사용자와는 기본적으로 메인에서 소통하면서, 해당 작업 세션의 대화에도 직접 참여할 수 있게 연결한다. 사용자의 의도와 우선순위, 후속 요청을 전달하고, 진행 결과와 판단이 필요한 질문을 사용자에게 돌려준다.

작업 세션은 질문, 막힘, 새로 발견한 작업, 공통 계약의 변경과 검토 가능한 결과를 보고한다. 직접 대화에서 결정된 범위나 계약, 우선순위 변경도 공통 기록에 반영하고 영향을 받는 세션에 전달한다. 다른 작업에 영향이 없는 세부 논의는 해당 세션에서 이어간다. 호스트가 해당 세션에서 직접 승인을 요구하면 그 경로를 사용자에게 안내한다.

원본 대화, 현재 담당과 상태, 산출물과 검증 근거를 작업 기록에서 찾아갈 수 있게 한다. 보고와 연결된 근거로 판단하고, 쟁점이 있을 때 해당 원본을 확인한다. 모든 내부 실행 로그를 메인 맥락에 반복해서 복사하지 않는다.

## 결과를 수락하고 후속 작업을 잇는다

보고를 현재 계약과 실제 산출물, 검증 근거에 대조한다. [verify](../verify/SKILL.md)로 완료 조건을 확인하고, 검토가 필요하면 [review](../review/SKILL.md)를 적용한다. 충족한 결과는 사용한 산출물과 함께 수락하고, 부족하면 해당 조건과 근거를 명시해 기존 작업 세션에 보완을 요청한다.

필요한 선행 결과를 수락하면 그 산출물과 버전 또는 커밋을 후속 작업에 전달한다. 계약 변경이 기존 결과를 무효화하면 영향을 받는 작업과 검증을 조정한다. 상위 작업은 필요한 하위 결과의 수락과 합쳐진 흐름의 검증까지 확인한다.

결과 제출과 세션 종료를 구분한다. 수락한 작업 세션은 맥락을 보존한 채 유휴 상태로 두고 관련 요청으로 재개한다. PR 이후 CI나 리뷰 대응도 맡긴 전달 지점과 호스트 실행 수단의 범위에서 이어간다. 전달 지점을 충족하고 남은 후속 작업의 담당까지 확인했으면 호스트의 정리 수단으로 마무리한다.

전체 완료 조건과 맡긴 전달 지점을 충족했을 때 결과와 검증 근거를 보고한다. 막힌 작업은 영향, 담당과 재개 조건을 남기고, 사용자 판단이 필요한 선택에는 권고안을 함께 제시한다.
