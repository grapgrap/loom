# Diagnose

## 실패한 장면을 고정한다

사용자가 어디에서 무엇을 했고, 무엇을 기대했으며, 실제로 무엇을 보았는지 맞춰 본다. 기대 동작은 사용자 발언이나 기존 계약에 연결한다. 그 조건에서 실행하거나 당시의 실행 기록을 확인한다. 비슷한 정상 흐름만 실행할 수 있었다면 재현한 범위와 아직 빠진 조건을 밝힌다. 코드와 기록으로 확보할 수 없는 정보가 조사를 막으면, 다음 판단에 필요한 입력이나 관찰만 사용자에게 요청한다.

재현만 맡았으면 시작 조건, 행동, 관찰한 결과와 다시 확인할 방법을 전달하고 마친다. 원인 조사까지 맡았으면 확인한 증상을 출발점으로 삼는다.

## 원인을 가른다

실패한 진입점에서 잘못된 결과를 만든 판단이나 상태 변화까지 따라간다. 역할 간 계약을 알아야 경로가 풀리면 `$loom:understand`로 해당 경계를 확인한다. 입력과 상태가 알려져 있고 코드가 결과를 결정한다면 그 경로로 원인을 설명한다.

여러 원인이 같은 증상을 설명할 때는 후보들의 예측이 달라지는 관찰을 고른다. 조건을 하나 바꿔 실행하거나 경계에서 주고받은 값을 관찰해 후보를 좁힌다. 여전히 여러 설명이 가능하면 확인된 사실과 남은 가설, 이들을 구별할 다음 관찰을 구분한다.

## 회복할 동작을 전달한다

원인이 어떻게 증상으로 이어지는지 코드 위치와 실행 근거로 보여준다. 수정까지 맡았으면 회복할 동작과 책임을 기준으로 다음 작업을 고른다. 약속이 정해져 있으면 재현 조건과 원인, 보존할 약속을 `$loom:implement`에 넘긴다. 기대 동작이나 판단을 맡을 역할을 새로 정해야 하면 결과가 갈리는 장면을 `$loom:architect`에 전달한다.
