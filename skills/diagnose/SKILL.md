# Diagnose

## 증상 확정

사용자 행동을 재현하거나 실제 실행 기록을 확인해, 어떤 조건에서 기대 결과와 실제 결과가 어긋났는지 적는다. 재현 확인만 맡았으면 시도한 조건과 관찰한 결과를 전달하고 마친다. 증상을 확인할 근거가 부족하면 추가로 필요한 입력이나 기록을 밝히고, 근거를 확보한 뒤 원인을 조사한다.

## 원인 조사

1. **가설 수립** — 확인한 증상을 설명할 원인 후보를 세운다. 여러 원인이 같은 증상을 낼 수 있으면 후보마다 어떤 관찰이 그 가설을 지지하거나 배제할지 정한다.
2. **코드 확인** — 증상이 발생한 진입점부터 코드를 따라가며 실제로 가능한 후보를 추린다. 책임과 호출 관계를 알아야 후보를 구별할 수 있으면 `$loom:understand`로 해당 흐름을 확인하고 조사를 이어간다. 확인한 입력과 상태로 실행 경로와 잘못된 결과가 모두 정해지면, 그 경로를 근거로 원인 조사를 마친다.
3. **검증** — 코드만으로 원인을 가릴 수 없으면 후보들의 예측이 갈리는 지점에 작은 검증 코드를 두고 증상을 재현한다. 관찰값을 각 예측과 대조해 후보를 좁힌다. 같은 결과가 여러 후보에 들어맞으면 남은 후보들을 구별할 조건이나 관찰 지점을 골라 다시 실험한다.

## 진단 결과

관찰한 증상과 확인한 원인을 근거로 연결한다. 원인을 확정할 수 없으면 남은 후보와 이들을 가르는 데 필요한 관찰을 밝힌다. 수정까지 맡았으면 진단 결과와 재현 조건을 `$loom:work`에 전달한다.
