# Work

## 이번에 어디까지 맡았는가

사용자가 이루려는 일을 한 장면으로 잡는다. 누가 어떤 조건에서 행동하고 어떤 차이를 확인하려는가? 질문이면 이해에 필요한 설명이, 설계면 사용자가 읽고 고칠 수 있는 제안이, 변경이면 실제 경로에서 확인한 동작이 결과다. 사용자가 지정한 책임 경계나 구현 방식과 기존 호출자에게 지킬 약속도 완료 조건에 넣는다.

사용자가 선택한 것, 아직 열어 둔 것, 에이전트에게 맡긴 것을 구별한다. 요청과 프로젝트에서 판단할 수 있는 일은 진행한다. 선택에 따라 제품 동작이나 사용자가 정한 경계가 달라지면 차이가 드러나는 예를 보여준다. 결정에 의존하지 않는 작업은 이어간다.

## 지금 필요한 일을 고른다

- 현재 역할과 기존 호출자가 의존하는 동작은 `$loom:understand`로 확인한다. 사용자 제보, 운영 기록, 실패한 테스트에서 특정 결과가 나온 이유를 묻는다면 `$loom:diagnose`에서 그 조건과 경로를 조사한다.
- 외부 사례에 따라 선택이 달라지면 `$loom:explorer`로 적용 전제를 확인한다. 새로 정할 제품 동작이나 책임 경계는 `$loom:architect`에서 사용자와 글과 그림을 보며 합의한다.
- 합의한 동작을 테스트와 코드로 옮길 때는 `$loom:implement`를 쓴다. 설계안만 있을 때도 `$loom:review`로 의도와 약속을 대조할 수 있다. 구현이 있으면 공개 동작까지 대조한다. `$loom:write`는 설계나 리뷰에서 내린 판단과 그 근거를 독자가 읽을 수 있게 다듬는다.

## 세션을 넘길 때와 작업을 마칠 때

다른 에이전트가 이전 대화 없이 프로젝트만 열었을 때 남은 작업을 이어갈 수 있는지 본다. 미완료라면 코드에서 읽히지 않는 결정과 이유, 현재 구현과의 차이, 다음에 확인할 장면을 관련 프로젝트 문서에 남긴다. 적당한 곳이 없으면 작업 가까이에 짧게 적는다. 새 세션은 현재 요청을 기준으로 그 기록을 코드와 테스트에 대조해 남은 곳부터 진행한다.

구현을 맡았으면 대표 장면을 실행하고 상태를 바꾼 역할을 따라가, 테스트로 어떤 약속을 다시 확인할 수 있는지 보여준다. 차이의 원인이 밝혀졌으면 맡은 범위에서 구현이나 테스트를 고치고 같은 장면을 다시 확인한다. 기대할 동작을 새로 정해야 하면 설계로 돌아간다. 사용자가 직접 판단하기로 한 프로토타입에는 그 장면을 경험할 시작 방법을 건넨다.

사용자와 설계를 합의한 자료는 그때 확인한 버전의 TypeScript 도메인 모델과 TLA+ 흐름 모델, 검증 설정과 함께 다시 열 수 있게 보존한다. 구현과 테스트에서 복원할 수 있는 인계용 메모와 실험 초안은 정리한다. 이후 선택에 필요한 배경은 해당 결정의 PR이나 기존 문서에서 찾을 수 있게 한다. 결과를 보고할 때에는 확인한 조건·결과와 판단에 영향을 주는 미확인 사항을 밝힌다.
