# Work

## 이번에 무엇을 확인하는가

요청과 앞선 대화에서 사용자가 이루려는 일과 맡긴 범위를 파악한다. 질문에는 근거를 들어 답하고, 설계를 요청하면 판단할 수 있는 설계를, 변경을 요청하면 검증한 동작을 전달한다. 이미 정한 내용은 다음 작업의 출발점으로 삼는다.

기능 변경은 사용자가 먼저 경험하고 싶은 장면을 고른다. 따로 지정한 장면이 없으면 정상 흐름부터 시작한다. 요청과 기존 동작으로 결과가 정해지면 어떤 관찰로 확인할지 잡고 진행한다. 같은 요청에서 서로 다른 결과가 가능하고 지금 하나를 선택해야 한다면, 누가 무엇을 했을 때 무엇이 달라지는지 보여준다. 사용자가 장면을 고치거나 다른 결과를 제시할 수 있게 묻는다. 뒤로 미룰 수 있는 예외는 지금 결정할 일에서 뺀다.

## 다음 작업을 고른다

- 현재 동작과 책임을 알아야 하면 `$loom:understand`, 외부 사례가 판단에 필요하면 `$loom:explorer`를 사용한다.
- 무엇을 보장하고 어느 역할이 맡을지 정해야 하면 `$loom:architect`를 사용한다. 계약이 정해졌고 변경을 맡았으면 `$loom:implement`로 진행한다.
- 결함의 재현이나 원인 조사가 필요하면 `$loom:diagnose`를 사용한다. 원인이 확인된 결함은 재현 조건과 회복할 계약을 구현에 바로 넘긴다. 새 제품 정책이 필요한 부분만 설계로 돌린다.
- 설계나 구현이 합의를 지키는지 검토할 때는 `$loom:review`, 확인한 사실을 독자에게 맞게 작성하거나 다듬을 때는 `$loom:write`를 사용한다.

조사로 풀 수 있는 의문과 구현 방법은 맡은 범위에서 처리한다. 새 근거가 제품의 약속이나 작업 범위를 바꾸면 영향을 받는 장면을 사용자에게 돌려준다. 그 선택과 독립적인 작업은 이어간다.

## 같은 장면으로 마친다

동작 변경은 합의한 시작 조건과 행동을 실제로 거쳤는지 확인하고 기대와 관찰을 함께 보여준다. 결과를 가르는 조건이 빠졌으면 그 조건에서 다시 실행한다. 기대와 다르면 맡은 범위에서 원인을 찾아 바로잡고, 확인할 수 없는 조건은 미확인으로 남긴다. 사용자가 코드를 읽지 않고도 판단할 수 있도록 실행 기록이나 같은 장면을 재현할 방법을 연결한다.

사용자가 직접 경험하고 결정하기로 했으면 실행 가능한 프로토타입과 시작 방법을 건넨다. 에이전트가 확인한 동작과 사용자 판단이 남은 부분을 구분한다. 피드백으로 기대가 바뀌면 설계에서 해당 장면과 계약을 고친다. 기대는 같고 구현이 어긋났으면 실패한 조건에서 원인을 찾아 고친다. 바뀐 결과는 같은 장면으로 다시 보여준다.
