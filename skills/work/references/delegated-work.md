# 위임받은 업무를 수행한다

전달받은 업무 ID로 [업무 CLI](context-work.md)의 `work show`를 읽고 목표, 범위, 완료 조건, assignment, 선행 결과와 작업 경로를 대조한다. 필요한 상위 업무와 선행 업무를 조회하고 `recall`, `search`, `read`, `graph`로 관련 합의와 원본 근거를 확인한다. 받은 명세와 근거에서 이해한 목표, 현재와 변경 후 동작, 보존할 계약과 검증 방법을 짧게 설명하고, 누락이나 모순이 있으면 조율자에게 알린다. 이해완료 상태나 별도 승인 단계를 만들지 않는다.

서브 에이전트는 CLI를 읽기 전용으로 사용한다. 이 규약은 `work`와 보조 스킬의 기록 및 상태 변경 절차보다 우선한다. 업무 변경, `record`, `tidy`와 그 밖의 CLI 저장 명령은 조율자가 수행한다. worker ID는 호스트 보고에서 담당자를 식별하는 데 사용하고, 조율자의 actor를 대신 사용하지 않는다.

전체 계획과 업무 간 조정은 조율자가 맡고, 작업자는 맡은 범위의 세부 계획, 수행과 검증을 맡는다. 같은 워크트리의 다른 변경을 보존한다. 업무 간 충돌, 범위나 완료 조건 변경 또는 추가 위임이 필요하면 근거와 함께 조율자에게 요청한다.

판단과 출처, 조건별 관찰과 근거, 남은 행동은 지정된 호스트 메시지와 결과 반환 경로로 보고한다. 지정된 중간 결과와 막힘, 전제 변경, 기록 정리가 필요한 신호도 조율자에게 알린다. 조율자가 이 보고를 바탕으로 `record`와 `work report`를 저장한다.

수행을 마치면 업무 ID, 읽은 명세의 ref, 변경 경로, 조건별 실제 검증 결과와 근거, 실패나 미확인, 남은 일을 호스트로 반환한다. 조율자가 현재 명세와 결과를 대조하고 `work submit`으로 결과를 고정한 뒤 검토하여 수락하거나 보완을 요청한다. 작업자는 보완 요청과 현재 명세를 읽고 수정 및 검증 결과를 같은 호스트 경로로 다시 반환한다.
