# 대상과 진술을 연결한다

원본 기록에서 같은 대상과 그 대상에 관한 진술을 연결해, 다른 기록에 흩어진 근거를 함께 찾는다. 에이전트가 원문을 해석하고 대상의 동일성·관계의 의미를 판단한다. CLI는 ID·참조·저장 상태의 일관성을 보장한다.

record와 업무 CLI는 각각 원본을 추가한다. 대상·진술·대체 관계와 유효 상태는 tidy apply가 성공할 때 기억·처리 지점과 같은 리비전에 반영한다. managed 업무의 현재 관계·진행·수락은 [업무 CLI](context-work.md)가 즉시 소유하며 그래프를 정리할 때까지 기다리지 않는다. 원본과 이전 진술은 보존한다. work:<id>@<revision>도 그래프 근거로 사용할 수 있다. 정리 전 새 기록은 recall.pending에서 함께 읽는다.

새 CLI는 기존 정리 형식 1을 읽고, 다음 반영부터 그래프·리포트를 포함하는 형식 2로 저장한다. 형식 1만 지원하는 이전 CLI는 이 정리 파일을 읽거나 갱신할 수 없다. 같은 프로젝트에서 정리 데이터를 공유하는 작업자는 새 CLI를 사용한다. 일상 `record` 원본의 형식은 바꾸지 않는다.

## 그래프 변경분을 구성한다

`tidy prepare`의 `current.graph`를 읽고, 필요한 과거 원본을 `search`·`read`로 확인한다. `tidy apply`의 `graph`에는 변경할 `entities`, 추가할 `statements`, 제외할 `retire`만 전달한다. 생략한 항목은 유지된다.

대상(`entities`)의 필드는 다음과 같다.

| 필드      | 의미                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------- |
| `id`      | 프로젝트 안에서 같은 대상을 가리키는 ID. 기존 기록 ID와 같은 1–80자 소문자·숫자·하이픈 규칙을 따른다. |
| `kind`    | `decision`, `condition`, `module` 등 대상의 종류. ID와 같은 표기 규칙을 따른다.                       |
| `name`    | 사람이 읽는 이름.                                                                                     |
| `aliases` | 선택 사항. 같은 대상을 가리키는 다른 이름의 배열.                                                     |
| `sources` | 대상을 식별한 실제 원본 ref. 하나 이상 필요하다.                                                      |

기존 대상의 ID와 종류는 유지한다. 이름·별칭·근거를 갱신할 수 있다. 이름이 비슷한 후보는 원문과 실제 업무·코드 위치를 대조해 같은 대상인지 판단한다.

진술(`statements`)의 필드는 다음과 같다.

| 필드                      | 의미                                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`                      | 진술 ID. 대상 ID와 별도의 이름 공간이며 같은 표기 규칙을 따른다.                                                                                 |
| `subject`                 | 주체의 대상 ID.                                                                                                                                  |
| `predicate`               | `assumes`, `depends-on` 등 관계. ID와 같은 표기 규칙을 따른다. 같은 의미에는 같은 표현을 쓴다.                                                   |
| `object`                  | 다른 대상이면 `{"entity":"대상-id"}`, 값이면 `{"value":2}` 또는 `{"value":false}` 등으로 표현한다.                                               |
| `text`                    | 관계와 필요한 맥락을 보존한 자연어 진술.                                                                                                         |
| `scope`                   | 프로젝트 공통이면 `{"type":"project"}`, 업무에 한정되면 `{"type":"work","id":"업무-id"}`. 기록이 속한 업무와 진술의 적용 범위를 별도로 판단한다. |
| `sources`                 | 주장을 뒷받침하는 실제 원본 ref. 하나 이상 필요하다.                                                                                             |
| `origin`                  | 원문에 명시됐으면 `{"kind":"stated"}`, 추론했으면 `{"kind":"inferred","premises":["전제-진술-id"]}`. 추론에는 하나 이상의 전제가 필요하다.       |
| `status`                  | 입력은 `active` 또는 `unresolved`. 미확인·충돌·잠정 해석은 `unresolved`로 남긴다. 생략하면 `active`다.                                           |
| `conditions`              | 선택 사항. 적용할 코드 버전·실행 조건 등 추가 조건을 문자열 배열로 보존한다.                                                                     |
| `validFrom`, `validUntil` | 선택 사항. 원문에서 확인한 유효 시작·종료 시각. 정리한 시각으로 대신하지 않는다.                                                                 |
| `supersedes`              | 선택 사항. 이 진술로 대체할 **진술 ID** 배열. 기억의 `supersedes`가 가리키는 원본 ref와 구분한다.                                                |
| `contradicts`             | 선택 사항. 충돌 여부를 검토할 진술 ID 배열. 이것만으로 기존 진술의 상태를 바꾸지 않는다.                                                         |

진술 내용은 같은 ID로 덮어쓰지 않는다. 정정·확정에도 새 진술 ID와 실제 근거를 쓰고, 같은 적용 범위의 이전 진술을 대체한다. `stated`는 원문에 그렇게 적혀 있다는 뜻이며 사실성이나 검증 완료를 보장하지 않는다. 예측·선호·제안을 사실로 바꾸지 않는다. 추론을 다시 기록한 원본도 독립적인 관찰로 세지 않는다.

활성 진술의 `supersedes`에 연결된 이전 진술은 `superseded`가 되고 `supersededBy`에 새 진술 ID가 남는다. 새 진술은 이전 진술과 같은 `scope`여야 한다. 최신 기록이라는 이유만으로 대체하지 않으며, 원문에서 대체 의사와 적용 조건을 확인한다. 적용 범위가 다르면 기존 진술을 유지하고 별도 진술로 남긴다.

더는 적용하지 않을 진술은 `graph.retire`에 `{"id":"진술-id","reason":"제외 이유","sources":["원본-ref"]}`를 전달한다. `retired` 상태와 이유가 남는다. 대체·제외되거나 미확정인 진술을 전제로 삼은 활성 추론은 `unresolved`가 되고 `reviewNeeded`에 재검토할 전제 ID가 표시된다. 이는 추론의 결론이 거짓이라는 판정이 아니다. 새 근거로 확인한 결과는 새 진술로 남긴다.

예를 들어 실제로 읽은 원본을 근거로 다음 변경분을 구성할 수 있다.

```json
{
  "entities": [
    {
      "id": "storage-choice",
      "kind": "decision",
      "name": "저장 방식 선택",
      "sources": ["note:storage@1"]
    },
    {
      "id": "one-writer",
      "kind": "condition",
      "name": "작성자가 하나다",
      "sources": ["note:storage@1"]
    }
  ],
  "statements": [
    {
      "id": "storage-assumption",
      "subject": "storage-choice",
      "predicate": "assumes",
      "object": { "entity": "one-writer" },
      "text": "저장 방식 선택은 작성자가 하나라는 전제를 따른다.",
      "scope": { "type": "work", "id": "storage" },
      "sources": ["note:storage@1"],
      "origin": { "kind": "stated" }
    }
  ]
}
```

위 객체를 `snapshot`과 함께 `tidy apply`의 `graph`에 넣는다. 대상과 전제 진술은 같은 변경분에서 추가할 수 있다. 존재하지 않는 대상·진술, 전제나 대체 관계의 순환, 준비 이후의 원본 인용은 반영되지 않는다. 실패하면 그래프와 처리 지점을 바꾸지 않는다.

## 관계를 따라 근거를 조회한다

```sh
node "<plugin-root>/scripts/context/cli.ts" graph --cwd "<checkout>" --work storage --entity one-writer --depth 2
node "<plugin-root>/scripts/context/cli.ts" graph --cwd "<checkout>" --work storage --query "작성자 전제" --limit 20
```

`graph`는 프로젝트 공통과 지정한 업무의 현재 진술을 조회한다. `--history`를 붙이면 대체·제외된 진술도 포함한다. `--entity`는 지정한 대상에서, `--query`는 BM25로 찾은 진술과 그 대상에서 탐색을 시작한다. 기본 깊이는 2, 최대 5다. `--limit`은 반환할 주 진술의 수이며 기본 50, 최대 200이다. `remaining`은 같은 탐색 범위에서 응답에 담지 못한 주 진술 수다.

결과의 `paths`에는 대상·진술 ID의 연결 경로가, `sources`에는 원본 ref·시각·발췌가 담긴다. `premises`는 선택한 추론의 근거 중 주 진술 목록에 없는 전제다. 근거를 보존하기 위해 주 진술의 limit과 별도로 반환하며, 다른 업무 범위나 이전 상태의 진술도 포함될 수 있다. 근거의 범위를 결론의 적용 범위로 확대하지 않는다. 필요한 전체 원문은 `read --ref`로 읽는다.

탐색은 관계의 양쪽 방향을 따라 관련 근거를 찾는다. 실제 관계의 방향은 각 진술의 `subject`·`object`를 확인한다. 경로가 연결됐다는 사실만으로 인과관계나 관계의 추이성을 가정하지 않는다. 적용 범위·조건·유효 시각과 미확정 상태를 읽고 결론을 판단한다. 이 CLI는 일반 논리 증명기를 제공하지 않는다.

`recall`도 `graph` 결과와 `pending`을 함께 반환한다. `--entity`, `--query`, `--depth`, `--limit`으로 그래프 범위를 좁힐 수 있다. `--query`는 기존 기억의 단어 필터에도 적용된다. 조회만으로 그래프를 만들거나 갱신하지 않는다.

원본을 `forget`하면 그 원본에 의존한 대상·진술과 이를 전제로 삼은 추론을 모든 정리 이력에서 제거한다. 여러 원본을 공동 근거로 가진 대상도 그중 하나가 삭제되면 제거하므로 연결된 진술이 함께 제외될 수 있다. 대체·충돌 연결만 삭제된 진술을 가리키는 경우에는 연결을 제거하고 현재 근거가 남은 진술은 유지한다. 삭제된 대체 진술 때문에 이전 진술을 자동으로 다시 활성화하지 않는다. 결과 리포트에 담긴 삭제 대상의 내용도 함께 제거한다.
