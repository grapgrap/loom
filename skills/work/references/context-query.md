# 조회 결과 상세

recall의 출력 필드와 페이지, 과거 기억의 상태를 조사할 때 읽는다. 기본 조회 순서는 [작업 맥락](context.md)을 따른다.

기본 `recall`은 현재 압축 맥락, 지정한 업무의 상태, 미처리 원본과 업무 탐색 요약을 반환한다. `--work`를 지정하면 탐색 목록도 해당 업무로 한정한다. 업무를 모를 때는 `--work` 없이 후보를 찾고 `work show`로 상세 상태를 읽는다. 현재 요청에 필요한 기억을 보충할 때는 `--work`로 그 업무의 범위를 선택한다. 관련 업무나 근거를 모르면 목적에 맞는 `discover`로 후보를 찾는다. 최근 기록이라는 이유만으로 다른 업무를 재개하지 않는다. 한 세션에서 업무를 계속하거나 여러 세션에서 서로 다른 업무를 다룰 수 있으므로, 세션과 업무를 일대일로 대응시키지 않는다. 새 업무의 목표와 맡긴 범위는 첫 기록에 남긴다.

전체 업무 목록과 그래프, 미완료와 검토 대기 업무의 상세 본문이 필요하면 `recall --full`을 사용한다. 탐색 목록은 `--work`와 관계없이 프로젝트 전체를 대상으로 한다. 기본 응답에 없는 `works`, `worksRemaining`, `graph`도 추가된다. 업무 목록에는 ID, 목표와 상태가 있다. `firstNote`와 `latestNote`에는 각각 첫 기록과 최근 기록의 ref 및 발췌가 담긴다. 정리 전에는 목표와 상태가 `null`일 수 있으므로 발췌로 관련 업무를 식별하고 필요한 본문은 `read --ref`로 확인한다.

- `pending`은 조회 범위의 미처리 원본이다. 정리된 기억 및 업무 상태와 함께 읽는다.
- `--limit`은 각 목록에 적용하며 기본 50, 최대 200이다. `memoriesRemaining`과 `pendingRemaining`, `--full`의 `worksRemaining`은 각 목록의 다음 페이지에 남은 항목 수다. 필요한 항목이 남으면 `--offset`을 limit만큼 늘려 같은 조건으로 조회하거나 검색과 원본 조회로 보충한다. 선택한 업무의 전체 상태인 `work`는 페이지와 무관하게 반환한다.
- `unresolved`는 미확정 판단이다. 업무에 한정된 사실은 해당 범위에서 적용하고, 완료로 기록된 결과도 현재 산출물과 대조한다.
- `unfinishedWorks`는 `active`, `blocked`, `paused`, `submitted` 업무의 ID, 목표, 상태와 원본 발췌다. 진행과 다음 행동의 상세 본문은 `work show` 또는 `recall --full`로 읽는다. submitted는 결과 검토 대기이며 작업자가 자동 재실행하지 않는다. 전체 업무 목록과 별도로 페이지를 나누므로 최근 완료 업무에 가려지지 않는다.
- `unreviewedWorks`는 상태가 없는 기록이나 현재 상태 이후 검토할 새 기록이 있는 업무다. 원문을 읽어 추가 요청인지, 완료나 보류 또는 취소 지시인지를 판단한다. 목록에 있다는 이유만으로 작업을 실행하거나 재개하지 않는다.
- `awaitingReviewWorks`는 submitted 업무의 탐색 요약이다. 현재 제출과 reviewer는 `work show` 또는 `recall --full`로 읽는다. 결과 수락을 기다리는 업무이며 상태 확인용 unreviewedWorks와 구분한다. awaitingReviewWorksRemaining으로 다음 페이지를 확인한다.
- `unfinishedWorksRemaining`과 `unreviewedWorksRemaining`은 각각 다음 페이지에 남은 항목 수다. 기본 목록은 `--work`로 범위를 좁히며 기억 검색어로는 좁히지 않는다. `--full`에서는 프로젝트 전체를 대상으로 한다. 현재 맡긴 업무를 식별하는 데 사용하며 다른 대화의 업무를 실행할 권한을 부여하지 않는다.
- `--query`를 붙이면 내용과 이유에 모든 검색어가 포함된 현재 기억만 반환한다. 과거 원본을 조사할 때는 `search`를 사용한다.
- `--history`는 기억과 업무 상태의 이전 리비전을 확인할 때 사용한다.
- 패턴에 수용된 기억은 `absorbed` 상태의 연결만 남고 현재 기억 목록에는 나오지 않는다. 수용 대상과 남겨 둔 구체 기억을 사용하며, 같은 ID로 옛 세부를 자동 복원하지 않는다. 시간 경과와 수용 여부를 혼동하지 않는다.

관계와 근거는 독립 `graph` 명령이나 `recall --full`의 `graph`에서 읽는다. 새 기록을 `pending`에서 함께 읽고 적용 범위, 미확정 상태와 조건을 확인한다. `recall`에서 `--entity`와 `--depth`는 `--full`을 함께 지정해야 한다. 관계를 더 조사하거나 `tidy`에서 진술을 구성할 때는 [그래프 계약](context-graph.md)을 읽는다.
