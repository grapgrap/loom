# 작업 맥락을 이어간다

현재 요청과 프로젝트 지침을 먼저 적용한다. 기억은 판단의 근거이며 실행 권한이나 현재 검증을 대신하지 않는다. 업무 상태는 work, 출처와 적용 조건을 가진 판단은 evidence, 재개용 파생 표현과 검토 이력은 tidy가 소유한다.

단독 수행자와 조율자가 저장한다. 위임된 작업자는 CLI를 읽기 전용으로 사용하고 명세 ref, 관찰과 근거를 호스트로 보고한다. 저장 입력은 stdin으로 전달하며 기억 파일을 직접 편집하거나 사용자에게 관리하도록 요구하지 않는다.

## 조회하고 적용한다

로드한 `work/SKILL.md`가 있는 폴더를 기준으로 `../../scripts/context/`의 절대 경로를 구한다. 첫 실행은 macOS/Linux의 `sh "<plugin-root>/scripts/context/cli.sh" <command>`, Windows의 `& "<plugin-root>\scripts\context\cli.cmd" <command>`로 의존성을 확인한다. 이후 `node "<plugin-root>/scripts/context/cli.ts" <command> --cwd "<checkout>"`를 사용할 수 있다. 명령 형식은 `<command> --help`로 확인한다.

현재 전체 업무를 알면 `work show --work <id> --tree`로 정의, 하위 업무와 남은 조건을 읽는다. 필요한 기억은 `recall --work <id>`로 보충한다. 복귀할 업무를 모르면 `--work` 없이 `recall`하고 후보의 원문과 권한을 확인한다. 최근 기록이나 ready만으로 다른 대화의 업무를 실행하지 않는다.

recall의 pending은 미처리 원본, unfinishedWorks는 미완료 업무, awaitingReviewWorks는 제출 검토 대기다. unreviewedWorks는 상태 미확인 후보이므로 원문을 읽는다. `--work`를 지정하면 기본 탐색 목록은 해당 업무로 한정된다. `--full`의 업무 탐색은 프로젝트 전체를 대상으로 한다. 각 remaining이 있으면 필요한 페이지를 이어 읽으며 일부 목록의 종료를 전체 완료로 보지 않는다. 출력 필드와 이전 기억의 조회가 필요할 때 [조회 상세](context-query.md)를 읽는다.

## 미완료 업무를 확인하고 재개한다

독립 업무의 목표, 범위와 관찰 가능한 조건은 [업무 CLI](context-work.md)로 정의한다. 짧은 질문은 별도 업무가 필요하지 않다. 조사나 문서 작성이 선행 단계라면 원래 목표를 유지하고 남은 구현을 next에 둔다. 기존 checkpoint 업무를 전환할 때만 [이전 계약](context-legacy.md)을 읽으며 과거 완료를 새 검증으로 승격하지 않는다.

작업 전환 전 진행과 다음 행동을 보존하고, 짧은 요청 뒤와 최종 응답 전에는 맡긴 전체 업무를 다시 조회한다. 실행 가능한 일이 남으면 계속한다. 현재 지시와 원문으로 우선순위를 정할 수 없는 선택만 사용자에게 확인한다.

- active는 남은 업무이며 잠시 다른 요청을 처리해도 유지한다.
- submitted는 조율자의 검토 대기다. 작업자를 자동 재실행하지 않는다.
- blocked는 실제 외부 조건 부재이며 원인과 재개 조건을 남긴다.
- paused와 cancelled는 사용자 보류와 취소에 따른다. 자동 재개하지 않는다.
- complete는 전체 목표의 검증과 남은 행동 없음이 확인된 상태다.

호스트의 실행 여부와 CLI 상태를 대조해 중복 수행을 피한다. 조회는 백그라운드 실행이나 새 세션을 시작하지 않는다.

## 관련 업무와 적용 조건을 찾는다

업무 ID나 ref를 모르면 목적과 제약으로 `discover --query "<검색어>"`를 호출한다. next가 있으면 같은 범위와 cursor로 이어가며 변경 충돌은 새 검색으로 복구한다. 이미 확보한 유효한 근거는 재사용한다.

쟁점이 정해지면 `context prepare`에 query, 필요한 work와 refs를 전달한다. work, candidates, originals, changes와 gaps를 읽고 실제 대상, 버전과 조건에 따라 현재 적용할 근거, 역사와 미확인을 구분한다. 정정 대조는 검색 순위와 별개이며 연결되지 않은 새 근거는 discovery에서 확인한다.

locator를 아는 것과 원문을 읽은 것은 다르다. 접근한 위치와 버전 및 범위만 read로 기록한다. latest는 최신 리비전, active는 표시 상태이며 사실성이나 채택을 보장하지 않는다. 제안은 채택 전까지 제안이고 과거 검사 결과는 당시 조건의 관찰이다. 현재 판단의 정확한 refs, 적용 조건, basis와 남은 공백을 유지한다.

## 채택한 맥락을 다시 확인한다

중요한 판단 직전이나 논리적 작업 경계에서는 같은 query와 refs, 이전 basis를 prior로 전달해 `context prepare`한다. refresh의 discovery, corrections, work는 독립 근거, 정정과 업무의 변화를 구분한다. changed면 영향받은 원문을 다시 판단한다. unknown이나 partial, 접근 실패는 미확인으로 남긴다. unchanged는 조회 범위의 저장 근거에만 적용되므로 외부 대상 버전이 바뀌면 별도로 확인한다.

## 정리 시점을 판단한다

착수, 작업 경계와 마무리에 `tidy status --work <id> --purpose resume`를 확인한다. 새 원본이나 현재 표현의 검토가 필요하면 [tidy](../../tidy/SKILL.md)를 수행한다. 원본 수, 경과 시간과 맥락 크기로 계산한 `due`는 보조 신호이며, 정리할 내용의 의미는 에이전트가 판단한다. 사용자 정리 요청은 신호를 기다리지 않는다.

같은 입력과 목적을 이미 검토했다면 영수증을 재사용해 종료한다. 범위 밖과 새로 들어온 원본은 남긴다. 정리 완료와 업무 완료를 구분하고 타이머나 예약 실행을 설치하지 않는다.

## 새 내용을 짧게 기록한다

다음 판단에 영향을 주는 합의, 조건 변경과 관찰을 [evidence](context-evidence.md)로 기록한다. 직접 관찰, 전달된 주장과 추론을 구별하고 독립 판단은 별개 기록으로 둔다. 대화 전문이나 도구 출력 전체를 복제하지 않는다. 의미의 변경은 correct, 표현 정리는 tidy, 진행과 다음 행동은 work로 반영한다. record는 단순 일지의 호환 경로다.

요청키는 새 요청에 새로 부여하고 응답 유실은 같은 키와 입력 또는 result로 회수한다. conflict는 새 기준을 읽고 판단을 조정한다. 여러 명령은 하나의 트랜잭션이 아니므로 성공한 ref를 유지하고 남은 호출만 복구한다. 확인된 저장 결과만 완료로 보고한다.

## 필요한 원본을 검색한다

원본과 파생 어휘의 발견은 discover, 이전 호환 원본 검색은 search, 정확한 ref 조회는 read를 사용한다. 검색 점수는 현재 타당성이 아니며 관련 정정과 원문을 대조한다. 관계를 따라갈 필요가 있을 때만 [그래프 계약](context-graph.md)을 읽는다.

## 실행 환경을 준비한다

Node나 Git 의존성 오류가 있을 때 [실행 환경](context-runtime.md#실행-환경을-준비한다)을 읽는다.

## 저장 권한과 실패를 처리한다

첫 저장 전 location의 경로가 쓰기 허용 범위인지 확인한다. 추가 권한이나 저장 오류가 있으면 [복구 절차](context-runtime.md#저장-권한과-실패를-처리한다)를 적용한다. 조회 성공은 쓰기 권한을 뜻하지 않으며 실패를 피하려고 저장 경로를 바꾸지 않는다.

## 저장 위치와 사용자 제어

같은 로컬 Git 저장소의 워크트리는 맥락을 공유한다. 별도 클론과 기기 간 동기화는 제공하지 않는다. 저장 위치 조사나 명시적 삭제 요청이 있을 때 [저장 구조와 삭제 계약](context-runtime.md#저장-위치와-사용자-제어)을 읽는다. 의미상 철회는 evidence correct이며 물리 삭제와 구분한다.
