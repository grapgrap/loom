# Implement

## 주석과 설계

구현 코드와 테스트 코드에 새 주석을 쓰지 않는다. 임시방편이나 복잡한 분기를 주석으로 정당화하고 싶다면 어떤 설계 결정이 그 설명을 요구하는지 먼저 살핀다. 이름이 모호하면 이름을 고치고, 잘못된 상태나 호출 순서를 허용하면 기존 계약을 지키면서 역할 내부의 타입이나 구조를 고친다. 테스트는 이름에 조건과 기대 동작을 드러내고, 그 동작을 어기면 실패하는 검증문으로 의도를 표현한다.

수정한 범위의 주석을 점검한다. 동작을 되풀이한 설명, 섹션 배너, 주석 처리한 옛 코드, TODO와 임시방편을 변호하는 주석은 지운다. 다음에 해당하는 기존 주석만 남긴다.

- 라이선스 헤더
- 바꿀 수 없는 외부 의존성·플랫폼·프로토콜 때문에 필요한 비직관적 동작의 짧은 이유
- 공개 API 계약을 정의하는 문서 주석
- 코드로 표현할 수 없는 제약을 설명하는 이슈 링크
- 포매터 지시문과 근거가 있는 린트 억제 지시문

## 구현 단위

새 동작은 `$loom:architect`에서 합의한 모델을 바탕으로, 사용자가 처음부터 끝까지 경험할 수 있는 가장 작은 흐름부터 구현한다. 그 흐름의 의미가 성립하려면 처음부터 지켜야 할 규칙을 함께 구현한다. 결함 수정은 재현 조건과 확인한 원인에서 시작해 어떤 계약을 회복하고 어떤 동작을 보존할지 짚는다. 각 단계에서 호출자가 어떤 조건에서 무엇을 하고 어떤 결과를 관찰할지 한 문장으로 적는다.

새 예외에서 구현이 기존 약속을 어기면 그 사례를 재현해 구현과 테스트를 보강한다. 여러 처리 방식이 합의를 충족하면 기존 동작과 일관된 방식을 택해 계속 진행하고, 테스트는 제품이 보장하는 결과를 확인한다. 예외를 다루려면 제품의 약속 자체를 바꿔야 할 때 그 장면을 `$loom:architect`에서 다시 다룬다.

## 테스트 범위

확인하려는 동작에 맞춰 테스트 범위를 고른다.

- 한 역할의 비즈니스 규칙은 유닛 테스트로 확인한다. 예를 들어 남은 잔액까지 취소할 수 있다면, 정확히 잔액만큼 요청했을 때와 잔액을 초과했을 때의 판단을 각각 확인한다.
- 역할 사이의 협력은 통합 테스트로 확인한다. 한 역할이 보낸 입력을 다른 역할이 실제로 받아 약속한 결과를 돌려주는지 살핀다.
- 사용자 진입점에서 최종 결과까지 이어지는 동작을 보장하려면 E2E 테스트로 확인한다.

같은 보장을 검증하는 기존 테스트는 재사용한다. 선택한 단계의 사례만 테스트로 옮기고, 나머지는 시나리오 목록에 둔다.

## 1. Red

한 가지 조건과 기대 결과를 하나의 테스트로 표현한다. 호출자가 관찰할 결과를 판별할 검증문에서 거슬러 올라가 호출 방법과 준비 조건을 정한다.

변경 전에 테스트를 실행해 기대한 동작을 충족하지 못해 실패하는지 확인한다. 준비 과정에서 실패하면 원인을 바로잡고 다시 실행한다. 처음부터 통과하면 검증문이 실제 요청의 조건과 결과를 확인하는지 대조한다. 이미 동작을 보장한다면 통과 근거를 기록하고 다음 단계로 넘어간다.

## 2. Green

선택한 테스트가 요구하는 동작을 구현한다. 결함은 재현한 경로에서 원인을 고친다. 해당 테스트와 기존 테스트를 실행해 새 동작과 보존할 동작을 함께 확인한다.

기대값은 합의한 컨셉의 규칙과 플로우의 약속에서 도출한다. 불변식은 그것을 깨뜨릴 수 있는 입력이나 사건 순서에서도 성립하는지 확인한다. 실제 출력을 기대값에 복사하거나 검증문을 약화하면 테스트가 같은 오류를 받아들인다. 구현 중 다른 흐름을 발견하면 목록에 추가하고, 구조 정리는 테스트를 통과한 뒤에 판단한다.

## 3. Refactor

테스트를 통과한 상태에서 의도를 읽기 어렵게 하거나 같은 규칙을 여러 곳에서 고치게 하는 구조를 찾는다. 개선할 부분이 있으면 동작을 유지하며 정리하고 같은 테스트를 다시 실행한다.

모양이 비슷한 코드도 서로 다른 이유로 바뀔 수 있다. 추상화를 추가하기 전에 함께 바뀌어야 할 규칙을 설명할 수 있는지 확인한다.

## 완료 판단

단계의 결과를 확인한 뒤 다음 단계로 넘어간다. 사용자 흐름의 시작부터 기대 결과까지 확인하면 해당 시나리오의 구현을 완료로 표시한다. `$loom:work`에는 합의한 장면에서 어떤 행동을 했고 무엇을 관찰했는지 보여주는 실행 기록이나 그 동작을 다시 확인할 방법을 전달한다. 사용자의 기대를 확인할 프로토타입은 대표 흐름을 직접 실행해 보고, 사용자가 같은 장면을 경험할 수 있도록 시작 방법과 확인할 결과도 함께 전달한다.
