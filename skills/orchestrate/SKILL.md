# Orchestrate

조율자는 전체 작업의 계획과 하위 작업의 배정, 진행 확인과 결과 수락을 맡는다. 작업자는 [work](../work/SKILL.md)로 맡은 범위를 수행하고 결과와 근거를 조율자에게 반환한다. 설명과 문서에는 [write](../write/SKILL.md)를 적용한다.

## 전체 목표와 하위 작업을 정한다

현재 대화, 프로젝트 지침과 실제 산출물에서 목표, 권한과 진행 상태를 확인한다. 사용자와 프로젝트가 정한 위임 범위와 모델을 따르고, 모델이 미정일 때만 먼저 확인한다. 모든 작업자에게 같은 워크트리의 절대 경로를 전달하고 그 경로에서 실행한다. 같은 워크트리에서 실행할 수 없다면 제약을 알리고 다른 체크아웃으로 임의 이동하지 않는다.

작업자를 실행하기 전에 다음을 정한다.

1. 사용자가 얻을 결과와 유지할 계약을 전체 완료 조건으로 정하고, 실제 사용 경로와 기대값에 연결한다.
2. 각 하위 작업이 충족할 완료 조건과 산출물, 수정 범위와 선행 결과를 정한다. 컴포넌트나 작업자 수에 맞춰 작업을 나누지 않는다.
3. 작업자가 확인할 입력, 환경과 기대 결과, 제출할 근거를 정한다. 첫 구현 전에 [verify](../verify/SKILL.md)로 검증 수단을 준비하도록 배치한다.
4. 선행 결과를 확인할 시점, 공통 검증 수단과 통합 담당자를 정한다. 하위 결과를 합친 동작의 검증도 담당자를 배정한다.

책임 경계를 바꾸는 구현에는 [architect](../architect/SKILL.md)에서 정한 책임과 입출력 계약을 전달한다. 설계 자체를 위임할 때는 합의한 경계와 아직 정하지 않은 계약을 구분한다.

대화에서 정한 명세와 담당자, 의존 관계에 따라 호스트의 에이전트 도구로 작업을 배정한다. 작은 작업에 별도 계획 문서를 만들지 않는다.

## 수정 범위를 나누고 명세를 전달한다

독립적인 조사는 병렬로 진행할 수 있다. 수정 작업은 같은 파일을 동시에 쓰지 않도록 나누며 선행 계약이 필요한 작업은 순서대로 진행한다. 공통 계약이나 범위가 충돌하면 영향을 받는 수정을 멈추고 조정한다. 조율자가 실행 중인 작업자의 영역을 직접 수정하지 않는다. 전체 포맷, 의존성 갱신, 브랜치와 커밋 작업은 수행자와 시점을 정하고 승인된 범위에서 맡긴다.

새 작업자에게 다음 내용을 직접 전달한다. 작업자가 조율자의 대화와 기록을 자동으로 공유한다고 가정하지 않는다.

- `work` 스킬과 같은 워크트리의 절대 경로
- 전체 목표와 맡긴 결과, 충족할 완료 조건과 수정 범위
- 다른 작업자의 영역과 선행 결과
- 합의한 계약과 제약, 원본 근거의 위치, 미결정 사항과 조건별 검증 방법
- 중간 보고 시점, 즉시 알려야 할 막힘과 전제 변경, 조율자 보고 절차
- 반환할 산출물, 변경한 경로, 조건별 관찰과 근거, 남은 일

작업자에게 [위임 수행 지침](../work/references/delegated-work.md)을 전달한다.

## 작업자의 이해를 계약과 대조한다

작업자가 명세와 원본 근거를 읽고 이해한 내용을 자기 말로 보고하게 한다. 설명한 목표, 수정 범위, 선행 결과, 현재와 변경 후 동작, 보존할 계약과 검증 방법을 명세와 대조한다. 수신 확인이나 명세의 반복만으로 이해가 일치한다고 판단하지 않는다.

누락이나 불일치가 있으면 원본 근거를 확인해 명세를 보완하고, 작업자가 수정된 내용을 어떻게 이해했는지 다시 대조한다. 맡은 작업에 필요한 계약과 이해가 일치하면 착수를 알린다. 그전에는 자료 확인과 질문만 진행하도록 한다.

이 대조와 착수 확인은 조율자가 맡고, 사람의 선택이 필요한 미결정 사항만 사용자에게 묻는다. 착수 확인이 결과 수락을 뜻하지는 않는다. 완료 여부는 실제 산출물과 검증 근거로 판단한다.

## 진행을 확인하고 결과를 검토한다

배정한 작업을 호스트 도구가 보여주는 실행 상태와 대조하고, 실행 중인 작업을 중복 배정하지 않는다. 실행이 끝났더라도 결과 제출과 검토 수락까지 마쳤다고 보지 않는다. 호스트의 대기와 알림 도구를 사용하고 상태 확인만을 위해 작업자를 다시 실행하지 않는다.

작업자의 보고를 현재 명세와 대조하고 보고자, 산출물과 검증 근거를 확인한다. 완료 선언만으로 실제 검증을 마쳤다고 보지 않는다. 범위, 완료 조건, 담당자나 의존 관계가 바뀌면 명세를 갱신해 관련 작업자에게 알리고, 영향을 받는 검증과 제출된 결과 및 후속 작업을 다시 확인한다. 목표나 권한의 변경은 사용자 지시를 따른다.

결과를 받으면 [review](../review/SKILL.md)로 실제 산출물을 검토하고 [verify](../verify/SKILL.md)로 완료 조건을 확인한다. 조건을 충족하면 수락하고, 보완이 필요하면 해당 조건과 근거를 명시해 수정을 요청한다. 명세 변경을 반영하지 않은 결과를 수락하거나 완료 기준을 낮추지 않는다. 범위 밖의 제안만으로 수락을 막지 않으며, 새 변경으로 무효화되지 않은 검증은 재사용한다.

## 전체 결과를 확인하고 마무리한다

작업 전환과 짧은 요청 뒤에는 전체 목표와 남은 통합 작업을 확인한다. 보류와 취소는 사용자 지시를 따른다. 막힌 부분은 원인과 재개 조건을 남기고 독립적으로 가능한 작업은 계속한다.

모든 하위 작업의 진행과 수락 여부를 확인하고 담당자가 없는 일이 남았는지 살핀다. 합쳐진 결과를 실제 사용 경로에서 검증하고 전체 완료 조건을 충족했을 때 완료를 보고한다. 최종 보고에는 전체 결과와 검증 근거, 수락한 하위 결과, 남은 실패와 미확인 사항을 연결한다.
