# Orchestrate

메인 에이전트(이하 조율자)는 전체 계획, 업무 분해·배정, 진행 확인과 최종 완료 판단을 맡는다. 서브 에이전트(이하 작업자)는 [work](../work/SKILL.md)로 할당된 범위의 세부 계획·수행·검증을 맡고, 조율자가 완료 조건을 확인할 수 있도록 근거를 보고한다. 전체 계획의 갱신과 하위 결과의 수락은 조율자가 책임진다.

`work`는 단일 에이전트의 독립적인 수행 지침으로 유지한다. [원칙](../../references/principles.md)의 적용 절차로 책임·의존 관계와 공유 상태의 변경 범위를 정한다. 설명과 보고에는 [write](../write/SKILL.md)를 적용한다.

## 전체 범위와 실행 조건을 정한다

- 사용자가 얻을 결과, 유지할 동작, 전체 완료 조건과 맡긴 전달 지점을 정한다. 위임은 그 범위와 실행 권한을 넘지 않는다.
- [작업 맥락](../work/references/context.md)의 절차로 관련 기억·업무 상태·미처리 원본을 읽는다. 과거 기록과 현재 산출물을 대조하고, 진행 중인 하위 업무가 있으면 먼저 확인한다.
- 사용자와 프로젝트의 위임·모델 정책을 따른다. 실행할 모델이 정해져 있지 않으면 첫 실행 전에 사용자에게 선택을 받는다. 이미 정한 선택은 재사용한다.
- 현재 워크트리의 절대 경로와 기존 변경을 확인한다. 호스트의 서브 에이전트 도구로 모든 작업자를 그 워크트리에서 실행한다. 같은 경로에서 실행할 수 없으면 그 조건을 알리고, 다른 워크트리나 클론으로 조용히 바꾸지 않는다.

## 전체 계획을 세우고 확인 가능한 업무로 분해한다

조율자는 작업자를 실행하기 전에 전체 목표에서 필요한 결과를 도출하고, 그 결과를 누가 어떤 순서로 만들고 확인할지 계획한다. 계획에는 하위 업무뿐 아니라 결과를 연결하는 통합과 전체 검증도 포함한다.

1. 전체 완료 조건을 사용자가 관찰할 결과와 보존할 계약으로 정한다. 각 조건에 확인할 산출물이나 사용 경로, 검증 조건과 기대 결과를 연결한다.
2. 전체 완료 조건을 충족하는 데 필요한 하위 업무를 나눈다. 각 업무가 어떤 전체 조건에 기여하는지, 맡길 결과와 수정 범위, 선행 결과와 담당자를 정한다. 파일을 나누는 것만으로 업무 분해를 대신하지 않는다.
3. 하위 업무에도 확인 가능한 완료 조건을 둔다. 필요한 입력·환경에서 무엇이 관찰되어야 하는지와 작업자가 제출할 증거를 명시한다. 예를 들어 만료된 세션의 접근 처리에서는 보호된 화면 진입 시 로그인 화면으로 이동하는지 확인한다. 검사 명령을 지정할 때는 통과 결과가 어떤 조건을 입증하는지도 밝힌다.
4. 선행 결과를 확인할 시점과 후속 업무의 착수 조건을 정한다. 하위 조건을 모두 만족해도 빠질 수 있는 연결 동작과 전체 사용 경로는 별도 통합·검증 업무로 둔다.

계획의 크기는 업무에 맞춘다. 작은 변경은 조율 기록의 짧은 목록으로 충분하다. 작업자는 맡은 범위의 수행 방법을 정하고 계획 변경을 제안할 수 있다. 업무 간 의존 관계, 범위·완료 조건과 전체 순서의 변경은 조율자가 판단해 계획과 명세에 반영한다. 사용자 목표나 권한을 바꾸는 선택은 사용자에게 확인한다.

## 업무와 조율 기록을 연결한다

조율자의 전체 업무와 각 하위 업무를 [공통 업무 CLI](../work/references/context-work.md)의 work create로 정의한다. 각 하위 업무에는 parent, 기여하는 상위 조건 ID인 contributesTo와 필요한 dependsOn을 연결한다. 목표·범위·완료 조건·순서는 업무 데이터에, 그 판단 이유와 출처는 record에 남긴다. 작은 업무에도 별도의 칸반이나 계획 파일을 만들 필요는 없다.

할당 전에 work assign으로 worker와 reviewer를 지정하고 reviewer에는 조율자 ID를 사용한다. 호스트에서 실행 ID를 받은 뒤 같은 담당자로 assign을 호출해 executionId를 연결한다. 이 연결은 이미 도착한 보고·제출을 지우지 않는다. 수정 파일·다음 점검 시점과 명세의 판단 근거는 조율 기록에 남긴다. 담당이나 명세를 바꾸면 무효화된 검증·제출과 영향받는 업무를 확인한다.

전체 진행은 work show --work <전체-id> --tree로 조회한다. 각 업무의 현재 조건 보고와 ready·blocked·awaitingReview·missingCriteria를 읽고 다음 행동을 정한다. 맥락은 recall --work <id>, 정확한 원본은 read --ref로 보충한다. pending은 정리하지 않은 원본이며 작업 대기열이나 완료 알림이 아니다. ready도 호스트에서 실행 중인 작업을 다시 실행할 권한을 뜻하지 않는다.

공유 기록의 `tidy`는 조율자가 맡는다. 작업자는 자신의 업무에 `record`를 추가하고 정리가 필요한 신호를 보고한다. 기록을 정리한 시점, 작업자가 수행을 마친 시점, 조율자가 전체 완료를 확정한 시점을 구분한다.

## 같은 워크트리의 수정을 조율한다

- 독립적으로 읽고 조사할 수 있는 업무는 병렬로 배정한다. 수정하는 업무는 동시에 같은 파일을 쓰지 않도록 담당을 나눈다.
- 같은 파일을 수정해야 하거나 선행 결과가 필요한 업무는 순서를 정한다. 선행 업무의 결과와 근거를 다음 명세에 전달한 뒤 실행한다.
- 저장소 전체 포맷, 의존성 갱신, 브랜치 변경, 커밋처럼 여러 작업에 영향을 주는 동작은 조율자가 수행자와 시점을 정한다. 이 배정이 사용자가 맡긴 실행 권한을 넓히지는 않는다.
- 작업 중 범위 충돌이나 공통 계약 변경이 드러나면 영향받는 수정을 멈추고 담당·순서를 다시 정한다. 조율자가 실행 중인 작업자의 수정 영역을 직접 고치지 않는다.

## 독립적으로 수행할 명세를 전달한다

실행하거나 다시 지시할 때 다음 내용을 작업자가 볼 수 있는 메시지에 포함한다. 조율자 자신의 기록에만 남겨두지 않는다.

| 항목        | 전달할 내용                                                                            |
| ----------- | -------------------------------------------------------------------------------------- |
| 수행 지침   | `work` 스킬 사용과 그 `SKILL.md`의 실제 절대 경로                                      |
| 업무        | 전체 목표·완료 조건과 이번 업무의 관계, 이번 업무의 목표·범위·완료 조건                |
| 위치와 기록 | 같은 워크트리의 절대 경로, 전체·하위 업무 ID, actor로 쓸 worker ID, CLI와 데이터 루트  |
| 수정 경계   | 맡긴 파일, 다른 작업자의 수정 범위, 선행 결과와 아직 결정하지 않은 조건                |
| 맥락과 검증 | 필요한 합의·제약·선행 결과와 원본 ref, 조건별 검증 방법·입력·환경·기대 결과와 증거     |
| 진행 보고   | 중간 결과를 확인할 시점, 즉시 알릴 막힘·전제 변경, 조건별 확인 결과·남은 일·다음 행동  |
| 조율 규약   | report·submit 사용과 reviewer, 공유 tidy 담당자, 범위 변경·추가 위임은 조율자에게 요청 |
| 반환할 결과 | 업무 ID, submission.ref 또는 막힘, 변경 경로, 조건별 실제 검증 결과·근거 ref, 남은 일  |

명세의 길이는 업무에 맞춘다. 작은 업무는 위 내용을 짧게 묶어 전달한다. 새 작업자는 앞선 대화나 다른 작업자의 보고를 이미 알고 있다고 가정하지 않는다.

작업자는 work show로 현재 명세와 assignment를 확인하고, report에 조건별 관찰·근거·남은 일을 저장한다. 판단과 출처는 자신의 업무에 record로 남긴다. 수행을 마치면 submit으로 결과를 고정하고 submission.ref와 함께 호스트의 결과 반환 경로로 보고한다. 같은 워크트리의 전체 diff를 자신의 변경으로 간주하지 않고 맡은 파일과 실제 수행을 구분한다.

## 진행을 확인하고 전체 계획을 갱신한다

작업자는 명세에서 정한 중간 결과를 확인할 수 있을 때 완료 조건별 확인 결과와 근거, 남은 일과 다음 행동을 보고한다. 막힘, 선행 결과나 공통 계약의 변경, 완료 조건을 확인할 수 없는 사정은 발견한 시점에 알린다. 작은 업무는 최종 결과 보고로 충분할 수 있다.

조율자는 업무 트리의 조건별 met·unmet·unknown 보고와 호스트의 실행 상태를 기록·산출물과 대조한다. 실행 중·종료와 조건 충족, submitted와 수락된 complete를 구분한다. 진행률이나 완료 선언만으로 충족을 판단하지 않는다. 전체 조건 중 아직 맡기지 않았거나 확인하지 못한 결과도 함께 확인한다.

점검 결과에 따라 후속 업무를 시작하거나 보완을 요청하고, 범위·완료 조건·의존 관계는 work revise로 조정한다. 무효화된 상위 조건·제출과 현재 리비전을 읽고, 영향받는 작업자에게 변경한 명세를 전달한다. CLI가 보존한 무관한 검증 근거는 재사용하고 달라진 조건을 확인한다. 호스트의 대기·알림 기능과 정한 점검 시점을 사용해 새 결과나 막힘을 확인한다. 사용자에게는 확인한 결과, 남은 조건과 계획의 중요한 변경을 공유한다.

## 완료 조건을 기준으로 결과를 리뷰한다

호스트 도구로 결과·막힘·실패를 수신하고 해당 하위 업무의 기록과 연결한다. 작업자의 실행 종료나 완료 보고만으로 전체 업무를 완료하지 않는다. 조율자가 직접 [review](../review/SKILL.md)를 적용하며, 가장 먼저 업무 명세의 완료 조건을 충족했는지 판단한다.

각 완료 조건을 실제 산출물과 [verify](../verify/SKILL.md)의 검증 근거에 대조해 확인됨·미충족·미확인으로 구분한다. 검사 통과가 실제 완료 조건을 입증하는지 확인하고, 작업자의 자기 보고만으로 충족을 확정하지 않는다. 미충족·미확인 조건과 다음에 확인할 사실을 명시하고, 근거 없이 완료 조건을 낮추지 않는다. 기존 계약과 회귀 위험, 책임 배치와 유지보수성도 목표·보존할 동작에 미치는 영향을 기준으로 검토한다. 범위 밖의 개선 제안만으로 결과 수락을 막지 않는다.

하위 결과를 수락하기 전에 담당 변경을 리뷰하고, 전체 완료를 판단하기 전에는 작업 간 연결과 합쳐진 결과를 리뷰한다. 검토할 파일의 관련 수정이 끝난 상태를 기준으로 판단한다. 유효한 검증·리뷰 근거는 재사용하고, 후속 수정으로 달라진 부분과 그 영향을 받는 경로를 다시 확인한다.

- 완료 조건과 보존할 계약을 충족하는 결과는 work accept에 현재 submission.ref, 수락 이유와 실제 리뷰 근거를 연결한다. 수락된 결과를 후속 업무의 맥락으로 전달한다.
- 보완은 work request-changes에 현재 제출과 지적 조건 ID·이유를 연결해 요청한다. 위치·근거를 작업자에게 전달하고 새 report·submit 결과를 받아 영향받는 부분을 검증·리뷰한다. 오래된 제출은 수락하지 않는다.
- 막힘이나 실패는 영향받는 범위와 재개 조건을 기록하고 실행 순서·범위를 조정한다. 사람의 선택이 필요한 문제는 대안과 영향을 제시하고 그 선택에 의존하는 업무를 기다린다.

## 재개하고 마무리한다

새로운 짧은 요청을 처리할 때에도 전체 업무의 원래 목표·남은 통합·검증을 유지한다. 작업 전환과 단기 요청 완료 뒤에는 [미완료 업무 규약](../work/references/context.md#미완료-업무를-확인하고-재개한다)에 따라 현재 맡긴 전체·하위 업무를 다시 확인하고 실행 가능한 다음 단위를 진행한다. 하위 결과나 단기 요청의 완료만으로 전체 실행을 끝내지 않는다. 실제 보류·취소는 사용자 지시를 상태와 근거에 반영한다.

재개할 때 조율 기록의 하위 업무 ID로 상태와 원본을 읽고 현재 파일·산출물과 대조한다. 호스트의 실행 상태를 읽어 살아 있는 작업과 종료한 작업을 구분한 뒤 다음 실행을 정한다. 상태 확인을 위해 작업자를 다시 실행하거나, 진행 중인 업무를 중복 배정하지 않는다. 확인하지 못한 실행 상태는 미확인으로 남긴다.

모든 할당의 실행 상태·결과·남은 일을 확인하고, 전체 완료 조건과 영향을 받는 사용 경로를 검증·리뷰한다. 상위 업무의 report에 통합 결과와 실제 근거를 연결한 뒤 complete한다. CLI는 필수 하위 결과·선행 업무·상위 조건·남은 행동을 검사하며 증거의 타당성 판단은 조율자가 맡는다. 기록의 정리 필요 여부를 확인하고 최종 보고에는 조건별 판단·근거, 수락한 하위 결과와 남은 실패·미확인을 연결한다.
