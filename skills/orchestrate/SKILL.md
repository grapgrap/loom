# Orchestrate

조율자는 전체와 하위 업무의 owner로서 계획, 기록 저장, 배정과 수락을 맡는다. 작업자는 [work](../work/SKILL.md)로 맡은 범위를 수행하고 근거를 호스트로 보고한다. 작업자의 CLI 접근은 읽기 전용이며 `tidy prepare`를 포함한 저장은 조율자만 한다.

## 범위와 업무를 구성한다

[작업 맥락](../work/references/context.md)으로 현재 목표, 권한과 진행을 확인한다. 사용자와 프로젝트의 위임 및 모델 선택을 따르고 미정인 모델만 먼저 확인한다. 모든 작업자를 같은 워크트리의 절대 경로에서 실행한다. 불가능하면 제약을 알리고 다른 체크아웃으로 조용히 옮기지 않는다.

책임과 계약을 판단할 때 [원칙](../../references/principles.md)을 적용한다. 경계를 바꾸는 구현은 [architect](../architect/SKILL.md)에서 정한 컴포넌트의 책임, 경계와 입출력 계약을 재사용한다. 설계 자체를 위임하면 합의한 경계와 미확정 계약을 명세로 준다. 설명에는 [write](../write/SKILL.md)를 적용한다.

작업자 실행 전에 다음을 정한다.

1. 사용자가 얻을 결과와 보존할 계약으로 전체 완료 조건을 정하고 실제 사용 경로와 기대값을 연결한다.
2. 각 하위 업무가 기여할 전체 조건, 산출물, 수정 범위와 선행 결과를 정한다. 컴포넌트나 작업자 수에 맞춰 나누지 않는다.
3. 작업자가 확인할 입력, 환경과 기대 결과 및 제출할 근거를 정한다. [verify](../verify/SKILL.md)의 검증 준비를 첫 구현 전에 배치한다.
4. 선행 결과의 확인 시점, 공통 검증 수단과 통합 담당을 정한다. 하위 업무만으로 확인되지 않는 전체 연결 동작도 맡긴다.

[업무 계약](../work/references/context-work.md)과 [위임 상태 전이](../work/references/work-delegation.md)에 따라 create, assign, report, submit과 accept를 사용한다. 목표와 관계 및 진행은 CLI에 두며 작은 작업에 별도 계획 문서를 만들지 않는다. 담당이나 조건을 바꾸면 무효화된 검증과 제출 및 후속 업무를 확인한다.

## 수정 범위와 명세를 전달한다

독립적인 조사는 병렬로 수행할 수 있다. 수정은 같은 파일을 동시에 쓰지 않도록 나누고 선행 계약이 필요하면 순차 진행한다. 공통 계약이나 범위 충돌이 생기면 영향받는 수정을 멈추고 조정한다. 조율자가 실행 중인 작업자의 영역을 직접 수정하지 않는다. 전체 포맷, 의존성 갱신, 브랜치와 커밋은 수행자와 시점을 정하고 맡긴 권한을 지킨다.

새 작업자에게 전달할 메시지에는 다음을 포함한다. 조율자 기록만으로 공유됐다고 가정하지 않는다.

- `work` 스킬의 실제 절대 경로와 전체 목표, 이번 업무의 기여 조건
- 같은 워크트리 경로, 업무 ID, worker ID, 조회할 CLI와 데이터 루트
- 맡긴 결과와 수정 범위, 다른 작업자의 영역과 선행 결과
- 합의한 계약과 제약, 정확한 원본 ref, 미결정 사항과 조건별 검증 방법
- 중간 보고 시점, 즉시 알릴 막힘과 전제 변경, CLI 읽기 전용 및 호스트 보고 규약
- 반환할 업무와 명세 ref, 변경 경로, 조건별 관찰과 근거, 남은 일

작업자는 [위임 수행 지침](../work/references/delegated-work.md)으로 명세를 읽고 이해한 목표와 검증 방법을 짧게 설명한다. 누락이나 모순을 알리되 충분한 명세에는 별도 이해완료 승인 없이 착수한다. 범위 변경과 추가 위임은 조율자에게 요청한다.

## 진행과 수락을 판단한다

`work show --work <전체-id> --tree`의 현재 조건과 호스트의 실행 상태를 대조한다. ready는 실행 중인 작업을 중복 배정할 권한이 아니며, pending은 정리하지 않은 원본이다. 작업자의 실행 종료, 제출과 수락을 구분한다. 호스트 대기와 알림을 사용하며 상태 확인을 위해 작업자를 다시 실행하지 않는다.

작업자의 보고를 현재 명세와 대조해 report한다. 실제 보고자와 산출물을 출처에 연결하고 작업자의 완료 선언으로 실제 결과의 검증을 대신하지 않는다. 조건, 담당과 의존 관계의 변경은 조율자가 판단해 명세에 반영하고 영향받는 작업자에게 전달한다. 목표나 권한의 변경은 사용자 선택을 따른다.

결과가 준비되면 submit으로 고정하고 [review](../review/SKILL.md)와 [verify](../verify/SKILL.md)의 기준으로 실제 산출물을 검토한다. 현재 제출의 산출물이 완료 조건을 충족하면 accept, 보완이 필요하면 해당 조건 ID와 근거로 request-changes한다. 오래된 제출을 수락하거나 기준을 낮추지 않는다. 범위 밖 제안만으로 수락을 막지 않으며 새 변경으로 무효화되지 않은 검증은 재사용한다.

## 전체 결과를 마무리한다

작업 전환과 짧은 요청 뒤에는 [재개 규약](../work/references/context.md#미완료-업무를-확인하고-재개한다)으로 원래 전체 목표와 남은 통합을 확인한다. 보류와 취소는 사용자 지시를 따른다. 막힌 부분은 원인과 재개 조건을 남기고 독립적으로 가능한 일은 계속한다.

모든 하위 업무의 상태와 아직 담당자가 없는 업무를 확인하고 합쳐진 실제 사용 경로를 검증한다. 전체 조건별 보고와 근거를 저장한 뒤 complete한다. 조율자가 [tidy](../tidy/SKILL.md)로 필요한 맥락을 정리하고, 최종 보고에는 전체 결과와 근거, 수락한 하위 결과 및 남은 실패와 미확인을 연결한다.
