# 명확한 표현

필요한 정보를 보존하면서 독자가 사실·제약·책임 관계를 한 번에 이해할 수 있게 쓴다.

## 의미를 보존하고 내용을 선별한다

판단이 충돌하면 다음 순서를 따른다.

1. 사실, 요구사항과 필수 맥락을 정확하게 보존한다.
2. 독자가 이해하거나 판단·행동하는 데 필요한 내용을 남긴다.
3. 용어, 어조와 구조를 일관되게 만든다.
4. 읽고 이해하기 쉽게 표현한다.
5. 위 조건을 해치지 않는 범위에서 줄인다.

간결함을 위해 조건·범위·책임 주체·불확실성을 삭제하지 않는다. 확인되지 않은 내용을 사실로 바꾸지 않는다.

대화와 제작 지침은 자동으로 문서의 내용이 되지 않는다. 지침은 구조와 표현에 반영한다. 사용자 요청·대화 이력·중간 추론·수정 과정·사용한 도구·제외한 대안은 독자의 판단에 필요할 때만 남긴다. 필요한 제약·근거·검증 결과·실패·미확인 사항은 보존한다. 예시는 독자의 이해에 필요한 경우에 포함한다.

## 목적에 맞게 구조를 정한다

- 결과 보고와 행동 요청은 결론·결정·필요한 행동을 먼저 쓴다. 문제와 근거를 따라 판단해야 하는 문서는 독자의 이해에 필요한 순서로 전개한다.
- 한 문장에는 하나의 주장·지시 또는 조건과 결과를 담고, 한 문단에는 하나의 주제를 둔다. 길이만으로 관계가 이어진 설명을 끊지 않는다.
- 조건은 해당 결과나 지시보다 먼저 쓴다.
- 순서는 번호 목록으로, 병렬 항목은 목록으로, 여러 항목을 여러 기준으로 비교할 때는 표로 정리한다. 항목 수를 맞추기 위해 내용을 나누지 않는다.
- 반복 수정으로 생긴 중복, 어조 변화와 끊긴 연결을 하나의 흐름으로 정리한다.

## 용어·주체·관계를 명확하게 쓴다

- 하나의 개념에는 하나의 용어를 사용한다. 독자에게 낯선 용어는 첫 사용 시 설명하고, 코드의 실제 이름과 도메인 용어를 정확하게 쓴다. 표현을 변주하려고 동의어로 바꾸지 않는다.
- 정착된 번역어나 음차를 사용하고, 적절한 표현이 없으면 원어를 유지한다.
- `처리한다`, `관리한다`, `지원한다`처럼 범위가 넓은 동사는 실제 행위로 바꾼다. `분석을 수행한다`보다 `분석한다`처럼 직접 쓴다.
- 누가 무엇을 하는지 밝힌다. 행위자가 알려지지 않았거나 중요하지 않을 때만 수동태를 사용한다.
- 사실·의무·제외·허용·능력·가능성을 구분한다. 허용은 허용하는 주체를 밝히고, 가능성을 보장이나 의무로 바꾸지 않는다.
- `이것`, `해당`, `this`, `it`은 선행 대상이 하나로 특정될 때만 사용한다. 조건·원인·결과의 관계를 접속사나 별도 문장으로 드러내고 엠대시로 함축하지 않는다.
- 일반적인 말로 정확하게 표현할 수 있으면 비유·관용 표현·장식적인 수식어를 사용하지 않는다. 정보를 추가하지 않는 도입구, 근거 없는 평가와 반복을 삭제한다.

## 한국어 문장을 완성한다

- 중간점(·)을 사용하지 않는다. 문맥에 맞는 조사와 접속 표현을 사용해 올바른 한국어로 쓴다. 예를 들어 `작성·교정·요약·검토`는 `작성, 교정, 요약과 검토`로, `판단·행동한다`는 `판단하고 행동한다`로 쓴다.
- 조사·어미·의미를 담은 문장 성분을 생략하지 않는다. 명사를 연속해서 나열하기보다 조사와 동사로 관계를 밝힌다.
- 제목과 목록 항목을 제외한 문장은 서술어와 종결어미로 끝낸다.
- 독자와 상황에 맞는 높임 수준을 선택하고 문서 전체에서 유지한다.
- 감탄·과장·수사적 표현을 덧붙이지 않는다.

## 산출물에 맞게 적용한다

| 산출물            | 기준                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 기술 문서         | 현재 상태·결정·제외한 대안을 구분한다. 제약의 출처가 판단에 필요하면 밝힌다. 용어가 많아 이해하기 어려우면 용어집을 둔다.      |
| 업무 커뮤니케이션 | 첫 문장에 알아야 할 내용이나 해야 할 행동을 쓴다. 기한은 구체적인 날짜로 표시하고, 필요한 경우 다음 단계와 담당자를 밝힌다.    |
| 주석              | 코드만으로 드러나지 않는 이유와 제약을 설명한다. 코드의 책임과 변경 범위는 [코드 규칙](../../../references/rules.md)을 따른다. |
| 에러 메시지       | 실패한 내용과 알려진 수정 방법을 실패 지점 가까이에 표시한다. 원인이나 해결 방법을 추측해 단정하지 않는다.                     |
| 테스트명          | 조건과 기대 결과를 서술한다.                                                                                                   |
| 커밋 메시지       | 제목에는 변경 내용을 쓰고, 필요한 본문에는 변경 이유를 쓴다.                                                                   |
| PR 본문           | 변경 내용·변경 이유·검증 방법을 포함한다.                                                                                      |

## 최종 점검

전달 전에 독자가 필요한 맥락을 갖추었는지, 같은 개념과 어조를 일관되게 썼는지, 주체·행동·조건·범위가 명확한지 확인한다. 문장을 줄이면서 의미를 잃거나 제작 과정의 흔적을 불필요하게 남기지 않았는지 확인한다.
