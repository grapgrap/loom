# 명확한 표현

독자가 필요한 사실과 제약, 책임 관계를 한 번에 이해하고 판단할 수 있도록 쓴다. 표현을 줄이거나 바꾸더라도 원문의 의미와 적용 조건을 보존한다.

## 의미를 보존하고 내용을 고른다

표현상의 선택이 충돌하면 다음 순서로 판단한다.

1. 사실, 요구사항과 필수 맥락을 정확하게 보존한다.
2. 독자의 이해, 판단과 행동에 필요한 내용을 남긴다.
3. 용어, 어조와 구조를 일관되게 만든다.
4. 읽고 이해하기 쉽게 표현한다.
5. 앞의 조건을 해치지 않는 범위에서 줄인다.

간결하게 쓰기 위해 조건, 범위, 책임 주체나 불확실성을 삭제하지 않는다. 확인되지 않은 내용을 사실로 바꾸지 않는다.

대화와 제작 지침은 문서의 구조와 표현에 반영한다. 사용자 요청, 대화 이력, 중간 추론, 수정 과정, 사용한 도구나 제외한 대안은 독자의 판단에 필요할 때만 본문에 넣는다. 필요한 제약과 근거, 검증 결과, 실패와 미확인 사항은 보존한다. 예시도 독자의 이해에 필요한 경우에 사용한다.

## 독자가 이해할 순서로 구성한다

결과 보고와 행동 요청은 결론, 결정이나 필요한 행동부터 쓴다. 문제와 근거를 따라 판단해야 하는 문서는 독자의 이해에 필요한 순서로 전개한다. 반복 수정으로 생긴 중복이나 끊긴 연결은 하나의 흐름으로 정리한다.

한 문장에는 하나의 주장이나 지시, 또는 조건과 그 결과를 담는다. 한 문단은 하나의 주제를 다루되 서로 이어진 설명을 길이만으로 나누지 않는다. 조건은 그 조건이 적용되는 결과나 지시보다 먼저 쓴다.

순서가 있는 행동은 번호 목록으로, 병렬 항목은 목록으로 정리한다. 여러 대상을 여러 기준으로 비교할 때는 표를 사용한다. 항목 수를 맞추려고 내용을 억지로 나누지 않는다.

## 용어와 책임 관계를 명확히 한다

- 하나의 개념에는 하나의 용어를 사용한다. 낯선 용어는 처음 나올 때 설명하고 코드의 실제 이름과 도메인 용어를 정확하게 쓴다. 표현을 다양하게 만들기 위해 같은 개념의 이름을 바꾸지 않는다.
- 정착된 번역어나 음차를 사용한다. 적절한 표현이 없으면 원어를 유지한다.
- 범위가 넓은 동사 대신 실제 행동을 쓴다. 예를 들어 무엇을 하는지 알기 어려운 “관리한다”를 구체화하고, “분석을 수행한다”는 “분석한다”로 쓴다.
- 누가 무엇을 하는지 밝힌다. 행위자를 모르거나 행위자가 중요하지 않을 때만 수동태를 사용한다.
- 사실, 의무, 제외, 허용, 능력과 가능성을 구분한다. 허용하는 주체를 밝히고 가능성을 보장이나 의무로 바꾸지 않는다.
- “이것”, “해당”, “this”, “it”은 가리키는 대상이 하나로 분명할 때만 사용한다. 조건, 원인과 결과의 관계는 접속사나 별도 문장으로 설명하며 엠대시로 함축하지 않는다.
- 일상적인 말로 정확하게 설명할 수 있으면 비유, 관용 표현이나 장식적인 수식어를 덧붙이지 않는다. 정보를 더하지 않는 도입구, 근거 없는 평가와 반복은 삭제한다.

## 한국어 문장을 완성한다

중간점으로 단어를 연결하지 말고 문맥에 맞는 조사와 접속 표현을 쓴다. 여러 작업을 나열할 때는 “작성, 교정, 요약과 검토”처럼 쓰고, 함께 할 행동은 “판단하고 행동한다”처럼 문장으로 연결한다.

조사, 어미와 의미를 담은 성분을 생략하지 않는다. 명사를 연속해서 나열하기보다 조사와 동사로 관계를 밝힌다. 제목과 목록 항목을 제외한 문장은 서술어와 종결어미로 끝낸다.

독자와 상황에 맞는 높임 수준을 선택하고 문서 전체에서 유지한다. 감탄, 과장이나 수사적 표현은 덧붙이지 않는다.

## 산출물의 목적에 맞춘다

| 산출물            | 기준                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 기술 문서         | 현재 상태, 결정과 제외한 대안을 구분한다. 판단에 필요한 제약의 출처를 밝히고, 용어가 많아 이해하기 어려우면 용어집을 둔다. |
| 업무 커뮤니케이션 | 첫 문장에 알아야 할 내용이나 해야 할 행동을 쓴다. 기한은 구체적인 날짜로 표시하고 필요한 다음 단계와 담당자를 밝힌다.      |
| 주석              | 코드만으로 드러나지 않는 이유와 제약을 설명한다.                                                                           |
| 에러 메시지       | 실패한 내용과 알려진 수정 방법을 실패 지점 가까이에 표시한다. 원인이나 해결 방법을 추측해 단정하지 않는다.                 |
| 테스트명          | 조건과 기대 결과를 서술한다.                                                                                               |
| 커밋 메시지       | 제목에는 변경 내용을 쓰고 필요한 본문에는 변경 이유를 쓴다.                                                                |
| PR 본문           | 변경 내용, 변경 이유와 검증 방법을 포함한다.                                                                               |

## 전달 전에 확인한다

독자가 필요한 맥락을 갖추었는지, 같은 개념과 어조를 일관되게 썼는지 확인한다. 주체, 행동, 조건과 범위가 분명해야 한다. 문장을 줄이면서 의미를 잃거나 독자에게 필요 없는 제작 과정의 흔적을 남기지 않았는지 점검한다.
