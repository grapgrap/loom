# Write

독자가 필요한 사실과 관계를 이해하고 판단하거나 행동할 수 있도록 쓴다. 요청한 작업에 맞춰 문서 구성과 표현의 기준을 적용한다.

## 목적과 범위를 정한다

목적과 독자를 파악하고, 맡은 작업이 작성, 교정, 요약과 검토 중 무엇인지 확인한다. 요청에서 명확하면 다시 묻지 않는다. 독자가 지금 이해하거나 판단하려는 문제를 기준으로 설명할 내용을 고른다. 개념과 관계의 이해, 선택의 비교, 다음 행동의 결정 등 질문의 목적에 맞춰 기여도를 판단한다.

주어진 사실로 요청한 글을 쓸 수 있으면 바로 작성한다. 새로운 사실을 확인해야 답할 수 있는 질문은 `$loom:work`에 전달하고 조사 결과가 뒷받침하는 범위에서 쓴다.

설명의 출발점은 독자의 전문성과 이미 공유한 맥락에 맞춘다. 독자가 아는 개념의 반복은 줄이고, 이번에 이해하거나 판단하는 데 필요한 내용과 근거를 연결한다. 독립적으로 전달할 문서는 대화를 몰라도 이해할 수 있도록 필요한 맥락을 포함한다.

## 필요한 기준을 적용한다

| 적용 상황                                                   | 참조                                   | 적용할 판단                                                              |
| ----------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------ |
| 글을 작성, 교정, 요약하거나 검토할 때                       | [명확한 표현](references/clarity.md)   | 의미를 보존하고 내용과 구조, 용어와 문장을 명확하게 만든다.              |
| 문제를 정의하거나 근거와 판단의 논리를 구성하거나 검토할 때 | [문서 프레이밍](references/framing.md) | 문제의 중요성, 판단 기준, 근거와 결론, 성립 조건과 적용 범위를 연결한다. |

해당 참조를 읽고 적용한다. 판단의 논리를 구성하거나 검토할 때는 두 기준을 함께 적용한다. 교정과 요약에서는 원문의 방향과 판단을 보존하고 문제나 제안을 새로 구성하지 않는다.

## 요청한 결과를 전달한다

질문에는 답과 판단에 필요한 근거를 간결하게 전달한다. 독립적인 작성이나 편집 요청에는 완성된 문서를 반환하고, 변경 요약은 요청받았을 때 문서 뒤에 붙인다. 검토만 요청받으면 근거와 수정 방향을 보고하며 문서를 임의로 수정하지 않는다. 독자의 판단에 필요하지 않은 제작 과정과 스킬 적용 설명은 덧붙이지 않는다.

작업 결과나 검토 내용을 보고할 때는 결과와 판단 근거를 한 페이지 이내로 구성한다. 다른 Loom 스킬을 보조한다면 맡은 범위와 완료 판정을 유지하며 수신자가 이해하거나 판단하는 데 필요한 내용을 선별한다. 실행자에게 인계할 상세 근거와 사용자에게 전달할 보고를 구분한다. 완료 조건의 실패나 결과 사용을 제한하는 미확인 사항은 영향과 대응 방향을 함께 전달한다. 업무 커뮤니케이션을 작성하거나 전송할 권한은 사용자가 맡긴 범위를 따른다.

여러 작업의 결과를 요약할 때는 독자가 각 판단의 원본 대화와 산출물, 검증 근거를 찾을 수 있게 한다.
