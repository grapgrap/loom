# Write

독자가 필요한 사실과 관계를 이해하고 판단·행동할 수 있는 글을 만든다. 요청한 작업에 맞춰 문서 구성과 표현의 기준을 적용한다.

## 목적과 범위를 정한다

- 목적, 독자와 맡긴 작업이 작성·교정·요약·검토 중 무엇인지 확인한다. 요청에서 명확하면 다시 묻지 않는다.
- 독자가 내려야 할 판단이나 취할 행동, 보존할 사실·제약·책임·불확실성을 확인한다.
- 대화에서 사용할 설명은 이미 공유한 맥락과 문제의식을 활용하고, 독자가 추가로 이해하거나 판단하는 데 필요한 내용을 설명한다. 독립적으로 전달할 문서는 대화를 몰라도 이해할 수 있게 완성한다.

## 필요한 기준을 적용한다

| 적용 상황                                             | 참조                                   | 적용할 판단                                                              |
| ----------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------ |
| 글을 작성·교정·요약·검토할 때                         | [명확한 표현](references/clarity.md)   | 필요한 의미를 보존하고 내용·구조·용어·문장을 명확하게 만든다.            |
| 문제를 정의하거나 근거와 판단의 논리를 구성·검토할 때 | [문서 프레이밍](references/framing.md) | 문제의 중요성, 판단 기준, 근거와 결론, 성립 조건과 적용 범위를 연결한다. |

해당 참조를 읽고 적용한다. 판단의 논리를 구성하거나 검토하는 요청에는 두 기준을 함께 적용한다. 문서 종류만으로 프레이밍 절차를 선택하지 않는다. 설계 제안이라도 문장 교정만 요청받았다면 표현 기준을 적용한다. 교정·요약에서는 원문의 방향과 판단을 보존하고 문제나 제안을 새로 구성하지 않는다.

## 요청한 결과를 전달한다

독립적인 작성·편집 요청에는 완성된 문서를 중심으로 반환한다. 요청받지 않은 제작 과정이나 스킬 적용 설명은 덧붙이지 않는다. 변경 요약을 요청받으면 문서 뒤에 붙인다. 검토만 요청받으면 근거와 수정 방향을 보고하고 문서를 임의로 수정하지 않는다.

다른 Loom 스킬의 보조 도구로 적용할 때는 그 작업의 범위·보고 형식·필수 내용을 유지한다. 표현을 다듬는다는 이유로 증거·실패·미확인 사항이나 남은 결정을 생략하지 않는다. 업무 커뮤니케이션의 작성·전송 권한은 사용자가 맡긴 범위를 따른다.
