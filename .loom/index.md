# Index

프로젝트의 도메인 엔티티와 그 관계를 기술하는 지도.

## 목표

- 소프트웨어 설계의 자연스러운 흐름을 구조화하여 재현 가능하게 한다
- 구조화된 흐름의 산출물이 시간이 지나도 유효하도록 피드백 루프를 유지한다

## 목록

- [[index]] — 디렉토리의 진입점, 항목과 관계를 요약하는 탐색 지도
- [[concept]] — 시스템을 이루는 도메인을 불변 수준에서 정의하는 영속 문서 (분해)
- [[flow]] — 도메인들을 불러 조합하는 오케스트레이션을 기술하는 영속 문서 (조합)
- [[decision]] — concept과 flow의 변경 맥락을 기록하는 횡단 문서
- [[proposal]] — 영속화 이전 단계에서 문제와 해결의 방향성을 제안하고 팀 확인을 구하는 자기완결적 문서
- [[plan]] — 문제와 원하는 결과를 확인하고 현재 구현을 조사하며, 구현 초안과 영향을 사용자와 검토하여 실행할 작업을 구성하는 문서
- [[rule]] — 항상 지켜져야 하는 강제적 합의
- [[convention]] — 강하게 권장되지만 대체 가능한 형태

## 관계

```
  proposal (영속화 이전 · 팀 확인)
       │ 채택 시 후속 세분화 논의의 준거
       ▼
  concept (분해 · 도메인)  <== 불러 조합 ==  flow (조합 · 오케스트레이션)
          \                                        /
                    decision (변경 맥락)
                           |
                         plan
                           ^ 자동 참조
                    rule · convention
```

- **proposal**은 영속 문서로 확정하기 이전 단계에서 문제와 해결의 방향성을 제안하고 팀의 확인을 구한다. 프로젝트의 공유 어휘로 서술하되 loom 문서를 참조하지 않아 문서 하나로 자기완결적이며, 채택되면 후속 세분화 논의의 준거가 된다. 영속 문서망을 세우기 이전의 입구에 선다.
- **concept**은 시스템을 이루는 도메인을 불변 수준에서 정의한다(분해). **flow**는 그 도메인들을 불러 조합하는 오케스트레이션을 기술한다(조합). 두 축은 같은 불변 수준에 있다. 가르는 질문 하나로 나눈다 — 여러 도메인을 불러 조합하면 flow, 한 도메인 안의 동작·계산이면 concept이다. 명명 가능성은 판별 근거가 아니다.
- **decision**이 concept과 flow의 변경을 횡단적으로 기록한다. 여러 엔티티에 걸칠 수 있다.
- **plan**이 concept·flow·decision을 참조하고 실제 구현을 조사하여 구현 방안과 영향을 사용자와 검토한다. 검토한 변경안에서 작업과 결과 간 의존관계를 도출한다. concept과 flow의 의미 변경이 필요하면 해당 설계를 재검토한다.
- **rule·convention**은 각 스킬이 룰 카탈로그 로드 단계에서 인지하는 합의 잔고다. 강제성 축에서 rule이 무거운 자리, convention이 가벼운 자리이며, `.loom/rules/` 폴더에 보관된다.
- 누적된 decision이 새 rule·convention의 판단 기준 역할을 한다. 별도의 "원칙" 엔티티는 두지 않으며, 깊은 판단 근거는 사용자 본인의 영역에 머문다.
