# Loom 문서 책임을 내부 참조 계약으로 보관한다

## 맥락

Loom 문서를 작성하는 에이전트가 concept, flow, decision과 index의 책임을 혼합하는 문제를 보완하기 위해 사용자 범위에 `loom_document_responsibilities.md`가 작성되어 있었다. 이 문서는 각 문서 유형이 소유하는 내용, 소유하지 않는 내용과 책임 위반 시의 라우팅을 하나의 계약으로 설명한다.

이 계약을 Loom이 직접 집행하려면 shape, review와 calibrate가 같은 내용을 참조해야 한다. 계약을 문서 유형별 concept으로 분산하면 실행 시점에 다시 요약해야 하고, concept과 실행용 요약 사이에 권위가 나뉠 수 있다. 반대로 계약 전문을 각 스킬과 에이전트에 복사하면 변경 시 서로 다른 내용으로 표류할 수 있다.

## 결정

Loom 문서 책임 계약을 새 concept으로 정의하지 않고, Loom 플러그인이 소유하는 단일 내부 참조 문서로 보관한다.

- 현재 `loom_document_responsibilities.md`의 전체 내용을 내부 참조 문서의 초기 계약으로 사용한다.
- shape는 Loom 문서를 작성하기 전과 작성한 후에 계약을 참조하여 내용을 올바른 문서 유형으로 라우팅하고 책임 위반을 교정한다.
- review는 이번 세션에서 변경된 Loom 문서를 검토할 때 계약을 명시적 평가 기준으로 사용한다.
- calibrate는 누적된 Loom 문서를 감사할 때 계약을 사용하여 문서 유형 사이의 책임 드리프트를 발견한다.
- 템플릿은 계약을 불러오는 방식과 같은 참조 가능한 내부 자산으로 취급한다. 스킬, 에이전트와 템플릿에는 계약 전문을 복제하지 않는다.
- 프로젝트의 rule이나 convention으로 복사하지 않는다. 이 계약은 특정 프로젝트의 합의가 아니라 Loom 문서 작성과 검증에 적용되는 내장 기준이다.

### 전제 조건

- 스킬과 에이전트가 플러그인 내부 참조 문서를 명시적으로 불러올 수 있다.
- 템플릿을 활용할 때와 마찬가지로, 행동 시점의 명시적 참조가 계약을 실제 판단에 사용하도록 유도한다.

### 제약 조건

- 실행 주체가 참조 문서를 불러오지 않으면 계약이 작동하지 않는다.
  - 제약이 없었다면: 참조 여부와 무관하게 문서 책임을 구조적으로 강제했을 것이다.

## 대안

### 문서 책임을 concept으로 정의한다

- 설명: 문서 책임을 Loom 도메인의 concept으로 만들고 concept을 단일 진실 공급원으로 사용한다.
- 트레이드오프: 현재 계약은 여러 문서 유형의 작성과 검증에 적용되는 실행 기준이다. 이를 문서 유형별 concept과 함께 유지하면 책임 정의와 실행용 계약의 경계가 다시 필요하고, 계약 전문을 한 번에 참조하려는 목적이 약해진다.

### 계약 전문을 각 스킬과 에이전트에 복사한다

- 설명: shape, reviewer와 calibrate의 지침에 문서 책임 내용을 각각 포함한다.
- 트레이드오프: 계약이 변경될 때 여러 복사본을 함께 갱신해야 하며, 복사본 사이의 내용이 표류할 수 있다.

### 프로젝트 rule로 보관한다

- 설명: 각 프로젝트의 `.loom/rules/`에 문서 책임 계약을 복사하고 룰 카탈로그를 통해 불러온다.
- 트레이드오프: Loom 자체의 문서 의미를 프로젝트별 합의로 바꾸며, 프로젝트마다 같은 계약을 중복해서 보관해야 한다.

## 영향

- shape - Loom 문서 작성 전후에 내부 문서 책임 계약을 참조한다.
- review와 reviewer - 변경된 Loom 문서의 책임 적합성을 계약에 따라 검토한다.
- calibrate - 누적된 Loom 문서의 책임 드리프트를 계약에 따라 감사한다.
- templates - 문서 구조를 제공하되 문서 책임 계약의 권위 있는 복사본이 되지 않는다.
