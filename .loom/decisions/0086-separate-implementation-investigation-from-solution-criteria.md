# 현재 구현의 조사와 구현 방안의 판단 기준을 구분한다

## 맥락

plan을 현재 구현에 근거하여 변경 방법과 영향을 검토하는 과정으로 정의했다. 이 표현은 현재 구현을 조사하라는 뜻과 기존 구조 안에서 해법을 찾으라는 뜻을 구분하지 못했다. 기존 구조 자체가 문제의 원인인 경우에도 구조를 유지하도록 해석할 여지가 있었다.

또한 변경 방법은 수정 절차와 설계 선택 중 무엇을 의미하는지 불분명했다. 필요한 것은 문제를 해결하기 위해 코드의 어느 부분을 어떤 구조나 동작으로 바꿀지 제안하고 그 영향을 검토하는 과정이다.

## 결정

현재 구현은 문제 이해와 영향 분석의 대상으로 조사한다. 구현 방안의 타당성은 문제를 해결하고 원하는 결과를 만드는지로 판단한다.

- 기존 구조를 유지할지는 검토에서 결정한다. 구조 자체가 원인이면 재구성하거나 제거하는 방안도 검토한다.
- 구현 방안은 문제를 해결하기 위해 코드의 어느 부분을 어떤 구조나 동작으로 바꿀지에 대한 제안이다.
- 변경안은 구현 방안과 예상 영향, 필요한 대응을 포함한다.
- plan은 문제와 원하는 결과를 확인하고 현재 구현을 조사한다. 구현 방안과 그 영향을 사용자와 검토한 뒤 실행할 작업을 도출한다.
- review는 현재 동작의 설명을 코드와 대조한다. 구현 방안은 문제 해결과 원하는 결과를 기준으로 검증한다. 기존 구조의 유지 자체를 타당성의 기준으로 삼지 않는다.

현재 구현의 조사 의무와 변경 영향 검토는 유지한다. 기존 도메인의 의미나 경계를 바꿔야 할 때 shape에서 재검토하는 절차도 유지한다.

### 전제 조건

- 현재 동작을 정확히 이해하는 것과 기존 구조를 유지하는 것은 서로 다른 판단이다.
- 문제와 원하는 결과를 기준으로 구현 방안을 검토하면서도 기존 동작에 미치는 영향을 코드에서 확인할 수 있다.

## 대안

### 현재 구현에 근거한다는 표현을 유지한다

- 설명: 기존 표현을 유지하고 기존 구조를 바꿀 수 있다는 단서를 추가한다.
- 트레이드오프: 조사 대상과 판단 기준의 혼동이 핵심 정의에 남는다. 두 행위를 분리하여 기술한다.

### 현재 구현의 조사를 요구하지 않는다

- 설명: 원하는 결과를 중심으로 구현 방안만 검토한다.
- 트레이드오프: 현재 문제의 원인과 기존 동작에 미치는 영향을 확인하려는 plan의 목적을 충족하지 못한다.
