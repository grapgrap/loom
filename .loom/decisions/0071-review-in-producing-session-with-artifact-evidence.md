# review를 산출물을 만든 세션의 증거 기반 적대적 검토로 전환한다

## 맥락

Loom은 plugin agent인 reviewer를 제거하면서, 산출물을 만든 대화의 관성을 차단하기 위해 review를 새 세션에서 직접 실행하도록 바꾸었다. 새 세션은 `git status`와 diff로 검토 대상을 재구성하고, 범위가 모호할 때만 사용자에게 묻는다는 전제였다.

실제 실행에서 이 전제는 검토 범위를 잃는다. 한 세션에서 앞선 작업을 커밋한 뒤 다음 작업을 계속하면 `git status`에는 아직 커밋하지 않은 마지막 변경만 남는다. `.loom/plans/`처럼 Git에서 무시된 산출물은 변경되어도 후보나 모호함의 신호조차 나타나지 않는다. 파일 목록만 넘기는 handoff도 modified 파일이 어떻게 바뀌었는지 보존하지 않으므로, 새 세션이 raw 변경을 복원하려면 결국 commit range나 patch에 준하는 별도 전달 계약이 필요하다.

동일 세션에서 현재 review 절차를 실행한 결과도 새 세션만이 적대적 검토를 수행할 수 있다는 전제를 약화했다. 동일 세션 검토는 독립 forward-test와 같은 문서 불일치를 발견했고, 추가로 Git 상태 기반 범위 판정의 결함과 룰 카탈로그의 실행 불능을 지적했다. 독립 검토에서만 나온 지적은 이미 기록된 합의와 충돌하여 자기반박을 통과하지 못했다. 한 차례의 실행이 구조적 독립성을 증명하지는 않지만, raw 산출물 재독해와 자기반박을 강제하면 동일 맥락에서도 유효한 적대적 검토가 가능함을 확인했다.

따라서 검토의 비판적 거리와 검토 범위의 완전성을 하나의 세션 경계로 함께 해결하지 않는다. 무엇을 검토할지 정하는 범위 근거와, 그것이 정당한지 판정하는 평가 근거를 분리한다.

## 결정

review는 기본적으로 산출물을 만든 동일 세션에서 직접 실행한다.

- **범위 식별에는 세션 맥락을 사용한다.** 사용자가 명시한 범위를 우선하고, 그렇지 않으면 현재 세션의 실행 이력에서 생성·수정·삭제한 파일, 세션 중 만든 commit과 그 범위, Git에서 무시되었지만 다룬 산출물을 파악한다.
- **평가 근거에는 대화의 의도를 사용하지 않는다.** 세션에서 합의했다는 사실이나 에이전트가 변경을 선택한 이유는 정당화가 아니다. 검토자는 raw 파일, 실제 diff·patch·commit range, `.loom` 문서와 적용 가능한 일반 표준을 다시 읽어 비판하고 자기반박한다.
- `git status`는 검토 범위의 원천이 아니라, 세션에서 파악한 범위와 현재 작업 트리 사이의 누락·혼입을 확인하는 보조 신호로 사용한다.
- tracked 미커밋 변경은 diff로, 세션 중 커밋한 변경은 해당 commit 또는 range로 변화 내용을 읽는다. untracked·ignored 산출물은 현재 본문과 세션에 남은 편집 증거를 읽는다. modified 산출물의 변경 전후를 복원할 수 없으면 이를 숨기지 않고 사용자에게 범위나 증거를 확인한다.
- 별도의 영속 handoff 문서는 기본 계약으로 두지 않는다. plan은 기존대로 세션 간 진행 맥락을 운반하지만, review만을 위한 파일 목록이나 서술형 요약을 추가로 강제하지 않는다.
- 새 세션 review는 사용자가 더 강한 독립 감사를 원할 때 선택할 수 있다. 이 경우에는 `git status`로 범위를 추정하지 않고, 사용자가 지정한 commit·range·patch 또는 명시적 산출물 범위를 검토한다.
- review는 계속 검증·보고만 수행하고 산출물을 직접 수정하지 않는다.

### 전제 조건

- 동일 세션은 실행 이력을 범위 식별에 활용할 수 있다: 작업 중 사용한 파일과 Git 동작이 대화 및 도구 이력에 남으므로, 현재 작업 트리만 보는 것보다 세션 산출물을 완전하게 파악할 수 있다.
- 적대성은 대화의 부재만이 아니라 평가 증거의 제한과 자기반박에서도 나온다: 현재 review 절차의 실제 실행에서 동일 세션도 자신이 만든 설계의 전제를 회귀로 판정했다.
- raw 변화가 서술형 handoff보다 강한 검토 근거다: modified 파일은 경로뿐 아니라 diff·patch·commit range가 있어야 변화가 만든 회귀를 검토할 수 있다.

### 제약 조건

- 동일한 에이전트와 대화 맥락은 자기 판단에 유리한 인지 편향을 남길 수 있다.
  - 제약이 없었다면: 범위 완전성과 구조적 독립성을 동시에 자동 보장했을 것이다. 현재는 동일 세션의 증거 규율을 기본으로 하고, 필요할 때 raw 변경 범위를 명시한 새 세션 감사를 선택한다.
- 세션 이력이 축약되거나 외부 변경이 섞이면 실행 이력만으로 정확한 범위를 확정하지 못할 수 있다.
  - 제약이 없었다면: 런타임이 세션별 변경 원장을 자동 제공했을 것이다. 현재는 Git 증거와 대조하고 불일치가 남을 때 사용자에게 확인한다.
- ignored 파일의 변경 전 상태가 편집 증거에 남지 않았다면 완전한 diff를 복원할 수 없다.
  - 제약이 없었다면: 모든 산출물에 자동 스냅샷이 존재했을 것이다. 현재는 복원 불능을 보고하고 현재 상태 검토인지 변경 검토인지 구분한다.

## 대안

### 새 세션에서 `git status`로 검토 범위를 추정

- 설명: 산출물 생성 대화와 검토 대화를 분리하고, 새 세션이 작업 트리의 변경 후보를 읽는다.
- 트레이드오프: 이미 커밋된 세션 변경과 ignored 산출물을 발견하지 못하며, 그 누락은 모호함으로도 드러나지 않는다. 구조적 거리의 대가로 검토 대상 자체를 잃는다.

### shape·plan·task가 review handoff 문서를 항상 작성

- 설명: 각 단계가 검토 대상 파일과 변경 설명을 영속 문서로 남겨 새 세션에 전달한다.
- 트레이드오프: 경로 목록은 modified 파일의 실제 변화를 보존하지 못하고, 서술형 설명은 구현자의 해석을 검토자에게 주입한다. raw patch 수준으로 확장하면 모든 작업에 별도 변경 원장을 유지하는 비용이 생긴다.

### 동일 세션에서 익명 subagent에게 위임

- 설명: 메인이 파악한 raw 범위를 일반 subagent에 전달하여 구조적 거리를 확보한다.
- 트레이드오프: 런타임별 위임 기능과 전달 계약에 다시 의존한다. 독립 감사에는 사용할 수 있지만 Claude Code와 Codex가 공유하는 기본 review 흐름으로 삼지 않는다.

## 영향

- review 스킬 - 기본 실행 위치를 동일 세션으로 바꾸고, 세션 실행 이력은 범위 식별에만 사용하며 평가 근거는 raw 산출물로 제한한다. `git status`는 범위 원천에서 대조 수단으로 내려간다.
- 사용자 안내 - 새 세션 호출을 기본으로 설명하지 않는다. 동일 세션 review와 명시적 raw 범위를 사용하는 선택적 독립 감사를 구분한다.
- [[0056-delegate-review-to-fresh-reviewer]] - 맥락 분리가 적대성의 필수 전제라는 결론을 뒤집는다. 적대적 자세와 raw 산출물 재구성 목적은 유지한다.
- [[0057-review-as-adversarial-critique-stage-agnostic]] - 이번 세션 산출물 전체를 단계와 무관하게 비판한다는 범위를 유지한다.
- [[0058-reviewer-evaluation-hierarchy-and-curation]] - 프로젝트 합의 우선, 일반 표준, 자기반박, raw 산출물 계약은 유지하되 별도 검토자 역할 분리는 요구하지 않는다.
- [[0062-plan-as-living-handoff-document]] - plan의 세션 간 진행 맥락 책임은 유지하며 review 전용 handoff 책임은 추가하지 않는다.
- [[0069-review-as-fresh-session]] - 새 세션 기본 실행과 `git status` 기반 범위 판정을 뒤집는다. review 스킬의 직접 검토와 report-only 책임은 유지한다.
- [[0070-remove-plugin-agents]] - reviewer 제거는 유지하되 새 세션에서만 review한다는 조항을 뒤집는다. curator 관련 결정은 영향을 받지 않는다.
