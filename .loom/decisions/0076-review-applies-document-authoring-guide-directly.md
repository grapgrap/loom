# Review가 문서 작성 가이드를 직접 적용한다

## 맥락

Loom 문서 작성 가이드를 도입하기로 한 논의에서는 review가 별도 reviewer 에이전트에 검토를 위임하는 구조를 전제로 삼았다. 같은 시기에 Loom의 Claude Code와 Codex 공통 배포를 위해 plugin agent가 제거되었고, review 스킬이 산출물 재구성, 비판, 검증, 심각도 분류와 보고를 직접 담당하는 구조로 변경되었다.

문서 작성 가이드의 검토 기준은 유지해야 하지만, 이를 위해 제거된 reviewer를 다시 도입하면 런타임 공통 워크플로라는 현재 구조와 충돌한다. 또한 가이드 적용을 이유로 review의 검토 범위를 누적된 `.loom` 문서 전체로 확대해서는 안 된다.

## 결정

Review 스킬이 확인된 검토 범위 안의 Loom 문서에 문서 작성 가이드를 직접 적용한다.

- Review는 먼저 현재 세션의 산출물과 사용자가 지정한 대상을 바탕으로 검토 범위를 확정한다.
- 확정된 범위에 Loom 문서가 포함된 경우, review는 비판을 시작하기 전에 플러그인 내부 문서 작성 가이드를 읽는다.
- Review는 범위 안의 Loom 문서를 비판할 때 문서 유형별 책임, 내용 라우팅, 위키링크의 구조적 사용과 기술문서의 의미 명료성을 평가한다.
- 별도 reviewer 에이전트를 만들거나 검토 절차를 위임하지 않는다.
- Review는 가이드 위반을 포함한 비판을 검증하고 심각도와 근거를 보고하되 산출물을 직접 수정하지 않는다.
- 가이드 적용은 검토 범위를 넓히지 않는다. Review는 확인된 산출물이나 사용자 지정 범위를 넘어 `.loom` 전체를 자동으로 감사하지 않는다.
- Shape, plan과 task가 작성 시 가이드를 적용하고 calibrate가 목적 정렬 감사에만 집중하는 분담은 유지한다.
- 앞선 문서 작성 가이드 결정에서 `reviewer`를 소비 주체로 표현한 조항은 별도 에이전트의 존속을 뜻하지 않으며, 이 결정에 따라 review 스킬의 직접 책임으로 바뀐다.

### 전제 조건

- Review가 범위를 먼저 확정하면 Loom 문서가 없을 때 불필요하게 가이드를 로드하지 않으면서도 모든 Loom 문서 검토에 같은 기준을 적용할 수 있다.
- 검토 기준의 소유 주체를 review 스킬로 모으면 Claude Code와 Codex에서 같은 절차를 유지할 수 있다.

### 제약 조건

- Review의 범위 밖에 있는 기존 Loom 문서의 가이드 위반은 발견되지 않을 수 있다.
  - 제약이 없었다면: 현재 변경 검토의 초점을 유지하면서도 누적 문서 전체의 위반을 별도 비용 없이 발견했을 것이다.

## 대안

### Reviewer 에이전트를 다시 도입한다

- 설명: 문서 작성 가이드의 평가를 전담하는 plugin agent를 복원하고 review가 위임한다.
- 트레이드오프: Claude Code와 Codex의 공통 워크플로가 런타임별 agent 배포 방식에 다시 의존한다.

### Review가 항상 가이드를 읽는다

- 설명: 검토 범위의 문서 유형과 관계없이 review 진입 시 가이드를 로드한다.
- 트레이드오프: 코드처럼 Loom 문서가 전혀 없는 검토에도 불필요한 기준과 컨텍스트를 추가한다.

### Review의 범위를 `.loom` 전체로 넓힌다

- 설명: 가이드를 로드한 review가 누적된 모든 Loom 문서를 함께 검사한다.
- 트레이드오프: 확인된 변경 산출물의 검토라는 review의 범위가 전체 문서 감사로 바뀐다.

## 영향

- review - 검토 범위에 Loom 문서가 있을 때 내부 문서 작성 가이드를 직접 읽고 평가한다.
- plugin agents - 문서 작성 가이드 도입을 이유로 reviewer를 다시 추가하지 않는다.
- shape·plan·task - 자신이 작성하거나 변경한 Loom 문서에 가이드를 적용하는 책임을 유지한다.
- calibrate - 문서 작성 가이드 소비자에서 제외되고 목적 정렬 감사에 집중한다.
