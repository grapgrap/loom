# 템플릿을 Loom 문서의 구조 틀로 한정한다

## 맥락

Loom 문서 작성 가이드는 문서 유형별 책임, 내용 라우팅, 위키링크의 구조적 사용과 기술문서의 의미 명료성을 하나의 내부 기준으로 제공한다. 이 기준을 작성 시점에 쉽게 적용하도록 각 문서 템플릿의 보조 안내를 늘리는 방안이 있었다.

그러나 작성 가이드의 상당 부분은 concept과 flow의 구분, decision과 현재 설계의 관계, 구현 상세의 목적지처럼 여러 문서 유형을 함께 비교해야 하는 판단이다. 이런 기준을 개별 템플릿에 나누어 넣으면 한 템플릿만으로 전체 판단을 표현하기 어렵고, 같은 기준의 일부가 여러 템플릿에 중복된다. 가이드가 변경될 때 템플릿의 안내가 함께 바뀌지 않으면 서로 다른 기준을 제시할 수도 있다.

템플릿은 문서의 구조를 정의하는 파일로 이미 사용되고 있다. 문서 작성 판단은 가이드가 맡고, 템플릿은 그 판단에 따라 선택된 문서를 실제로 작성할 수 있는 틀을 제공하도록 경계를 분명히 할 필요가 있다.

## 결정

Loom의 템플릿을 문서의 섹션과 입력 형태를 제공하는 구조 틀로 한정한다.

- 템플릿은 섹션 이름과 순서, 선택 가능한 섹션, 자리표시자, 목록이나 단계의 기본 형태를 제공한다.
- 템플릿은 각 섹션에 필요한 입력을 식별할 수 있는 최소한의 섹션별 안내를 포함할 수 있다.
- 템플릿은 concept과 flow의 판별, 문서 사이의 내용 라우팅, 구현 상세의 목적지처럼 여러 문서 유형을 가로지르는 책임 기준을 설명하지 않는다.
- 템플릿은 위키링크 정책, 책임 위반 판별과 기술문서 작성 기준을 완전하거나 요약된 체크리스트로 복제하지 않는다.
- 작성 스킬은 Loom 문서를 변경하기 전에 내부 문서 작성 가이드를 읽어 작성 판단을 형성하고, 선택한 문서 유형의 템플릿을 구조 틀로 사용한다.
- 작성이 끝나면 스킬이 가이드에 따라 결과를 검증한다. 템플릿 자체는 가이드 준수를 보장하는 실행 주체가 아니다.
- 기존 템플릿에 포함된 안내는 이 경계에 따라 정리한다. 섹션을 채우는 데 필요한 국소적인 안내는 유지하고, 다른 문서 유형이나 코드를 목적지로 지시하는 기준은 가이드에만 둔다.

### 전제 조건

- 스킬이 작성 전에 가이드를 명시적으로 로드하므로 템플릿이 같은 기준을 반복하지 않아도 작성 판단에 사용할 수 있다.
- 섹션 구조와 최소 입력 안내만으로도 에이전트가 가이드에 따른 판단을 실제 문서 형태로 옮길 수 있다.

### 제약 조건

- 템플릿만 단독으로 읽으면 문서 유형을 선택하거나 내용의 목적지를 판단할 수 없다.
  - 제약이 없었다면: 템플릿 하나가 구조와 모든 작성 판단을 함께 제공했을 것이나, 문서 유형을 가로지르는 기준을 완전하게 표현하려면 작성 가이드를 다시 복제해야 한다.

## 대안

### 템플릿에 작성 가이드의 보조 안내를 확장한다

- 설명: 각 템플릿에 해당 문서의 책임, 다른 문서와의 구분과 기술문서 작성 주의사항을 상세히 넣는다.
- 트레이드오프: 문서 유형을 가로지르는 기준이 여러 템플릿에 부분적으로 복제되고, 가이드와 템플릿이 서로 다른 내용을 제공할 수 있다.

### 템플릿에 작성 가이드의 요약본을 넣는다

- 설명: 모든 템플릿에 공통된 짧은 체크리스트를 포함한다.
- 트레이드오프: 요약본이 별도의 실행 기준처럼 작동하고, 생략된 조건 때문에 가이드와 다른 판단을 유도할 수 있다.

### 템플릿을 제거하고 작성 가이드만 사용한다

- 설명: 가이드가 문서 구조까지 설명하게 하고 별도 템플릿을 두지 않는다.
- 트레이드오프: 반복되는 섹션과 입력 형태를 매번 재구성해야 하며, 작성 가이드가 판단 기준과 물리적 문서 양식을 함께 소유하게 된다.

## 영향

- templates - 모든 템플릿은 문서 구조와 최소한의 섹션별 입력 안내만 제공한다.
- concept·flow 템플릿 - 다른 문서 유형이나 코드로 내용을 보내는 횡단 기준을 제거한다.
- decision·index·plan·principle 템플릿 - 같은 경계를 위반하는 안내가 있는지 확인하되, 구조 안내만 있다면 변경하지 않는다.
- document authoring guide - 문서 간 책임, 내용 라우팅, 위키링크와 기술문서 작성 판단의 단일 기준을 유지한다.
- shape·plan·task - 가이드를 먼저 적용하고 템플릿을 구조 틀로 사용하며 작성 결과를 다시 검증한다.
