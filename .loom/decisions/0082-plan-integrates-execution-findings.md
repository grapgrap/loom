# plan은 진행 맥락을 누적하지 않고 실행 중 발견을 현재 실행 경로에 반영한다

## 맥락

concept과 flow는 프로젝트 구성요소의 역할과 조합을 불변 수준에서 기술하고, 코드는 이를 구체적인 구현으로 닫는다. plan은 두 수준 사이에서 설계를 실행 가능한 태스크로 바꾸기 때문에, 실제 코드를 확인하고 구현하는 동안 작성 시점에는 알 수 없었던 기술적 사실을 만나게 된다.

plan을 실행 단계까지 살아있는 문서로 연장하면서 이 사실을 보존할 자리로 진행 맥락을 도입했다. 진행 맥락은 진행 상태, 다음 작업을 위한 핸드오프와 작업 중 발견을 함께 담았다. 그러나 실행 중 생겼다는 시점만으로 서로 다른 의미의 정보를 한 섹션에 누적하면, 어떤 태스크를 바꾸는 정보인지 드러나지 않고 코드나 decision과 중복되는 작업 일지가 된다.

진행 맥락을 모두 제거하면 설계 문서와 코드의 해상도 차이에서 생긴 사실을 후속 태스크에 전달할 경로도 사라진다. 필요한 것은 별도 기록장의 유지가 아니라, 실행 중 발견을 의미에 따라 현재 실행 경로에 흡수하는 피드백 경로다.

## 결정

plan은 확정된 설계를 코드로 실체화하는 현재 실행 경로이며, task의 실행 내내 갱신되는 살아있는 문서다.

- task가 코드에서 확인한 기술적 사실이 남은 실행에 영향을 주면, 그 사실을 영향받는 태스크의 변화·결과·검증이나 태스크 간 의존관계에 직접 반영한다.
- 비자명한 기술적 선택이 구현의 형태를 바꾸면 선택의 근거를 decision에 기록하고, plan에는 후속 실행을 제약하는 선택의 결과만 반영한다.
- 기술적 사실이 concept이나 flow의 의미 변경을 요구하면 plan에 흡수하지 않고 shape로 돌아간다.
- 코드에서 직접 확인할 수 있고 남은 실행에 영향을 주지 않는 구현 상세는 plan에 중복하여 기록하지 않는다.
- 실행 중 발견을 시간순으로 누적하는 전역 진행 맥락은 두지 않는다.
- 완료되지 않은 태스크의 재개 지점을 plan과 코드만으로 특정할 수 없을 때에만 해당 태스크에 임시 핸드오프를 둔다. 발견을 현재 실행 경로에 반영하거나 태스크를 완료하면 핸드오프를 제거한다.

plan을 살아있는 문서로 유지한다는 기존 방향은 보존한다. 살아있음은 진행 맥락을 누적하는 성질이 아니라, 코드에서 얻은 피드백에 따라 남은 실행 경로가 현재 상태로 갱신되는 성질이다.

### 전제 조건

- 실행 중 발견한 사실은 대체로 특정 태스크나 의존관계에 영향을 준다: 영향을 받는 위치에 반영하면 후속 실행자가 별도 기록을 해석하지 않아도 된다.
- plan은 실행 단계에서도 갱신할 수 있다: 작성 시점의 가정이 현실과 다르면 남은 실행 경로를 고칠 수 있다.
- 기술적 선택의 근거는 발생 시점에 decision으로 보존할 수 있다: plan이 선택의 이유까지 대신 기록할 필요가 없다.

### 제약 조건

- plan은 구현 명세가 아니다. 코드와 설계 문서의 해상도 차이를 모두 복제하지 않는다.
  - 제약이 없었다면: 실행 중 알게 된 구현 상세를 plan에 모두 보존했을 것이다.
- 세션은 미완료 태스크 도중에 중단될 수 있다. plan과 코드만으로 재개 지점을 특정할 수 없는 경우에는 최소한의 핸드오프가 필요하다.
  - 제약이 없었다면: 별도 핸드오프 없이 현재 실행 경로만 갱신했을 것이다.

## 대안

### 전역 진행 맥락을 계속 누적한다

- 설명: 진행 상태, 핸드오프와 작업 중 발견을 plan의 별도 섹션에 시간순으로 기록한다.
- 트레이드오프: 기록은 쉽지만 정보의 의미와 소비 태스크가 드러나지 않는다. 실행이 진행될수록 현재 plan이나 코드와 중복되고 오래된 사실이 남는다.

### 실행 중 발견을 plan에 남기지 않는다

- 설명: plan은 작성 시점의 태스크와 의존관계를 유지하고, 구현 중 알게 된 내용은 코드와 대화에만 둔다.
- 트레이드오프: 설계 문서와 코드의 해상도 차이에서 생긴 제약이 후속 태스크에 전달되지 않고, 작성 시점의 가정을 그대로 실행하는 문제가 되살아난다.

### 구현 설계 문서를 별도로 도입한다

- 설명: 설계 문서와 코드 사이의 기술적 사실과 선택을 전담하는 새 문서 유형을 만든다.
- 트레이드오프: 현재 필요한 정보는 plan의 태스크, decision과 코드에 의미별로 배치할 수 있다. 별도 문서는 같은 구현 상태를 중복하고 새 생명주기를 추가한다.

## 영향

- [[plan]] - 진행 맥락의 누적 대신 실행 중 발견을 태스크와 의존관계에 직접 반영하고, 임시 핸드오프의 조건과 수명을 한정한다.
- task 스킬 - 실행 중 발견을 의미에 따라 plan, decision이나 shape로 라우팅하고 plan의 영향받는 위치를 갱신한다.
- plan 템플릿 - 전역 진행 맥락을 제거하고 미완료 태스크의 임시 핸드오프를 태스크 안에 선택적으로 둔다.
- 문서 작성 가이드 - plan의 실행 중 갱신 책임을 진행 맥락 보존에서 현재 실행 경로의 갱신으로 바꾼다.
