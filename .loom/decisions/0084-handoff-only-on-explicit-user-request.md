# 임시 핸드오프는 사용자가 명시적으로 요청할 때만 작성한다

## 맥락

plan은 미완료 태스크의 재개 지점을 plan과 코드만으로 특정할 수 없는 경우에 임시 핸드오프를 자동으로 작성해 왔다. 이 조건은 핸드오프를 전역 진행 맥락과 구분하고 필요한 동안에만 유지하려는 목적에서 도입되었다.

그러나 task는 코드뿐 아니라 문서와 다른 산출물도 변경할 수 있다. 어떤 산출물의 조합으로 재개 지점을 복원할 수 있는지를 자동으로 판정하면, task가 다루는 산출물이 달라질 때마다 판정 범위를 다시 정의해야 한다. 더 근본적으로, 핸드오프가 필요한지는 사용자가 작업을 넘기려는 의사에 관한 문제다. 에이전트가 산출물 상태만으로 핸드오프 의사를 추론하면 사용자가 요청하지 않은 진행 기록을 plan에 추가할 수 있다.

## 결정

task는 사용자가 명시적으로 요청할 때만 현재 미완료 태스크에 임시 핸드오프를 작성한다.

- 사용자가 요청하지 않으면 task는 재개 가능성을 판정하거나 임시 핸드오프를 작성하지 않는다.
- 임시 핸드오프에는 다음 실행자가 이어서 수행할 재개 지점과 아직 끝나지 않은 작업만 기록한다.
- task가 태스크 실행을 재개하거나 태스크를 완료하면 임시 핸드오프를 제거한다.
- 진행 상태와 실행 중 발견은 임시 핸드오프와 분리한다. 진행 상태는 해당 태스크에, 남은 실행에 영향을 주는 발견은 영향받는 태스크나 결과 의존에 반영한다.

이 결정은 임시 핸드오프를 태스크 지역 정보로 유지하면서 생성 권한을 자동 판정에서 사용자의 명시적 요청으로 옮긴다. 재개 지점의 복원 가능성은 더 이상 임시 핸드오프의 생성이나 제거 조건이 아니다.

### 전제 조건

- 사용자는 작업을 다른 세션이나 실행자에게 넘기려는 경우 핸드오프를 명시적으로 요청할 수 있다.
- 사용자가 요청하지 않은 경우에는 Plan과 현재 산출물이 기본적인 재개 근거로 남는다.

### 제약 조건

- 세션이 예고 없이 종료되고 사용자가 핸드오프를 요청하지 않으면 별도의 재개 정보가 남지 않는다.
  - 제약이 없었다면: task가 세션 종료 가능성을 감지하여 임시 핸드오프를 자동으로 작성했을 것이다.

## 대안

### 재개 가능성을 기준으로 자동 작성한다

- 설명: Plan과 구현 산출물만으로 재개 지점을 특정할 수 없으면 task가 임시 핸드오프를 작성한다.
- 트레이드오프: task가 다루는 산출물마다 복원 근거를 정의해야 하며, 사용자가 작업을 넘길 의사가 있는지와 무관하게 핸드오프를 만들 수 있다.

### 모든 미완료 태스크에 작성한다

- 설명: 태스크가 미완료 상태이면 항상 임시 핸드오프를 작성한다.
- 트레이드오프: 진행 상태와 현재 산출물로 알 수 있는 내용을 중복하고, 임시 핸드오프를 전역 진행 기록처럼 사용하게 된다.

- [[0083-remove-handoff-when-resumption-is-recoverable]] - 재개 지점의 복원 가능성을 생성·제거 조건으로 사용한 결정을 변경한다.

- review 스킬 - 임시 핸드오프의 태스크 지역성, 내용과 재개·완료 후 잔존 여부를 확인한다. 사용자의 요청 여부는 산출물만으로 추론하지 않는다.
