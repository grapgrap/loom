# Plan

문제와 원하는 결과를 확인하고 현재 구현을 조사한다. 구현 방안과 그 영향을 사용자와 검토한 뒤 실행할 작업을 구성하여 실행 중 갱신하는 문서.

## 목적

사용자가 변경 전후의 동작과 주요 선택을 이해하고 판단하도록 돕는다. 검토한 변경안에서 작업과 의존관계를 도출하여 연속적인 실행을 가능하게 한다.

## 책임

현재 구현을 조사해 문제의 원인을 파악한다. 문제와 원하는 결과를 기준으로 구현 방안을 제안한다. 변경 후 흐름과 기존 동작에 미치는 영향을 추적하여 부작용과 대안을 사용자와 검토한다. 검토한 변경안에서 실행할 작업, 완료 결과, 의존관계와 검증 방법을 도출한다. 실행 중 예상과 다른 사실이 드러나면 영향받는 변경안과 남은 작업을 갱신한다.

## 정책

- 현재 구현에서 확인한 사실과 아직 확인하지 못한 가정을 구분한다.
- 구현 방안은 문제를 해결하기 위해 코드의 어느 부분을 어떤 구조나 동작으로 바꿀지에 대한 제안이다. 변경안은 구현 방안과 예상 영향, 필요한 대응을 포함한다.
- 현재 구현은 문제 이해와 영향 분석의 대상이다. 기존 구조를 유지할지는 문제와 원하는 결과를 기준으로 판단한다. 구조 자체가 원인이면 재구성하거나 제거하는 방안도 검토한다.
- 주요 변경은 구현 초안으로 구체화한다. 구현 초안은 변경할 코드 위치와 책임, 주요 인터페이스와 데이터 타입, 호출 관계와 핵심 로직을 표현한다. 핵심 로직은 수도코드 또는 코드로 제시한다.
- 관련 구현을 조사하고 해당 부분의 초안을 사용자와 검토한 뒤 연결되는 다음 부분으로 진행한다. 합의한 초안을 plan에 남긴다.
- 책임 배치나 핵심 동작을 실행자가 새로 결정해야 하는 범위는 실행 가능 상태로 확정하지 않는다. 검증 결과가 필요하면 검증할 작업과 그 결과로 결정할 내용을 구분한다.
- 변경안 전체를 완성한 뒤에만 사용자에게 제시하지 않는다. 판단을 바꿀 발견이나 선택이 드러나는 시점에 현재 이해와 영향을 공유하고 함께 검토한다.
- 실행에 필요한 현재 동작의 요약, 변경안, 예상 영향과 미확인 사항을 남긴다. 탐색 과정 전체를 기록하지 않는다.
- 작업 분해와 실행 관리는 변경안 검토에서 도출한다. 태스크마다 수행할 변화, 완료 결과와 검증 방법을 명시한다.
- 의존관계는 선행 작업의 결과가 후속 작업의 전제가 되는 관계로 구성한다.
- 각 태스크는 구현 초안을 현재 코드와 선행 작업 결과에 대조하여 적용 가능성을 먼저 확인한다. 실제 적용 방안과 필요한 조정, 확인 근거 및 검증 방법을 요약하고 사용자와 합의한 뒤 실행한다.
- 기존 설계 판단을 유지하는 적용 조정은 task에서 합의한다. 책임 배치나 핵심 동작이 달라지면 관련 부분을 다시 플래닝한다.
- 이미 합의한 방향은 실행 요약으로 이어받는다. 새로운 판단이 필요한 사항은 합의된 내용과 구분하여 논의한다.
- 실행 중 발견에도 합의한 변경 방향과 영향 판단이 유지되면 작업 중 해결할 수 있다. 주요 판단이나 다른 작업의 전제가 달라지면 영향받는 변경안과 작업을 사용자와 다시 검토한다.
- 실행 중 확인한 사실은 영향받는 변경안, 태스크나 의존관계에 반영한다. 시간순 작업 일지로 누적하지 않는다.
- 비자명한 선택의 근거는 decision에 기록하고, plan에는 실행에 필요한 선택의 결과와 제약을 반영한다.
- 사용자가 명시적으로 요청할 때만 현재 미완료 태스크에 임시 핸드오프를 남긴다. 태스크를 재개하거나 완료하면 제거한다.

## 경계

- plan 자체는 구현을 수행하지 않는다.
- concept과 flow의 의미나 경계를 변경해야 하면 shape에서 해당 설계를 재검토한다. 구현 방안의 구체성만으로 shape로 돌아가지 않는다.
- 모든 구현을 사전에 명세하거나 코드의 현재 상태를 복제하지 않는다. 변경 판단과 실행에 필요한 내용만 담는다.
- 기술적 선택의 근거를 장기 보존하는 책임은 decision에 있다.
- 작업 수만으로 plan의 필요성을 판단하지 않는다. 단일 작업도 변경 영향 검토가 필요하면 plan의 대상이다. 방향과 영향이 명확한 기계적 변경에는 별도 plan을 요구하지 않는다.
- concept·flow와 독립적인 생명주기를 가진다. 하나의 concept이나 flow에서 여러 plan을 구성할 수 있다.

## 관계

- [[concept]] - 도메인의 책임과 정책을 변경 판단의 기준으로 참조한다.
- [[flow]] - 도메인 간 조합을 참조하여 실제 구현의 변경 전후 흐름을 검토한다.
- [[decision]] - 선택의 근거를 참조하고 실행에 필요한 결과와 제약을 반영한다.
- [[rule]] - 강제적 합의를 변경안과 검증에 반영한다.
- [[convention]] - 권장되는 형태를 변경안 검토에 활용한다.
